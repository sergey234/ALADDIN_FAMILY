## 🔍 ДЕТАЛЬНЫЙ АНАЛИЗ ПРОБЛЕМЫ

### 🔴 КРИТИЧЕСКАЯ ПРОБЛЕМА #1: NetworkManager - вложенные retry

**Сценарий краша:**
1. Запрос получает 401 ошибку
2. Создается Task для обновления токена (строка 923)
3. Токен обновлен → вызывается `performRequest` с `isRetry: true` и тем же `completion` (строка 971)
4. Retry запрос тоже получает 401 ошибку
5. Создается еще один Task для обновления токена
6. Если оба Task вызывают completion → двойной вызов → краш!

**Вероятность:** 🔴 **80%** - это наиболее вероятная причина краша!

---

### 🔴 КРИТИЧЕСКАЯ ПРОБЛЕМА #2: SubscriptionManager - нет защиты

**Сценарий краша:**
1. Вызывается `registerDeviceAnonymously()`
2. Создается `CheckedContinuation`
3. Если `NetworkManager` вызывает completion дважды → `continuation.resume()` вызывается дважды → краш!

**Вероятность:** 🔴 **95%** - это гарантированная причина краша при двойном вызове из NetworkManager!

---

### 🟡 ПРОБЛЕМА #3: Обработка ошибки 401 создает Task

**Сценарий:**
1. Получена ошибка 401
2. Создается Task для `handle401Error()` (строка 708)
3. Вызывается `continuation.resume(throwing: error)` (строка 717)
4. Если Task как-то влияет на continuation → возможен конфликт

**Вероятность:** 🟡 **40%** - возможная дополнительная причина
