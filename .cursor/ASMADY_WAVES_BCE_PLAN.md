## Главная идея (одна фраза)

Не «включить все skills». На **одной живой цели ALADDIN** прогнать skill → записать «нашёл пользу / нет» → решить constantly / on-demand / archive.

---

## Порядок (жёсткий)

```text
1) Волна B (4 ROI-пилота) — по одному, не пачкой
2) Волна C — только когда есть развилка или UX-вопрос
3) Волна E — отдельный чат/день, не смешивать с iOS-кодом
```

Параллелить B и E **нельзя** в одном коммите.  
C можно в тот же день, что B, если это другой чат и другая тема.

# Волна B — ROI-пилоты (4 skill’а)

## Зачем волна

Понять: эти четыре skill’а **реально ловят баги / улучшают UX**, или только занимают место. После каждого — вердикт в journal.

## Общие правила B

| Правило | Как |
|---------|-----|
| Одна цель на skill | Не «проверь всё приложение» |
| Доказательство | Список findings или «0 полезных» — тоже результат |
| Фикс не обязателен в том же чате | Сначала ROI; фикс — отдельным GO, если Critical |
| Не ломать Figma OB / no-mock | Anti-slop и UI не = переписать онбординг без ТЗ |
| Журнал | Дописать секцию в `ASMADY_PILOT_JOURNAL.md` |

**Метрика ROI (для всех четырёх):**

- ✅ **Keep on-demand** — ≥1 полезный finding ИЛИ ясный «этот чеклист ускорил работу»  
- 🗄 **Archive** — 0 пользы два раза подряд  
- ⚡ **Constantly** — только если владелец явно сказал (обычно не нужно)

## B1 · `asm-r-04` · dual-review (вторая проверка кода)

| | |
|--|--|
| **Skill** | `@aladdin-dual-review` |
| **Лучшая цель** | Последний рисковый diff: Voice Safety / Antifake / parental / VPN UI (не BACKUPS) |
| **Как** | 1) `swift-reviewer` или `matt-code-review` на diff 2) второй проход dual-review: API-контракты, mock bypass, secrets, blast radius 3) таблица Critical / High / Other |
| **Не делать** | Auto-merge · править прод без GO · ревью всего репо |
| **Done когда** | Findings записаны + вердикт keep/archive |
| **Время** | ~30–45 мин |

**Фраза владельцу для старта:**  
«Прогони dual-review на Voice Safety / Antifake diff (коммит X или uncommitted)».

---

## B2 · `asm-r-05` · ui-stress (стресс UI)

| | |
|--|--|
| **Skill** | `@aladdin-ui-stress` |
| **Лучшая цель** | Один экран: **Antifake Hub** *или* **Voice Notes** (не оба сразу) |
| **Как** | Чеклист: длинный RU · Dynamic Type · safe area · dark · hit targets · empty/error/loading **без mock-лжи** |
| **Доказательство** | 5–10 пунктов PASS/FAIL; скрин или пометки в journal |
| **Не делать** | Подмена Figma sync · «починить всё» без приоритета |
| **Done когда** | Список FAIL → либо тикеты, либо wontfix с причиной |
| **Время** | ~40–60 мин (+ симулятор, если доступен) |

**Фраза:** «UI-stress на Antifake Hub» / «UI-stress на Voice Notes».

---

## B3 · `asm-r-06` · anti-slop-design (анти-AI-дизайн)

| | |
|--|--|
| **Skill** | `@aladdin-anti-slop-design` |
| **Лучшая цель** | Один **маркетинговый / hero** surface: App Store icon page copy **или** Main hero ambient **или** landing (если трогаем web — вне iOS commit) |
| **Как** | Сверить с Character Bible / Figma; вычеркнуть generic (фиолетовый glow, emoji-декор, «Inter everywhere») |
| **Не делать** | Ломать OB_00…07 без SYNC ТЗ · тащить awesome-design-skills пачкой |
| **Done когда** | «Что убрали / что оставили под бренд» в journal |
| **Время** | ~30–45 мин |

**Фраза:** «Anti-slop на [конкретный экран/landing], Figma не трогать без ТЗ».

---

## B4 · `asm-r-07` · hypothesis (+ AJTBD)

| | |
|--|--|
| **Skill** | `@aladdin-hypothesis` + `@aladdin-ajtbd` |
| **Лучшая цель** | Одна гипотеза Voice **или** Antifake (из JTBD волны A: ссылка/голос за &lt;2 мин) |
| **Как** | Заполнить: *Если X → то метрика Z → потому что барьер W*. Один эксперимент + 3 GATES |
| **Не делать** | Пять гипотез сразу · менять API без GO |
| **Done когда** | Гипотеза + go/no-go эксперимента записаны |
| **Время** | ~25–40 мин (док); эксперимент — отдельно |

**Пример гипотезы (стартовый черновик):**  
*Если* родитель может сказать «проверь ссылку» и попасть в тот же Antifake pipeline,  
*то* доля завершённых проверок за сессию вырастет,  
*потому что* не нужно искать кнопку Antifake вручную.

**Фраза:** «Сформулируй одну hypothesis по Voice→Antifake и GATES».

---

## Рекомендуемая последовательность внутри B

```text
B4 hypothesis (дешево, задаёт смысл)
  → B2 ui-stress на экран из гипотезы
  → B1 dual-review на код, если гипотеза ведёт к коду
  → B3 anti-slop только если трогаем визуал/маркетинг
```

Так ROI связан с продуктом, а не с «прогнать ради галочки».

# Волна E — business (отдельный контур)

## Зачем

Деньги, трафик, SEO — **не** качество iOS-сборки. Смешение = мусор в `feat(build N)` и риск секретов/бот≠iOS.

## Как сделать наилучшим образом

| Шаг | Действие |
|-----|----------|
| 1 | **Новый чат** с темой «Business ALADDIN — не iOS release» |
| 2 | Выбрать **один** фокус на сессию: pricing **или** SEO **или** landing **или** Metrika |
| 3 | Артефакты класть в `docs/business/` *или* отдельный репо / Notion — **не** в Screens/ |
| 4 | Перед любым `git commit` — проверка: нет `telegram_stars_shop_bot`, нет `.env`, нет iOS build bump «заодно» |
| 5 | Если нужен landing-код — ветка/репо **landing**, коммит без `feat(build N)` |

## Рекомендуемый первый business-спринт (E0)

1. **Pricing clarity** — одна страница: Individual / Family / Premium (факты из StoreKit, без выдуманных цен).  
2. **SEO/landing** — один ключ/статья или один экран лендинга (anti-slop сразу).  
3. **Metrika/аналитика** — что уже меряем vs что нужно для гипотезы B4.

Док-канон: [`ASMADY_BUSINESS_OUT_OF_IOS.md`](ASMADY_BUSINESS_OUT_OF_IOS.md).
