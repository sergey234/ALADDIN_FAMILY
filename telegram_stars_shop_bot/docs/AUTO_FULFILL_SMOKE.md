# Смоук: автовыдача (iStar) + админка (п.37)

Короткий чеклист перед продом. Секреты только в `.env` на сервере, не в репозитории.

## 1. Конфиг

- `AUTO_FULFILL_ENABLED=true`, типы: `AUTO_FULFILL_STARS_ENABLED` / `AUTO_FULFILL_PREMIUM_ENABLED` по плану.
- `ISTAR_API_KEY`, при необходимости `ISTAR_API_BASE`, `ISTAR_WALLET_TYPE=TON`.
- В кабинете iStar: URL вебхука `https://<ваш-домен>/v1/payments/istar-webhook`, `ISTAR_WEBHOOK_SECRET` совпадает с кабинетом.
- Partner API доступен снаружи: `GET https://<домен>/health` → `200`, `{"status":"ok"}`.

## 2. Воркер

Один цикл (без `--forever`), из каталога приложения с верным `DATABASE_PATH`:

```bash
python3 -m partner_api.auto_fulfill_worker --limit 5
```

В логах `stats=` — ожидаемо нули, если нет подходящих `paid` или выключен мастер-флаг.

## 3. Счастливый путь (ручной смоук)

1. Оформить тестовый заказ Stars/Premium с валидным `@username` в примечании, довести до **`paid`** (LAVA / Crypto / баланс / админ «Оплачен»).
2. Запустить воркер или дождаться cron; убедиться: статус **`processing`**, в админ-карточке заполнен **провайдер ref**.
3. Дождаться вебхука `order.completed` от iStar (или симулировать POST с верной подписью на тестовом стенде): статус **`completed`**, покупателю пришло «Готово».

## 4. Админка (37-6)

- На заказе в `paid` / `processing`: кнопка **«Только вручную»** — воркер не берёт заказ; в аудите `adm:ffman`.
- Супер-админ: **«Снова авто»**, **«Сброс авто-полей»** на `paid` — сбрасывает попытки/ref/ошибку; в аудите `adm:ffauto` / `adm:ffrst`.
- В тексте карточки видны режим, ref, последняя ошибка.

## 5. Негатив

- Неверный получатель / лимит попыток — заказ остаётся на операторе, **без** авто-возврата (см. `docs/EDGE_CASES.md`).
- `order.failed` от iStar — в логах заказа ошибка, покупателю сообщение с поддержкой.

## 6. Регрессия

```bash
cd telegram_stars_shop_bot && python3 -m pytest -q
```

После изменений в вебхуках или БД — повторить п.1–2 на копии БД.
