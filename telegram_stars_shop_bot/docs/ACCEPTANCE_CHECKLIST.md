# Ручной чеклист приёмки (перед продом)

Сопоставление с **ID из плана** (44 строки §3.0): `docs/ACCEPTANCE_CHECKLIST_BY_ID.md`.

Отметьте пункты после проверки в стейджинге / препроде.

## Онбординг и меню

1. [ ] `/start` — первый экран, кнопка «Далее», второй экран с 10 кнопками хаба.
2. [ ] `/menu` — снова экран 2 + хаб.
3. [ ] Команда `/my` — профиль и клавиатура хаба.

## Каталог и пустые разделы

4. [ ] **Купить Stars** — список товаров или явное сообщение о пустом `products.yaml`.
5. [ ] **Premium / Подарки** — при отсутствии позиций — понятное сообщение и выход в меню.

## Заказ (основной сценарий)

6. [ ] Выбор товара → способ оплаты → ввод `@username` → подтверждение → заказ создан, админу уведомление.
7. [ ] **Мои заказы** — список, пагинация, открытие деталки, кнопка поддержки.

## Баланс и выкуп

8. [ ] **Пополнить баланс** — пресеты и своя сумма, заявка админу, зачисление через админ-кнопку.
9. [ ] Оплата заказа **с баланса** (полностью) и **частично** (mix) — суммы в деталке заказа сходятся.
10. [ ] **Продать Stars** — ввод количества, заявка админу.
11. [ ] **Мои заявки на выкуп** — пагинация, статусы по-русски.

## Профиль, рефералка, данные

12. [ ] Профиль — балансы, ссылка, FAQ рефералки.
13. [ ] **Данные и политика** — экран открывается, возврат в профиль.

## API и ключи

14. [ ] **Наш API** — выпуск Partner API ключа (при заданном `API_KEY_PEPPER`), ключ показывается один раз.
15. [ ] `GET /health`, `GET /v1/user/profile` с `X-API-KEY`, `POST /v1/orders/create` с `Idempotency-Key` (повтор — тот же заказ).

## Поддержка и админка

16. [ ] Поддержка — с URL / с шаблонами FAQ без URL.
17. [ ] `/admin` — смена статусов заказа, пополнения, выкупа (под админским ID).

## Регресс

18. [ ] `/cancel` в процессе checkout сбрасывает сценарий.
19. [ ] Чеки — список завершённых заказов открывает карточку заказа.

## Sentry и автоплатежи / вебхуки

20. [ ] При заданном `SENTRY_DSN` ошибки в боте и Partner API попадают в проект Sentry (smoke: искусственная ошибка на стейджинге).
21. [ ] `POST /v1/payments/provider-webhook` с валидным `X-Payment-Signature` переводит API-заказ из `pending_payment` в `paid`; повтор с тем же `idempotency_key` — без дубликата.
22. [ ] `PUT /v1/webhooks/subscription` задаёт HTTPS URL; при смене статуса API-заказа партнёр получает `POST` с `X-Partner-Signature` (см. `RUNBOOK` раздел 10).
