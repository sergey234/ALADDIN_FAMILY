## Advanced Settings — план исправлений по Safari/Threat + переносы текста (по пунктам 1–5)

Правила выполнения:
- Делаем **по 1 правке за раз** → быстрый прогон: открыть экран → поменять → выйти/зайти → kill app → открыть снова.
- Где есть “Сохранить” — UX не меняем, только проверяем, что save/load работает.

### 1) Safari: почему “Фильтрация сайтов” и “Ограничение соцсетей” показывают одинаковое
**Факт в текущем коде:**
- Обе карточки открывают один и тот же `FamilyContentBlockModal`.
- Внутри `FamilyContentBlockModal` всегда показывается `ContentBlockerCategory.allCases`, то есть один и тот же список категорий.

**Что нужно сделать:**
- Развести “контекст” модалки:
  - `FamilyContentBlockModal(mode: .sitesFilter, allowedCategories: …, preset: …)`
  - `FamilyContentBlockModal(mode: .socialRestriction, allowedCategories: [.socialMedia], preset: [.socialMedia])`
- В UI модалки показать заголовок/описание, которые явно относятся к выбранной карточке.

### 2) Safari: почему тумблер “не переключается” и что должно быть “истиной”
**Факт в текущем коде:**
- `ContentBlockerManager.isEnabled` = это **только** состояние включенности расширения Safari (через `SFContentBlockerManager.getStateOfContentBlocker`).
- В `AdvancedProtectionSettingsScreen` и в `FamilyContentBlockModal` биндинг `isEnabled` сделан “read-only” (set игнорируется), поэтому визуально тумблер может не менять состояние.

**Продуктовая логика (чтобы не было “истина/ложь”):**
- Истина #1: **состояние Safari extension** (enabled/needsActivation/error) — отдельно и честно.
- Истина #2: **состояние двух карточек** (сайты / соцсети) — это не “extension enabled”, а “какие правила (категории) применены”.

**Что нужно сделать:**
- Ввести отдельное хранение:
  - `safari_sitesFilter_selectedCategories` (Set/Array rawValues)
  - `safari_socialRestriction_enabled` (Bool) или тоже через категории
- Правила, которые реально применяются в Content Blocker: **объединение** (union) выбранных категорий двух карточек.
- Тумблер карточки:
  - ON = применить свой preset (или ранее выбранный набор)
  - OFF = убрать только “свой” набор, не трогая другой (и не ломая вторую карточку)
- Если `status == .needsActivation`, то при попытке включить:
  - показываем инструкцию + кнопку “Открыть настройки”, а UI состояния карточки не врет (остаётся OFF/needsActivation).

### 3) Threat: почему “карточки не открываются сразу”, а потом открываются “пачкой”
**Факт в текущем коде:**
- Есть `showThreatProtectionSheet` и ещё 4 отдельных флага `showPhishingSettings / showMalwareSettings / …`.
- Это 5 разных `.sheet` на одном экране. iOS часто откладывает показ второго sheet, пока первый не будет закрыт → получается “запаздывание/пачка”.

**Что нужно сделать:**
- Убрать цепочку `.sheet` и сделать **единый механизм навигации**:
  - Вариант A (предпочтительный): внутри `ThreatProtectionSettingsSheet` сделать `NavigationStack` + `NavigationLink` в соответствующую модалку (без второго sheet).
  - Вариант B: `sheet(item:)` через enum `ThreatDestination` и показывать один sheet, который меняет контент.
- Обязательно: при тапе по пункту “Phishing/…” должно быть 1 действие → немедленное открытие настроек.

### 4) Проверка wiring/сохранения в 4 модалках Threat
Цель: убедиться, что все переключатели реально связаны с источником истины и сохраняются.
- Открыть каждую из 4 модалок.
- Для каждого Toggle/Picker:
  - источник истины: `ComponentConfigurationService` / `ComponentStatusService` / `@AppStorage` (что фактически используется)
  - если есть “Сохранить” — проверяем, что save/load отрабатывает.
  - если “автосохранение” — проверяем, что изменение пишется сразу.

Чек:
- toggle → выйти → зайти (значения на месте)
- kill app → открыть снова → значения на месте

### 5) UX переносы: “Мониторинг активности” (разрывы “нг”, “и”)
**Почему так бывает:**
- маленький доступный width + `.lineLimit(1)`/`minimumScaleFactor`/`layoutPriority` могут заставлять движок переносить по символам.

**Что нужно сделать:**
- Проставить для заголовка/подзаголовка/метрик:
  - `.lineLimit(nil)` или адекватные лимиты
  - `.fixedSize(horizontal: false, vertical: true)` там, где нельзя “схлопывать”
  - `layoutPriority(…)` для текста vs кнопок справа
- Проверить визуально на iPhone SE и Pro Max.

## Дополнительно (ответы на вопросы)

### “Защита от угроз” в Advanced Settings и “Защита ALADDIN → защита от угроз” — конфликт?
План проверки:
- Сверить componentId, которые переключаются в обоих местах.
- Подтвердить, что оба UI работают через единый источник истины `ComponentStatusService` (тогда конфликтов не будет).

### Как искали отсутствующие ключи локализации
Использовался скрипт (python/regex), который:
- собирает все `localized("...")` из активных `.swift` (исключая BACKUPS/архивы/DerivedData/docs)
- собирает все ключи, определённые в `Core/Localization/LocalizationManager.swift`
- делает разницу `used - defined` и сохраняет отчёт в `docs/AUDIT_LOCALIZATION_MISSING_KEYS_ACTIVE.json`
