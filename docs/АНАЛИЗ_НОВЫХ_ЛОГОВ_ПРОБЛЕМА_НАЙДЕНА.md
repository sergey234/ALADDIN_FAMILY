
**Что происходит:**
1. **Временная последовательность:**
   - `16:20:29` - `KeychainAutoRecoveryService.repairTokensIfNeeded()` вызывается из `ALADDINApp.init()`
   - `16:20:29` - Токен **удаляется** из Keychain
   - `16:20:30` - `SubscriptionManager.loadPersistedData()` пытается загрузить токен, но его уже нет!

2. **Проблема в логике:**
   ```swift
   // Текущая логика (НЕПРАВИЛЬНАЯ):
   if let data = keychain.loadData(forKey: .authToken),
      (try? JSONDecoder().decode(String.self, from: data)) == nil {
       keychain.delete(forKey: .authToken)  // ❌ Удаляет валидный токен!
   }
   ```
   
   **Почему это неправильно:**
   - Токен в Keychain хранится как `JWTToken` (Codable объект), а не как `String`!
   - Проверка `decode(String.self, ...)` всегда проваливается для `JWTToken`
   - Поэтому валидный токен удаляется как "повреждённый"

3. **Последствия:**
   - Токен удаляется **ДО** того, как `SubscriptionManager` загрузит его
   - `SubscriptionManager.loadPersistedData()` не находит токен в Keychain
   - Токен остаётся только в памяти (`SubscriptionManager.currentToken`)
   - При следующем запуске приложения токена не будет

## 🔧 РЕШЕНИЕ ПРОБЛЕМЫ

### Исправление #1: Исправить логику KeychainAutoRecoveryService

**Текущая логика (НЕПРАВИЛЬНАЯ):**
```swift
if let data = keychain.loadData(forKey: .authToken),
   (try? JSONDecoder().decode(String.self, from: data)) == nil {
    keychain.delete(forKey: .authToken)  // ❌ Удаляет валидный токен!
}
```

**Правильная логика:**
```swift
// Проверяем, можно ли декодировать как JWTToken (реальный формат)
if let data = keychain.loadData(forKey: .authToken) {
    // Пробуем декодировать как JWTToken (правильный формат)
    if (try? JSONDecoder().decode(JWTToken.self, from: data)) == nil {
        // Если не получается декодировать как JWTToken, пробуем как String (старый формат)
        if (try? JSONDecoder().decode(String.self, from: data)) == nil {
            // Только если оба формата не работают - удаляем токен
            keychain.delete(forKey: .authToken)
            AppConfig.authToken = nil
            print("⚠️ KeychainAutoRecoveryService: удалён повреждённый auth_token")
        }
    }
}
```

**Или лучше:**
```swift
// Проверяем, можно ли декодировать токен в любом формате
if let data = keychain.loadData(forKey: .authToken) {
    let canDecodeAsJWTToken = (try? JSONDecoder().decode(JWTToken.self, from: data)) != nil
    let canDecodeAsString = (try? JSONDecoder().decode(String.self, from: data)) != nil
    
    // Удаляем только если токен нельзя декодировать ни в одном формате
    if !canDecodeAsJWTToken && !canDecodeAsString {
        keychain.delete(forKey: .authToken)
        AppConfig.authToken = nil
        print("⚠️ KeychainAutoRecoveryService: удалён повреждённый auth_token")
    }
}
```

## 🎯 ВЫВОДЫ

### Главная проблема:
**`KeychainAutoRecoveryService.repairTokensIfNeeded()` удаляет валидные токены, потому что проверяет неправильный формат!**

### Причина:
- Токен хранится как `JWTToken` (Codable объект)
- Проверка пытается декодировать как `String`
- Декодирование проваливается → токен удаляется как "повреждённый"

### Решение:
- Исправить логику проверки: проверять декодирование как `JWTToken`
- Изменить порядок инициализации: загружать токен **ДО** проверки
