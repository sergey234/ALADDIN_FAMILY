### ✅ ПРОБЛЕМА #1: "Не удалось загрузить список детей" показывается неправильно

**Описание:**  
В разделе "Управление → Участники семьи → Родитель → Выберите ребенка" и в "Родительский контроль" показывается ошибка "Не удалось загрузить список детей!" даже когда есть дети или когда это нормальная ситуация (нет токена, нет детей).

**Исправления:**

1. **Улучшена логика в `ParentalControlScreen.loadChildMembers()`:**
   - ✅ Добавлена проверка токена перед загрузкой
   - ✅ Если нет токена - не показываем ошибку (это нормально для неавторизованных пользователей)
   - ✅ Если после фильтрации нет детей - показываем сообщение "Нет детей" вместо ошибки
   - ✅ Проверяем тип ошибки: для `unauthorized` не показываем ошибку загрузки детей

**Файлы изменены:**
- `Screens/07_ParentalControlScreen.swift`

**Код исправления:**
```swift
private func loadChildMembers() {
    isChildrenLoading = true
    childrenErrorMessage = nil
    
    // ✅ ИСПРАВЛЕНИЕ: Проверяем токен перед загрузкой
    guard AppConfig.authToken != nil else {
        DispatchQueue.main.async {
            self.isChildrenLoading = false
            // Не показываем ошибку, если нет токена - это нормально для неавторизованных пользователей
            self.children = []
            self.childrenErrorMessage = nil
        }
        return
    }
    
    apiService.getFamilyMembers { result in
        DispatchQueue.main.async {
            self.isChildrenLoading = false
            switch result {
            case .success(let members):
                self.statsErrorMessage = nil
                self.children = members
                
                // ✅ ИСПРАВЛЕНИЕ: Проверяем, есть ли дети после фильтрации
                if childMembers.isEmpty {
                    // Если нет детей, не показываем ошибку - это нормальная ситуация
                    self.childrenErrorMessage = nil
                    self.statsErrorMessage = localizationManager.localized("parental_children_empty")
                    return
                }
                
                guard let resolvedId = resolveSelectedChildID() else {
                    self.statsErrorMessage = localizationManager.localized("parental_children_empty")
                    return
                }
                loadParentalControlData(for: resolvedId)
            case .failure(let error):
                // ✅ ИСПРАВЛЕНИЕ: Проверяем тип ошибки
                let networkError = NetworkError.from(error)
                if case .unauthorized = networkError {
                    // Для ошибки авторизации не показываем ошибку загрузки детей
                    self.children = []
                    self.childrenErrorMessage = nil
                } else {
                    // Только для других ошибок показываем сообщение
                    let message = localizationManager.localized("parental_children_error_generic")
                    self.childrenErrorMessage = message
                    self.statsErrorMessage = message
                    print("❌ Ошибка загрузки списка детей: \(error.localizedDescription)")
                }
            }
        }
    }
}
```

### ✅ ПРОБЛЕМА #2: Переброс на онбординг при нажатии на тумблеры в "Защита детей"

**Описание:**  
При нажатии на любой из 5 тумблеров в разделе "Защита детей" происходит переброс на экран онбординга. Это происходит из-за того, что при отсутствии токена отправляется уведомление `SessionExpired`, которое обрабатывается в `ALADDINApp` и перенаправляет на онбординг.

**Исправления:**

1. **Улучшена логика в `ParentalControlViewModel.toggleComponent()`:**
   - ✅ При отсутствии токена НЕ отправляем `SessionExpired` - это не истекшая сессия, а просто отсутствие токена
   - ✅ Откатываем изменение UI, показываем сообщение об ошибке, но НЕ перенаправляем на онбординг
   - ✅ `SessionExpired` отправляется ТОЛЬКО если токен был установлен ранее, но стал невалидным (это действительно истекшая сессия)

**Файлы изменены:**
- `ViewModels/ParentalControlViewModel.swift`

**Код исправления:**
```swift
private func toggleComponent(...) async {
    // ✅ ИСПРАВЛЕНИЕ: Проверка токена перед переключением
    // ✅ НЕ отправляем SessionExpired при отсутствии токена - это может быть нормальная ситуация
    guard AppConfig.authToken != nil else {
        print("⚠️ ParentalControlViewModel: Токен отсутствует, невозможно переключить компонент \(componentId)")
        // ✅ ИСПРАВЛЕНИЕ: Откатываем изменение UI, но НЕ отправляем на онбординг
        updateClosure(!newValue) // Откатываем обратно
        toastManager.showError("Требуется авторизация. Войдите в аккаунт.")
        // ✅ ИСПРАВЛЕНИЕ: НЕ отправляем SessionExpired - это не истекшая сессия, а просто отсутствие токена
        return
    }
    
    // ... остальной код ...
    
    case .failure(let error):
        if case .unauthorized(let message) = error {
            // Откат при ошибке
            updateClosure(!newValue)
            let errorMessage = message ?? "Сессия истекла. Пожалуйста, войдите снова."
            toastManager.showError(errorMessage)
            // ✅ ИСПРАВЛЕНИЕ: Отправляем SessionExpired ТОЛЬКО если это действительно истекшая сессия
            // Проверяем, что токен был установлен ранее (не просто отсутствует)
            if AppConfig.authToken != nil {
                // Токен был, но стал невалидным - это истекшая сессия
                NotificationCenter.default.post(
                    name: NSNotification.Name("SessionExpired"),
                    object: nil,
                    userInfo: ["message": errorMessage]
                )
            }
            // Если токена не было, не отправляем SessionExpired - это не истекшая сессия
        }
}
```

### ✅ ПРОБЛЕМА #3: 5 тумблеров в разделе "Защита детей"

**Описание:**  
В разделе "Защита детей" есть 5 тумблеров. Пользователь просит перечислить их все и объяснить логику работы.

**Список всех 5 тумблеров:**

1. **Обнаружение самоповреждений** (`self_harm_detection_agent`)
   - **Что это:** AI-агент, который обнаруживает контент о самоповреждениях (self-harm) в сообщениях, видео и текстах
   - **Компонент:** `self_harm_detection_agent`
   - **Метод переключения:** `viewModel.toggleSelfHarmDetection(newValue)`

2. **Обнаружение груминга** (`grooming_detection_agent`)
   - **Что это:** AI-агент, который обнаруживает попытки груминга (установление доверительных отношений с детьми для последующего злоупотребления)
   - **Компонент:** `grooming_detection_agent`
   - **Метод переключения:** `viewModel.toggleGroomingDetection(newValue)`

3. **Обнаружение онлайн-хищников** (`online_predators_agent`)
   - **Что это:** AI-агент, который обнаруживает подозрительную активность онлайн-хищников
   - **Компонент:** `online_predators_agent`
   - **Метод переключения:** `viewModel.toggleOnlinePredators(newValue)`

4. **Психологическая поддержка** (`psychological_support_agent`)
   - **Что это:** AI-агент, который предоставляет психологическую поддержку детям в сложных ситуациях
   - **Компонент:** `psychological_support_agent`
   - **Метод переключения:** `viewModel.togglePsychologicalSupport(newValue)`

5. **Родительский контроль бот** (`parental_control_bot`)
   - **Что это:** Улучшенный бот родительского контроля для управления настройками защиты детей
   - **Компонент:** `parental_control_bot`
   - **Метод переключения:** `viewModel.toggleParentalControlBot(newValue)`
   - **Особенность:** Имеет дополнительные настройки (`hasSettings: true`)

**Расположение в коде:**
- Файл: `Screens/07_ParentalControlScreen.swift`
- Метод: `childProtectionSection` (строки 701-759)

**Логика работы:**

1. **Загрузка статусов:**
   - При открытии экрана вызывается `viewModel.loadComponentStatuses()`
   - Статусы загружаются параллельно через `ComponentStatusService`
   - Каждый компонент имеет приоритет загрузки (critical, high, normal)

2. **Переключение тумблера:**
   - Пользователь нажимает на тумблер
   - Вызывается соответствующий метод `toggle*` в `ParentalControlViewModel`
   - Метод вызывает `toggleComponent()` с оптимистичным обновлением UI
   - Статус отправляется на сервер через `ComponentStatusService.updateStatus()`
   - При успехе показывается уведомление "Компонент обновлен"
   - При ошибке происходит откат UI и показывается сообщение об ошибке

3. **Синхронизация с сервером:**
   - Все изменения сохраняются на сервер через `ComponentStatusService`
   - Используется `RetryManager` для повторных попыток при временных ошибках
   - Статусы кэшируются локально для быстрого отображения

## 🔍 ДЕТАЛЬНЫЙ АНАЛИЗ ЛОГИКИ

### Логика работы "Выберите ребенка" в ParentalControlScreen:

1. **Загрузка детей:**
   - Вызывается `loadChildMembers()` при открытии экрана
   - Проверяется наличие токена авторизации
   - Если токена нет - список детей пустой, ошибка не показывается
   - Если токен есть - загружаются все члены семьи через `apiService.getFamilyMembers()`

2. **Фильтрация детей:**
   - Из всех членов семьи фильтруются только те, у кого роль `child` или `teenager`
   - Фильтрация происходит в computed property `childMembers`

3. **Отображение:**
   - Если идет загрузка - показывается индикатор загрузки
   - Если есть ошибка (и это не unauthorized) - показывается сообщение об ошибке с кнопкой "Повторить"
   - Если нет детей - показывается сообщение "Нет детей" с кнопкой "Повторить"
   - Если есть дети - показывается список для выбора

4. **Выбор ребенка:**
   - При выборе ребенка вызывается `loadParentalControlData(for: childId)`
   - Загружаются статистика и настройки для выбранного ребенка

### Логика работы "Выберите ребенка" в FamilyScreen:

1. **Загрузка детей:**
   - Вызывается `loadChildren()` при открытии модала
   - Дети загружаются из `UserDefaults` (ключ: `"family_members_list"`)
   - Фильтруются только дети с ролью `child` или `teenager`

2. **Отображение:**
   - Используется `Picker` для выбора ребенка
   - Если список пустой - `Picker` будет пустым (но ошибка не показывается)
