# 📋 ПОДРОБНАЯ ИНСТРУКЦИЯ: ОБНОВЛЕНИЕ GITHUB SECRETS

## 🎯 ЦЕЛЬ

Обновить GitHub Secrets новыми provisioning profiles, которые содержат правильный сертификат.

---

## 📝 ПОДГОТОВКА

### ШАГ 0: Проверить файлы

1. **Откройте Finder**
2. **Перейдите в папку Downloads** (Загрузки)
3. **Найдите файлы:**
   - `app_profile_base64.txt` (~16KB)
   - `ext_profile_base64.txt` (~17KB)
4. **Убедитесь, что файлы существуют и не пустые**

**Если файлов нет:**
```bash
cd ~/Downloads
cat "ALADDIN_App_Store_Distribution (1).mobileprovision" | base64 > app_profile_base64.txt
cat "ALADDINPacketTunnel_App_Store_Distribution (1).mobileprovision" | base64 > ext_profile_base64.txt
```

## 🔐 ШАГ 1: Открыть GitHub Secrets

### 1.1. Открыть репозиторий

1. **Откройте браузер**
2. **Перейдите по ссылке:** https://github.com/sergey234/ALADDIN_FAMILY
3. **Войдите в GitHub** (если не авторизованы)

### 1.2. Открыть Settings

1. **На странице репозитория найдите вкладки вверху:**
   - Code
   - Issues
   - Pull requests
   - Actions
   - Projects
   - Wiki
   - Security
   - **Settings** ← НАЖМИТЕ СЮДА
2. **Нажмите на вкладку "Settings"**

### 1.3. Открыть Secrets and variables

1. **В левом меню найдите раздел "Security"**
2. **В разделе "Security" найдите подраздел:**
   - Secrets and variables
   - **Actions** ← НАЖМИТЕ СЮДА
3. **Нажмите на "Actions"**

**Результат:** Вы должны увидеть страницу со списком секретов:
- `PROVISIONING_PROFILE_APP`
- `PROVISIONING_PROFILE_EXTENSION`
- И другие секреты

## 📝 ШАГ 2: Обновить PROVISIONING_PROFILE_APP

### 2.1. Найти секрет

1. **На странице "Secrets and variables" → "Actions"**
2. **Найдите в списке секрет:** `PROVISIONING_PROFILE_APP`
3. **Справа от секрета вы увидите кнопки:**
   - **"Update"** (Обновить) ← НАЖМИТЕ СЮДА
   - "Delete" (Удалить) - НЕ нажимайте!

### 2.2. Открыть файл app_profile_base64.txt

1. **Откройте Finder**
2. **Перейдите в папку Downloads** (Загрузки)
3. **Найдите файл:** `app_profile_base64.txt`
4. **Дважды кликните на файл**, чтобы открыть в текстовом редакторе
   - Или правой кнопкой → "Открыть с помощью" → "TextEdit" (или другой текстовый редактор)

### 2.3. Скопировать содержимое файла

1. **В текстовом редакторе:**
   - Нажмите `Cmd + A` (выделить все)
   - Нажмите `Cmd + C` (копировать)
2. **Проверьте:**
   - Должна быть длинная строка base64 (без переносов строк)
   - Длина примерно 16245 символов
   - Начинается с букв/цифр (A-Z, a-z, 0-9, +, /, =)

### 2.4. Вставить в GitHub

1. **Вернитесь в браузер** (на страницу обновления секрета)
2. **В поле "Value" (Значение):**
   - Удалите старое содержимое (если есть)
   - Нажмите `Cmd + V` (вставить)
   - Или правой кнопкой → "Вставить"
3. **Проверьте:**
   - В поле должна быть длинная строка base64
   - Нет переносов строк
   - Нет пробелов в начале или конце

### 2.5. Сохранить изменения

1. **Прокрутите страницу вниз**
2. **Найдите кнопку:** **"Update secret"** (Обновить секрет)
3. **Нажмите "Update secret"**
4. **Подтвердите обновление** (если спросит)

**Результат:** Вы должны увидеть сообщение об успешном обновлении секрета.

## 🚀 ШАГ 5: Запустить workflow и проверить результат

### 5.1. Открыть страницу Actions

1. **В репозитории найдите вкладки вверху**
2. **Нажмите на вкладку:** **"Actions"**

**Или перейдите напрямую:**
- https://github.com/sergey234/ALADDIN_FAMILY/actions

### 5.2. Найти workflow check-secrets

1. **На странице Actions найдите в левом меню:**
   - "All workflows"
   - **"check-secrets"** ← НАЖМИТЕ СЮДА
2. **Или найдите в списке workflows:**
   - "Build and Upload to App Store"
   - **"check-secrets"** ← НАЖМИТЕ СЮДА

### 5.3. Запустить workflow (если нужно)

**Если workflow не запустился автоматически:**

1. **На странице workflow найдите кнопку:** **"Run workflow"** (Запустить workflow)
2. **Нажмите "Run workflow"**
3. **Выберите ветку:** `master` (или `main`)
4. **Нажмите зеленую кнопку:** **"Run workflow"**

**Если workflow уже запущен:**
- Просто дождитесь завершения

### 5.4. Проверить результат

1. **На странице workflow найдите последний запуск** (самый верхний в списке)
2. **Нажмите на запуск**, чтобы открыть детали
3. **Проверьте шаги:**
   - ✅ "Decode App Profile" - должен быть успешным
   - ✅ "Extract App Profile UUID" - должен извлечь UUID `4dc2e0ff-f7bd-4ac0-aca8-98143ea99e7f`
   - ✅ "Decode Extension Profile" - должен быть успешным
   - ✅ "Extract Extension Profile UUID" - должен извлечь UUID `d1e59dc9-2171-4eca-a316-1bf714c895ec`
   - ✅ "Build Archive" - должен быть успешным

### 5.5. Проверить логи на ошибки

1. **На странице запуска workflow найдите шаг:** "Building archive with manual signing..."
2. **Нажмите на шаг**, чтобы открыть логи
3. **Проверьте логи на наличие ошибок:**
   - ❌ Если есть ошибка `Provisioning profile doesn't include signing certificate` - проблема не решена
   - ✅ Если ошибки нет и сборка успешна - проблема решена!

## 🔍 ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК

### Проблема: Не могу найти секрет

**Решение:**
- Убедитесь, что вы находитесь на странице: Settings → Secrets and variables → Actions
- Проверьте, что у вас есть права на изменение secrets
- Обновите страницу (F5 или Cmd + R)

### Проблема: Файл base64 не открывается

**Решение:**
- Откройте файл через TextEdit или другой текстовый редактор
- Или используйте терминал:
  ```bash
  cd ~/Downloads
  cat app_profile_base64.txt | pbcopy  # Скопирует в буфер обмена
  ```

### Проблема: GitHub не принимает секрет

**Решение:**
- Проверьте, что скопирован весь текст (нет обрезки)
- Убедитесь, что нет переносов строк
- Попробуйте скопировать еще раз

### Проблема: Workflow все еще падает с ошибкой

**Решение:**
- Проверьте логи workflow
- Убедитесь, что используются новые UUID (`4dc2e0ff...` и `d1e59dc9...`)
- Проверьте, что профили содержат правильный сертификат
