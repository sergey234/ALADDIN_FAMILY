## ✅ ИСПРАВЛЕНИЯ

### 1. PhishingProtectionSettingsModal

**Было:**
```swift
let currentStatus = await statusService.componentStatuses[componentId]
```

**Стало:**
```swift
Task { @MainActor in
    let currentStatus = statusService.componentStatuses[componentId]
    // ...
}
```

**Причина:** 
- `componentStatuses` - это `@Published` свойство, не требует `await`
- Но `ComponentStatusService` помечен как `@MainActor`, поэтому доступ должен быть на главном потоке
- Используем `Task { @MainActor in }` для обеспечения доступа на главном потоке

### 2. APIService - упрощение обработки ошибок

**Было:**
```swift
if let urlError = error as? URLError {
    continuation.resume(throwing: error)
} else if let networkError = error as? NetworkError,
          case .invalidStatusCode(let code) = networkError,
          code == 405 {
    // ...
}
```

**Стало:**
```swift
if let networkError = error as? NetworkError,
   case .invalidStatusCode(let code) = networkError,
   code == 405 {
    // ...
} else {
    continuation.resume(throwing: error)
}
```

**Причина:**
- Убрана лишняя проверка `URLError`
- Упрощена логика обработки ошибок
- Убрана лишняя переменная `patchError` в обработке ошибки PATCH

## 📋 ОСТАЛЬНЫЕ МОДАЛЬНЫЕ ОКНА

Для остальных модальных окон можно оставить `isEnabled: true`:

- `MalwareDetectionSettingsModal`
- `MobileSecuritySettingsModal`
- `NetworkSecuritySettingsModal`
- `IncidentResponseSettingsModal`
- `VoiceControlView`
- `EmergencyNotificationsView`
- `AnalyticsSettingsModal`
- `ComplianceView`

**Причина:** 
- `isEnabled` в `ComponentConfiguration` - это просто флаг в конфигурации
- Он не влияет на реальный статус компонента (который управляется через `ComponentStatusService`)
- Реальный статус компонента хранится отдельно в `ComponentStatusService.componentStatuses`
