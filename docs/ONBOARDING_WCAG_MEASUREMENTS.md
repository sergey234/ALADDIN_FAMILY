# WCAG: замеры контраста онбординга (sRGB, математика)

## Что это и зачем

**WCAG** (в части контраста) — правило: **текст должен отличаться от фона настолько**, чтобы люди с ослабленным зрением и при блике на экране могли читать без напряжения. Для обычного текста обычно требуют **не ниже 4.5:1**, для крупного заголовка — часто **3:1** (крупный = по гайдлайну Apple/WCAG: жирный от ~14pt и выше и т.п.).

**Зачем таблица:** зафиксировать **конкретные hex** из кода и **числа контраста**, чтобы дизайн карточки (Фаза A/B) опирался на факты, а не на ощущение.

---

## Можно ли «сделать все замеры» автоматически?

| Что сделано | Ограничение |
|-------------|-------------|
| Точный расчёт **для известных hex** (текст + однородный фон) | Да, см. ниже. |
| Учёт **каждого пикселя** с Lottie/PNG героя, полупрозрачных слоёв, blend mode, `softLight` на Main | Нет без **семплирования скриншота** (симулятор / устройство) или ручной проверки **Accessibility Inspector**. |
| Системные `Color.red` / `Color.orange` в SwiftUI | В документе взяты **типичные sRGB iOS** (как в колонке «Hex замера»); на другой ОС/настройке могут отличаться — тогда пересчитать по фактическому sRGB. |

Итого: **математику по палитре и градиентам** мы закрыли; **финальный знак «принято WCAG»** для composited экрана — после карточки/финального арта: Inspector или экспорт пикселя из симулятора.

## Таблица 1 — контраст текста на **однородных** фонах (без героя)

Коэффициент **X:1** = отношение яркостей по WCAG 2.1. **Body 4.5** = нужно ≥ **4.5** для обычного текста 16pt.

| Фон (модель) | Белый заголовок | `#94A3B8` описание | Золотой заголовок `#F59E0B` |
|--------------|-----------------|-------------------|------------------------------|
| `#0a1128` gradientStart | **18.69:1** OK | **7.29:1** OK | **8.70:1** OK |
| `#1e3a5f` gradientMiddle | **11.50:1** OK | **4.49:1** порог (строго 4.5 — **риск**) | **5.36:1** OK |
| `#2e5090` gradientEnd | **7.88:1** OK | **3.07:1** **FAIL** body | **3.67:1** OK как **крупный** (≥3:1) |
| Нижняя зона (blend к `#2e5090`) `rgb(25,44,79)` | **13.87:1** OK | **5.41:1** OK | **6.46:1** OK |
| Карточка `#1E293B` | **14.63:1** OK | **5.71:1** OK | **6.81:1** OK |

**Вывод:** без отдельной карточки описание **`textSecondary` на самом светлом стопе градиента** (`#2e5090`) **не тянет 4.5:1**. На среднем стопе — на грани. После затемнения низа (как в приложении) зона у кнопок **лучше**, но центр экрана может оставаться ближе к «светлому» синему — **карточка `#1E293B` (или material с эквивалентным итоговым RGB)** стабилизирует контраст.

## Рекомендации под следующий шаг плана

1. **Ввести карточку** (сплошная или почти сплошная поверхность **не светлее** `#1E293B` под блок заголовок+описание) — тогда `textSecondary` и белый/золотой уже **в норме** по таблице 1.  
2. После смены фона карточки — **один проход** Accessibility Inspector на **самом длинном** описании (DE/FR) и на **шаге 7** (золото + серый).  
3. **Тёмная тема:** если появится отдельная светлая поверхность карточки — **пересчитать** строки таблицы 1 для новых hex.
