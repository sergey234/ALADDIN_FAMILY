# Продуктовое решение: одна активная семья на аккаунт (P3)

**Решение (v1, зафиксировано для текущей реализации API):**

- У одного пользователя в продукте считается **не более одной «активной» семьи** в смысле клиента: сохранённый `family_id`, JWT и ответ `GET /api/family/members` должны согласовываться.
- **Несколько семей на один `user_id`** в базе не является целевым сценарием для UX. Если такие строки появляются (миграции, баги), сервер выбирает одну семью по правилу «членство + `last_active`» или владелец — это **временный технический** выбор, а не продуктовая фича.

**Что не делаем в v1 без отдельного эпика:**

- Публичный переключатель «моя семья A / семья B» в приложении.
- Отдельное поле `active_family_id` в профиле (можно запланировать в v2 при появлении требования).

**Следствие для разработки:**

- Конфликт `familyId` (клиент) vs семья по JWT → **HTTP 409** и понятное сообщение в приложении — ожидаемое поведение, а не авария.
