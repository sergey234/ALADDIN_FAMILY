## 🔐 КАК ПОЯВЛЯЕТСЯ ТОКЕН - ПОЛНАЯ ЦЕПОЧКА

### **1. РЕГИСТРАЦИЯ/ЛОГИН (FamilyRegistrationViewModel)**

**Путь:** `ViewModels/FamilyRegistrationViewModel.swift` → `saveTokens()`

**Процесс:**
1. Пользователь регистрируется/логинится через онбординг
2. API возвращает `accessToken` и `refreshToken`
3. Вызывается `saveTokens(accessToken:refreshToken:)`
4. Токены сохраняются в Keychain:
   ```swift
   KeychainManager.shared.save(accessToken, forKey: .authToken)
   KeychainManager.shared.save(refreshToken, forKey: .refreshToken)
   ```
5. Проверяется, что токены действительно сохранены
6. Отправляется уведомление `UserDidLogin`

**✅ ПРОВЕРКА:** Сохранение работает корректно с проверкой

---

### **2. ЗАГРУЗКА ПРИ СТАРТЕ (SubscriptionManager)**

**Путь:** `Core/Managers/SubscriptionManager.swift` → `loadPersistedData()`

**Процесс:**
1. При инициализации `SubscriptionManager` вызывается `loadPersistedData()`
2. Загружается токен из Keychain:
   ```swift
   if let tokenData = loadFromKeychain(key: tokenKey),
      let token = try? JSONDecoder().decode(JWTToken.self, from: tokenData) {
       currentToken = token
       // ✅ КРИТИЧНО: Также восстанавливаем токен в AppConfig
       AppConfig.authToken = token.token
   }
   ```
3. Токен восстанавливается в `AppConfig.authToken` для NetworkManager

**✅ ПРОВЕРКА:** Загрузка работает, токен восстанавливается в AppConfig

---

### **3. ЧТЕНИЕ ТОКЕНА (AppConfig)**

**Путь:** `Core/Config/AppConfig.swift` → `authToken` getter

**Процесс:**
1. При обращении к `AppConfig.authToken`:
   ```swift
   static var authToken: String? {
       get {
           // Сначала пробуем Keychain (основное хранилище)
           if let keychainToken = KeychainManager.shared.loadString(forKey: .authToken) {
               return keychainToken
           }
           // Fallback на UserDefaults для обратной совместимости
           return UserDefaults.standard.string(forKey: AppConfig.UserDefaultsKeys.authToken)
       }
   }
   ```
2. Сначала читается из Keychain
3. Если нет в Keychain - читается из UserDefaults (fallback)

**✅ ПРОВЕРКА:** Чтение работает корректно

## ⚠️ ВОЗМОЖНЫЕ ПРОБЛЕМЫ В ЦЕПОЧКЕ

### **Проблема 1: Токен не загружается при старте**

**Симптомы:**
- Токен есть в Keychain
- Но `AppConfig.authToken == nil` при старте
- `SubscriptionManager.loadPersistedData()` вызывается, но токен не восстанавливается

**Причины:**
1. ❓ `SubscriptionManager` инициализируется позже, чем `AnalyticsViewModel.load()`
2. ❓ Токен в Keychain в формате JWTToken, а не просто String
3. ❓ Ошибка декодирования JWTToken из Keychain

**Решение:**
- ✅ `TokenManager` уже решает эту проблему - проверяет Keychain напрямую
- ✅ Ждет загрузки токена до 500ms

---

### **Проблема 2: Токен не сохраняется при регистрации**

**Симптомы:**
- Регистрация проходит успешно
- Но токен не сохраняется в Keychain
- При следующем запуске токена нет

**Причины:**
1. ❓ Ошибка сохранения в Keychain
2. ❓ Проверка сохранения не проходит
3. ❓ Токен сохраняется, но в неправильном формате

**Решение:**
- ✅ `saveTokens()` уже проверяет сохранение
- ✅ Есть повторная попытка сохранения

---

### **Проблема 3: Токен удаляется**

**Симптомы:**
- Токен был, но исчез
- Пользователь не выходил из аккаунта

**Причины:**
1. ❓ SessionExpired срабатывает неправильно
2. ❓ Токен очищается при ошибках
3. ❓ Проблемы с Keychain (переустановка приложения)

**Решение:**
- ✅ Мы исправили ложные срабатывания SessionExpired
- ✅ SessionExpired теперь только при реальной 401 ошибке
