## 📊 АРХИТЕКТУРА РЕШЕНИЯ

```
TokenHealthMonitor.performProactiveRefresh()
    ↓
ШАГ 1: refreshToken() с retry (2 попытки)
    ├─ Попытка 1 → Успех → saveNewToken() → ✅
    └─ Попытка 1 → Ошибка → Попытка 2 (через 2 сек) → Успех → saveNewToken() → ✅
    └─ Обе попытки → Ошибка → Fallback
    ↓
ШАГ 2: Fallback - registerDeviceAnonymously()
    └─ Всегда работает → saveNewToken() → ✅
    ↓
saveNewToken() [УЛУЧШЕННАЯ ВЕРСИЯ]
    ├─ 1. AppConfig.authToken = новый_токен
    ├─ 2. KeychainManager.save(access_token)
    ├─ 3. KeychainManager.save(refresh_token)
    ├─ 4. СОГЛАСОВАНИЕ С ТАРИФАМИ:
    │   ├─ 4.1. extractSubscriptionFromJWT() → извлечь тариф
    │   ├─ 4.2. Если найден → сохранить в SubscriptionManager
    │   └─ 4.3. Если НЕ найден → fetchSubscriptionFromServer()
    ├─ 5. SubscriptionManager.storeToken(jwtToken)
    └─ 6. TokenHealthMonitor.startMonitoring()
```
