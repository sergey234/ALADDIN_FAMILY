## 🔬 ДЕТАЛЬНЫЙ АНАЛИЗ ПРОБЛЕМЫ

### Проблема 1: Доступ к `@MainActor` свойствам

**Файл:** `ComponentStatusService.swift`
```swift
@MainActor
class ComponentStatusService: ObservableObject {
    @Published var componentStatuses: [String: ComponentStatus] = [:]
    // ...
}
```

**Проблема:**
- `ComponentStatusService` помечен как `@MainActor`
- Это означает, что все его методы и свойства доступны только на главном потоке
- `Task { @MainActor in }` создает новый контекст, но доступ к `shared` может быть проблематичным

**Почему это вызывает ошибки:**
1. Swift компилятор строго проверяет доступ к `@MainActor` свойствам
2. `Task { @MainActor in }` не гарантирует, что `ComponentStatusService.shared` будет доступен сразу
3. Может потребоваться явный `await` для доступа к `@MainActor` свойствам

### Проблема 2: Использование `@Published` свойств

**Проблема:**
- `componentStatuses` - это `@Published` свойство
- `@Published` свойства не требуют `await`, но доступ к ним должен быть на главном потоке
- В async контексте доступ может быть проблематичным

**Почему это вызывает ошибки:**
1. SwiftUI `@Published` свойства синхронны, но требуют главного потока
2. `Task { @MainActor in }` должен работать, но компилятор может не понимать это
3. Может потребоваться явный вызов через `await MainActor.run`

### Проблема 3: Дублирование `MainActor.run`

**Проблема:**
- Внутри `Task { @MainActor in }` используется `await MainActor.run { }`
- Это избыточно и может вызывать ошибки

**Код с проблемой:**
```swift
Task { @MainActor in
    // ...
    await MainActor.run {
        toastManager.showSuccess(...)
    }
}
```

**Почему это вызывает ошибки:**
- `Task { @MainActor in }` уже на главном потоке
- `await MainActor.run` внутри него избыточно и может вызывать deadlock или ошибки компиляции

   - Использование методов предпочтительнее прямого доступа к свойствам
