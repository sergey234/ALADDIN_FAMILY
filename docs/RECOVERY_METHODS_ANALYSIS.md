## ✅ РЕАЛЬНЫЕ МЕТОДЫ ВОССТАНОВЛЕНИЯ (АНОНИМНЫЕ)

### 1. Recovery Code (Код восстановления) ✅ РАБОТАЕТ

**Реализовано:**
- ✅ `RecoveryCodeModal` - показ кода восстановления
- ✅ Генерация Recovery Code при создании семьи
- ✅ Формат: `FAM-A1B2-C3D4-E5F6`
- ✅ QR-код для кода восстановления
- ✅ Копирование кода
- ✅ Поделиться кодом

**Backend API:**
- ✅ `GET /api/family/recover/{family_id}` - восстановление доступа к семье
- ✅ `POST /api/family/send-recovery-email` - отправка кода на email (email НЕ сохраняется!)

**iOS реализация:**
- ✅ `recoverAccess(withCode:)` в `FamilyRegistrationViewModel`
- ✅ `recoverFamily(familyID:)` в `NetworkManager`
- ✅ Код сохраняется в `FamilyRegistrationViewModel.recoveryCode`
- ✅ API возвращает `recovery_code` в ответе `CreateFamilyResponse`

**Как работает:**
1. Пользователь создает семью → получает Recovery Code
2. При потере доступа → вводит Recovery Code
3. Система восстанавливает доступ к семье по `family_id`

**Как работает (когда POST join доступен на сервере):**

2. Система извлекает `family_id` из кода
3. Пользователь присоединяется к семье

### 4. Email отправка кода (ОПЦИОНАЛЬНО) ⚠️

**Backend API:**
- ✅ `POST /api/family/send-recovery-email` - отправка кода на email
- ⚠️ **ВАЖНО:** Email НЕ сохраняется в базе данных!
- ⚠️ Письмо отправлено → email забыт

**Как работает:**
1. Пользователь запрашивает отправку кода на email
2. Backend отправляет письмо с Recovery Code
3. Email НЕ сохраняется (соответствует анонимности)
4. Пользователь использует код из письма для восстановления

**⚠️ ПРОБЛЕМА:** В iOS приложении этот метод НЕ реализован (нет UI для ввода email).

**Как работает:**

**⚠️ ВАЖНО:** Email/Phone восстановление **НЕ ДОЛЖНО** быть реализовано, так как:
- Требует сбора персональных данных (email/телефон)
