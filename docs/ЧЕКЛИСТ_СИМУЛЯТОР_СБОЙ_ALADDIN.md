# Чеклист «раз в сбой» симулятора (схема **ALADDIN**)

Контекст: на **Intel Mac** (в т.ч. две видеокарты) возможны падения **SpringBoard** с **METAL 102** / обрывом **SimMetalHost** — это **среда симулятора**, а не баг кода приложения.

---

## 1. Схема и запуск

- Выберите схему **`ALADDIN`** (не дубликат **`ALADDIN 1`**).
- В общей схеме уже задано: запуск без LLDB (**PosixSpawn**), **GPU Frame Capture** отключён, **GPU Validation** отключён, **Debug XPC services** выключен, **View Debugging** и **вставка dylib для view debugging** выключены.
- Если Xcode снова подмешивает отладку: **Product → Scheme → Edit Scheme → Run → Diagnostics / Options** — отключите View Debugging и всё про dylib; сохраните схему.
- После неудачного Run при необходимости проверьте в логе **Event Metadata**, что не остались **`param_debugger_attachToXPC = 1`** и флаги **`param_diag_viewDebugging_*`**, если вы хотите минимальный вмешательный запуск.

---

## 2. Симулятор (устройство и состояние)

- Используйте стабильные конфиги, например **iPhone 13** или **iPhone 15** с нужным **iOS (например 18.4)**; **iPhone 16 Pro** не делайте единственным рабочим девайсом, пока запуск не стабилен.
- При повторяющихся ошибках открытия приложения (**FBSOpenApplicationServiceErrorDomain**, «SpringBoard crashed»): **Device → Erase All Content and Settings** или **удалить симулятор и создать новый** с тем же типом.

---

## 3. Хост (Mac)

- Полностью закройте **Simulator** и **Xcode**, при необходимости **перезагрузите Mac** (часто снимает зависание цепочки **SimMetalHost** / CoreSimulator).
- Не нагружайте параллельно тяжёлым Metal (игры, другой рендер), если симулятор уже нестабилен.

---

## 4. Отделить проблему среды от приложения

- Запустите сборку на **физическом iPhone**. Если на устройстве всё ок, а симулятор падает — **не рефакторьте приложение** под краш SpringBoard/MTLSimDriver.
- Краткая проверка по отчёту о краше: процесс **`com.apple.springboard`**, стеки **`MTLSimDriver`**, **`SimMetalHost`**, **`METAL 102`** — повод смотреть среду, а не бизнес-логику `family.aladdin.ios`.

---

## 5. Если сбой повторяется стабильно

- Оформите отчёт в **Feedback Assistant** (Xcode / macOS / симулятор), приложите **полный crash SpringBoard** и версии **Xcode / macOS / runtime** симулятора.
- Для ежедневной разработки рассмотрите **основной цикл на реальном устройстве**; для CI симулятора — по возможности **Apple Silicon** или облако: на Intel iOS 18+ симулятор может оставаться «хрупким».

---

*Файл схемы в репозитории: `ALADDIN.xcodeproj/xcshareddata/xcschemes/ALADDIN.xcscheme`.*
