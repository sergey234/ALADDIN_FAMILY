## 📖 ЧАСТЬ 1: КАК РАБОТАЮТ ТОКЕНЫ (ПРОСТЫМ ЯЗЫКОМ)

### 🎫 Что такое токен?

**Токен = пропуск для входа в защищенные части приложения**

Представь, что приложение - это клуб:
- **Без токена** = ты стоишь на улице, не можешь войти
- **С токеном** = у тебя есть пропуск, можешь войти и пользоваться всеми функциями

### 🏠 Где хранятся токены? (3 места)

**1. Keychain (сейф)**
- Самое безопасное место
- Токен хранится даже после перезапуска приложения
- Как сейф в банке - надежно, но нужно время чтобы открыть

**2. AppConfig (быстрый доступ)**
- Быстрый доступ для NetworkManager
- Как карман - быстро достать, но может потеряться
- Используется для отправки запросов на сервер

**3. SubscriptionManager (память)**
- Хранится в памяти приложения
- Быстрый доступ, но пропадает при закрытии приложения
- Как записная книжка - удобно, но не навсегда

### 🔄 Как получается токен?

**Сценарий 1: Первый запуск приложения**
```
1. Приложение запускается
2. Проверяет: "Есть ли токен в сейфе (Keychain)?"
3. Нет токена → Регистрирует устройство на сервере
4. Сервер выдает токен
5. Токен сохраняется в 3 места:
   - Keychain (сейф) ✅
   - AppConfig (карман) ✅
   - SubscriptionManager (память) ✅
```

**Сценарий 2: Повторный запуск**
```
1. Приложение запускается
2. Проверяет: "Есть ли токен в сейфе?"
3. Есть токен → Загружает из сейфа
4. Восстанавливает в AppConfig и SubscriptionManager
```

### 🌐 Как используется токен?

**Когда приложение делает запрос к серверу:**
```
1. NetworkManager готовит запрос
2. Проверяет: "Нужна ли авторизация?" (requiresAuth: true)
3. Если нужна → Берет токен из AppConfig.authToken
4. Добавляет в заголовок: "Authorization: Bearer {токен}"
5. Отправляет запрос на сервер
6. Сервер проверяет токен
7. Если токен валидный → Возвращает данные ✅
8. Если токен отсутствует/невалидный → Возвращает 403 ошибку ❌
```

## ❌ ЧАСТЬ 2: В ЧЕМ ПРОБЛЕМА? (ПРОСТЫМ ЯЗЫКОМ)

### Проблема 1: Токен потерялся между хранилищами

**Что происходит:**
```
1. Токен есть в SubscriptionManager (память) ✅
2. Токен есть в Keychain (сейф) ✅
3. НО токена НЕТ в AppConfig (карман) ❌
4. NetworkManager ищет токен в AppConfig
5. Не находит → Отправляет запрос БЕЗ токена
6. Сервер видит запрос без токена → Возвращает 403 ошибку
```

**Почему это происходит?**
- При сохранении токена иногда не синхронизируется AppConfig
- При загрузке из Keychain иногда не восстанавливается AppConfig
- Race condition: запросы могут начаться до завершения синхронизации

### Проблема 2: Нет автоматического восстановления

**Что происходит:**
```
1. Запрос отправляется без токена
2. Сервер возвращает 403 ошибку
3. Приложение показывает ошибку пользователю
4. НО не пытается автоматически:
   - Восстановить токен из других хранилищ
   - Перерегистрировать устройство
   - Получить новый токен
```

**Почему это плохо?**
- Пользователь видит ошибку, но не знает что делать
- Приложение могло бы само исправить проблему
- Но сейчас этого не делает

### Проблема 3: Токен истекает, но не обновляется

**Что происходит:**
```
1. Токен выдан на 24 часа
2. Через 24 часа токен истекает
3. Приложение пытается обновить токен
4. НО для device tokens нет refresh token
5. Обновление невозможно
6. Нужна перерегистрация устройства
7. НО перерегистрация не происходит автоматически
```

**Почему это плохо?**
- Токен истекает каждые 24 часа
- Без refresh token нужно перерегистрироваться
- Но перерегистрация не происходит автоматически
- Пользователь видит ошибки

## ✅ ЧАСТЬ 3: МОЕ РЕШЕНИЕ (ПРОСТЫМ ЯЗЫКОМ)

### Решение 1: Гарантировать синхронизацию токенов

**Что делаем:**
```swift
// При сохранении токена
func storeToken(_ token: JWTToken) {
    // 1. Сохраняем в SubscriptionManager
    currentToken = token
    
    // 2. ✅ ВСЕГДА сохраняем в AppConfig
    AppConfig.authToken = token.token
    
    // 3. ✅ ПРОВЕРЯЕМ что сохранилось
    if AppConfig.authToken == nil {
        // Если не сохранилось - повторяем попытку
        AppConfig.authToken = token.token
    }
    
    // 4. Сохраняем в Keychain
    saveToKeychain(token)
}
```

**Простыми словами:**
- При сохранении токена ВСЕГДА сохраняем во все 3 места
- Проверяем что сохранилось
- Если не сохранилось - повторяем попытку

### Решение 2: Восстановление токена перед запросами

**Что делаем:**
```swift
// Перед отправкой запроса
func get(...) {
    if requiresAuth {
        // ✅ ПРОВЕРЯЕМ: Есть ли токен в AppConfig?
        if AppConfig.authToken == nil {
            // Нет токена → Пытаемся восстановить из SubscriptionManager
            if let token = SubscriptionManager.shared.currentToken {
                AppConfig.authToken = token.token
                print("✅ Токен восстановлен!")
            }
        }
        
        // Теперь точно есть токен (или ошибка)
        guard let token = AppConfig.authToken else {
            return error("Токен отсутствует")
        }
        
        // Отправляем запрос с токеном
        request.setValue("Bearer \(token)", ...)
    }
}
```

**Простыми словами:**
- Перед каждым запросом проверяем токен
- Если токена нет в AppConfig → ищем в SubscriptionManager
- Если нашли → восстанавливаем в AppConfig
- Теперь запрос идет с токеном

### Решение 3: Автоматическая перерегистрация при 403

**Что делаем:**
```swift
// При получении 403 ошибки
func performRequest(...) {
    if httpResponse.statusCode == 403 {
        // ✅ ОБНАРУЖЕНА 403 → Перерегистрируем устройство
        print("🔄 Обнаружена 403 - перерегистрируем устройство")
        
        Task {
            // Перерегистрируем устройство
            await SubscriptionManager.shared.performDeviceRegistration()
            
            // Теперь токен должен быть восстановлен
            // Можно повторить запрос (опционально)
        }
    }
}
```

**Простыми словами:**
- Если сервер вернул 403 → значит токен невалидный или отсутствует
- Автоматически перерегистрируем устройство
- Получаем новый токен
- Теперь запросы должны работать
