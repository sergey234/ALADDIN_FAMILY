## 3. В чём корневая проблема с Git (почему «просто push» не работает)

### 3.1 Две разные истории: локальный `main` и `origin/master`

Проверки:

```bash
git fetch origin
git merge-base HEAD origin/master   # завершается с кодом 1 — общего предка НЕТ
```

Первые коммиты различаются:

| Ветка            | Первый коммит (корень истории) |
|------------------|---------------------------------|
| Локальный `main` | `67821666` — *Initial commit: ALADDIN FAMILY AI Security System* |
| `origin/master`  | `a99cc886` — *Initial commit - before fixes* |

То есть это **unrelated histories** (склеены разные «корни» репозитория). Поэтому:

- `git push origin main` к **`origin/main`** некорректно ожидать как «продолжение» релиза 186 — у `origin/main` своя короткая история (на момент анализа — пара коммитов), она **не** та же линия, что **`origin/master`** с `40b71004`.
- Локальная ветка показывала псевдо-метрики вроде «ahead 227 / behind …» — это симптом **разошедшихся несовместимых графов**, а не «нужно rebase из главы».

### 3.2 Где «правда» для CI релиза 186

Успешный сценарий пользователя:

- **Ветка:** `master` (не `main`).
- **Коммит релиза 186:** `40b71004` — сообщение вроде: *Release build 186: Aladdin Kids branding, child header layout, iOS workspace rules.*

Следующий коммит на **`origin/master`** должен быть **над** `40b71004` одним или несколькими коммитами с изменениями 187.

### 3.3 Почему `git rebase origin/main` — плохая идея здесь

Пользователь **не просил** rebase. Технически rebase локального `main` на `origin/main` пытается «переиграть» сотни коммитов на другой корень и ломается (конфликты с неотслеживаемыми файлами, неверная топология). **Не повторять без явного запроса и без аудита истории.**

### 3.4 Про cherry-pick / отдельный worktree

Cherry-pick коммита `77d8daed` поверх **`origin/master`** был **попыткой** перенести **один** снимок изменений на «правильную» базу GitHub без rebase локальной ветки. Пользователь **отверг** этот путь («Какой нафиг cherry pick»). Значит: **дальнейшую стратегию выбирает человек**; ниже — нейтральные варианты, без указания «делать только так».

Возможно остался **второй worktree** (если команда завершилась):

- Путь: `/Users/sergejhlystov/ALADDIN_PUSH187`  
- Состояние: detached HEAD на **`40b71004`** после `git worktree add … origin/master`.

Проверка/уборка (выполняет человек, если нужно):


## 4. Что НЕ нужно делать без явного указания пользователя

- Не запускать **`git rebase origin/main`** или **`git rebase origin/master`** «чтобы push прошёл».
- Не делать **`git push --force`** на `master`/`main` без письменного согласия.
- Не «склеивать» unrelated histories через **`--allow-unrelated-histories`** без понимания последствий для команды.
- Не добавлять в коммит тысячи **`??` untracked** резервных копий из рабочего каталога — у пользователя огромное число неотслеживаемых файлов; пушить нужно только осмысленные пути (как минимум отслеживаемые изменения под `ALADDIN_NEW/mobile_apps/ALADDIN_iOS/` по согласованию).
