## 🎯 ЭТАП 5.1: ТЕСТИРОВАНИЕ refreshToken()

### **Сценарий 1.1: Успешное обновление токена (попытка 1)**

**Предусловия:**
- Пользователь авторизован
- Токен действителен, но истекает через < 5 минут
- Refresh token существует в Keychain
- Сервер доступен

**Шаги:**
1. Запустить приложение
2. Дождаться автоматического обновления токена (TokenHealthMonitor)
3. Проверить логи:
   - `🔄 DEFENSIVE JWT: Попытка 1: обновление через refresh_token`
   - `✅ DEFENSIVE JWT: Токен успешно обновлен через refresh_token (попытка 1)`
   - `💾 DEFENSIVE JWT: Сохранение нового токена с согласованием тарифов`
   - `✅ DEFENSIVE JWT: Access token сохранен в AppConfig.authToken`
   - `✅ DEFENSIVE JWT: Refresh token сохранен в Keychain`
   - `✅ DEFENSIVE JWT: Тариф извлечен из JWT: [уровень]`
   - `✅ DEFENSIVE JWT: Токен сохранен с тарифом: [уровень]`

**Ожидаемый результат:**
- ✅ Токен успешно обновлен
- ✅ `AppConfig.authToken` содержит новый токен
- ✅ Refresh token сохранен в Keychain
- ✅ Тариф извлечен из JWT и сохранен в `SubscriptionManager`
- ✅ Все API запросы используют новый токен
- ✅ Мониторинг перезапущен

**Проверка:**
```swift
// Проверить что токен обновлен
assert(AppConfig.authToken != nil)
assert(AppConfig.authToken != oldToken)

// Проверить что тариф сохранен
let currentToken = await SubscriptionManager.shared.currentToken
assert(currentToken?.subscriptionLevel != nil)
assert(currentToken?.limits != nil)
assert(currentToken?.components != nil)
```
