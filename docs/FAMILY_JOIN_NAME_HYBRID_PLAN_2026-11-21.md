## 0. Решение владельца (канон)

**Выбран путь B — «Гибрид имени»:**

| Было | Станет |
|------|--------|
| Обязательный шаг «Буква» A–Z | Поле **«Как вас зовут в семье?»** (RU + EN) |
| Уникальность `PARENT U` (`role + letter`) | Уникальность **`display_name`** внутри семьи (case-insensitive) |
| `personal_letter` обязателен в API | `personal_letter` **optional / legacy** (старые клиенты не ломаем) |
| Аватар/пин = выбранная буква | **Авто-инициал** = первая буква имени |
| Светлый/белый join-sheet | **Тёмный** семейный фон (как хаб), без сплошного белого |
| Ошибка «буква занята» | «Имя уже есть в семье — введите другое» |

Роль и возраст **остаются** (гармошки) — нужны для parental / elderly.  
Буква как UX-шаг **убирается полностью**.

| **7** | «Не найдено.» | Тупик | Preflight/invite 404; copy сырой | Фаза 2/3 human error + retry |

**Почему «все буквы заняты» — это иллюзия UX + старый контракт**, а не «в семье 26 человек»:
1. UI показывает все 26; занятость только после Submit.  
2. Уникальность — пара **роль+буква**, не «свободное место».  
3. Параллельно `already_in_another_family` блокирует join → «ничего не помогает».  
4. Ошибка иногда не сбрасывается при смене буквы.

**С именами эта ошибка класса `personal_letter_taken` уходит из продукта.**

## 2. Продуктовый поток (целевой)

### 2.1 Join существующей семьи (QR / код)

1. Скан QR **или** вставка `FAM-…`  
2. Preflight OK → экран присоединения (тёмный)  
3. Гармошка **1 · Роль**  
4. Гармошка **2 · Возраст**  
5. Поле **3 · Имя в семье** (кириллица и/или латиница)  
6. «Присоединиться к семье»  
7. Успех → семья + (как сейчас) auto-bind устройства при возможности  

**Нет:** шага буквы, экрана Promo, голого registration shell.

### 2.2 Правила имени

| Правило | Значение |
|---------|----------|
| Длина | 2–24 символа |
| Алфавит | Кириллица и/или латиница, пробел, дефис |
| Уникальность | `lower(trim(name))` **только в этой** `family_id` |
| Конфликт | «Имя „Маша“ уже есть. Введите другое (например Маша-2)» — **не** `personal_letter_taken` |
| Пусто | Нельзя; плейсхолдер RU/EN |
| Приватность | Имя видно семье; согласия: «имя в семье», не «личная буква» |
| Карточка | Имя + бейдж роли (`Маша` · Родитель), **не** `PARENT M` |
| Аватар/пин | Авто: первая буква/символ имени |

### 2.3 Create семьи

Тот же контракт имени вместо буквы. Один язык продукта везде.

### 2.4 Три двери (не путать)

| Дверь | Назначение | Куда вести |
|-------|------------|------------|
| **Приглашение / QR семьи** | Новый человек в семью | Только join (`InvitationCodeInputModal` / wizard) |
| **Восстановление** | Владелец вернуть доступ | Recovery flow; copy не «добавить человека» |
| **Бонусный / промокод** | Код от команды ALADDIN | `PromoActivationScreen`; FAM → **редирект на join** |

### Фаза 1 — контракт API (бэкенд)

- Лимит семьи (`family_roster_full`) остаётся; имя его не отменяет.

### 4.6 Security / privacy

- Имена только в семейном контуре.

### Как проверить join нового участника (Device QA)

**Подготовка**
1. Телефон A — владелец семьи, экран QR/приглашения (FAM).  
2. Телефон B — **чистый** профиль (или после одного «Удалить профиль»).  
3. Собрать свежий билд с этими правками на B.

**Сценарий «счастье»**
1. B: вставить/сканировать FAM → экран **тёмный**, не «бонусный код».  
2. Выбрать **1 Роль** (гармошка) → **2 Возраст** → **3 Имя** (`Маша` или `Dad`).  
3. «Присоединиться» → успех; на A участник виден как **Маша** / **Dad**, не `PARENT M`.  
4. Повторить join с тем же именем → полный текст «имя занято», без обрезки.  
5. Другое имя → успех (если есть слот).

**Регрессии**
6. Вставить FAM в «Активировать бонусный код» → уход на join.  
7. После delete профиля на B → сразу join в семью A без «телефон в другой семье».  
8. «Отмена/Закрыть» на join работает без перезапуска.  
9. Нет шага букв A–Z; нет сплошного белого join.  
10. Неверный/старый код → понятное «код не найден…», не сырое «Не найдено.»

**API smoke (опционально, с JWT)**  
`POST /api/family/join` с `display_name` без `personal_letter` → 200; дубль имени → 409 `display_name_taken`.
