## Простыми словами: экран согласия vs Sign in with Apple / Magic Link

### Экран «Согласие на обработку данных»

- **Что это:** юридический шаг перед продолжением **регистрации семьи / добавления участника** в том потоке, где используется `ConsentModal`.
- **Зачем:** пользователь явно соглашается на обработку персональных данных по правилам приложения — без этого нельзя честно запускать сценарии с ФИО, ролью, возрастом, QR и т.д.
- **Это не вход в аккаунт сам по себе:** это **разрешение на данные**, а не замена пароля.

### Sign in with Apple и Magic Link

- **Что это:** способы **войти в приложение / получить сессию** (кто вы такой для сервера), без классического пароля в форме.
  - **Sign in with Apple** — Apple выдаёт идентификатор; приложение обменивает это на ваш JWT на бэкенде.
  - **Magic Link** — вы вводите email, сервер шлёт письмо со ссылкой; по логам видно запрос  
    `POST /api/auth/magic-link/request` с телом вроде  
    `{"email":"…","redirectUrl":"aladdin://auth/magic"}` — открытие ссылки в приложении завершает вход.
- **Зачем они висели на экране согласия:** в `MainScreenWithRegistration` блок входа был сделан как **верхний overlay на весь экран**, поэтому он **рисовался поверх модалки согласия** (баг слоя UI, не логика согласия).
- **Исправление в коде:** показывать Apple/Magic Link **только когда не открыто окно согласия** (`!registrationVM.showConsentModal`). Имеет смысл в будущем вынести вход на **отдельный экран** до/после онбординга — чтобы не смешивать роли.

### Про лог JWT «действителен ещё 30351142 секунд»

Если в логе всё ещё огромное число секунд — это либо **старая сборка** без правки разбора поля `exp`, либо реально долгоживущий токен (~350 дней ≈ такой порядок секунд). После выката исправления в `JWTTokenManager` в логах должны быть **дни/часы** для длинного срока.

## Блок B — Главная: жёлтая карточка «Семья», тариф и капсула статуса

### Разделение понятий (важно для продукта и поддержки)

1. **Строка «Тариф: …» и цвет градиента карточки** — из **`SubscriptionManager`** (`getCurrentLevel()`, синх с сервером / JWT / trial).
2. **Капсула справа («Активна» / «Отключена» / «Нет связи» и т.д.)** — из **`MainViewModel.familyProtectionStatus`**, данные с **`getFamilyStats`**, плюс логика **TTL и порога ошибок** при сбоях сети.

Пользователю нельзя оставлять впечатление, что красная капсула = «тариф не оплачен», если это статус защиты/API.

### План работ

| № | Задача |
|---|--------|
| B1 | UX-копирайт: подпись у капсулы вроде «Статус защиты семьи», чтобы не путать с тарифом | **Сделано:** ключ `main_family_protection_badge_caption`, подпись над `FamilyStatusBadge` на главной |
| B2 | Логирование: при смене `familyProtectionStatus` — причина (API raw, error path, fails, ttl) — уже частично есть (`MAIN.STATUS`), проверить покрытие сценариев |
| B3 | Подстроить `statusTTLSec` / `failuresThreshold` после метрик с поля (меньше ложных «красных» при единичных обрывах) | **Сделано:** TTL 18 с, порог фейлов 3 (`MainViewModel`) |

### E‑Instruments (устройство, Release или Debug)

1. Xcode → Product → Profile → выбрать приложение → **SwiftUI** или **Time Profiler**.  
2. Запись **60–90 с**: главная → тарифы → назад на главную → добавить участника → пройти согласие → назад → открыть **семейный чат** → ввести текст (не отправлять при желании) → назад.  
3. Зафиксировать: главный поток, частота метрик (после throttle), тяжёлые `body` при необходимости.
