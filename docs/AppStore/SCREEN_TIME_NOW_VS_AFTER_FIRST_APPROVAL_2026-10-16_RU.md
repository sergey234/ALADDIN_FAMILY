## 1. Как лучше поступить (рекомендация)

| Этап | Действие | Зачем |
|------|----------|--------|
| **Сейчас** | Довести и опубликовать текущий продукт **без** системного Screen Time | Не смешивать Guideline 2.1 / первую публикацию с долгим Family Controls |
| **Сейчас** | В Store / письме Apple / тарифах **не обещать** «блокируем Instagram / считаем Screen Time» | Иначе риск отклонения |
| **Сейчас** | Оставить честный UI: лимиты сохраняются, блок «Статистика сегодня» — empty, без моков | Доверие + готовность к будущему |
| **После первой успешной публикации** | Подать Family Controls Distribution (Account Holder) | Отдельный трек на **следующую** версию |
| **После Assigned от Apple** | Ставить Monitor + Report (+ Shield), реальные цифры | Уже не ломает первую публикацию |

**Итог:** ваш порядок верный — **сначала публикация, потом заявление на Screen Time.**

Это **не** запрещено и **не** требует заявки Distribution.

### 2.2. Документы / процесс (сейчас)

| # | Что |
|---|-----|
| 1 | Держать канон: Screen Time = **следующая** версия |
| 2 | В Review Notes / письмо Apple: явно **не** заявлять системный Screen Time |

### 2.3. Чего НЕ делать сейчас

| # | Не делать | Почему |
|---|-----------|--------|
| 1 | Не создавать targets DeviceActivity Monitor/Report «в прод» | Без entitlement Archive/подписи сломаются или введут в заблуждение |
| 2 | Не добавлять `com.apple.developer.family-controls` в релизный entitlements | Пока нет Distribution Assigned |
| 3 | Не включать `allowsSystemFamilyControls = true` в App Store build | Claims выключены специально |
| 4 | Не возвращать мок «18 min Instagram» | Обман пользователя и Review |
| 5 | Не писать в ASO/тарифах «блокируем чужие приложения через Screen Time» | Guideline риск |
| 6 | Не подавать Family Controls заявку **до** первой успешной публикации | Ваше решение: сначала зелёный релиз |

## 3. Что «устанавливаем / везём» в ПЕРВОЙ публикации

### Включается в первую согласованную сборку

- Основное приложение ALADDIN (семья, защита, звонки, antifake, удобный режим и т.д. — по текущему scope релиза).  
- Уже существующие extensions: Content Blocker, Call Directory, Share, Widgets (что уже в Archive).  
- Родительские **настройки времени** (лимиты/расписание/сон) как правила в приложении.  
- Честный UI статистики (empty).  
- `AppStoreBuildPolicy.allowsSystemFamilyControls = false`.

### Не включается в первую публикацию

- Device Activity Monitor  
- Device Activity Report  
- Shield Configuration / Shield Action  
- Entitlement Family Controls  
- Обещания «системный Screen Time» в Store

## 4. Что делаем ПОСЛЕ первой успешной публикации и одобрения Apple

Порядок строго такой:

```
Первая публикация ✅
    → (по желанию 1–3 дня стабильности / без срочного reject)
    → Подача Family Controls Distribution (Account Holder)
    → Ожидание Assigned
    → Код Monitor + Report (+ Shield)
    → Device QA (2 iPhone)
    → Следующая версия в App Store с честными claims
```

### Фаза P1 — Сразу после зелёной публикации (1 день)

| # | Задача | Кто |
|---|--------|-----|
| P1.1 | Зафиксировать: «первая версия live, Screen Time = vNext» | Владелец |
| P1.2 | Утвердить Bundle ID: `…DeviceActivityMonitor`, `…DeviceActivityReport` (+ Shield по желанию) | Владелец |
| P1.3 | Подготовить текст заявки (есть в Distribution-плане §5) | Агент черновик / владелец подаёт |
| P1.4 | Account Holder подаёт Capability Request на main + Monitor + Report | **Владелец** |

### Фаза P2 — Пока Apple думает (можно параллельно, без entitlement)

| # | Задача | Примечание |
|---|--------|------------|
| P2.1 | Черновик `ScreenTimeUsageStore` (App Group schema) за feature-flag / `#if` | Не включать в App Store claims |
| P2.2 | UX picker «какие apps ограничить» на своих строках (ещё без системных tokens) | Не выдавать за системный Screen Time |
| P2.3 | Улучшить copy empty + онбординг родителя | Без ложных обещаний |
| P2.4 | Не мержить FC entitlement в релизную ветку до Assigned | Важно |

### Фаза P3 — После Assigned (инженерия следующей версии)

| # | Задача |
|---|--------|
| P3.1 | App IDs + profiles + entitlement на main/extensions |
| P3.2 | Targets Monitor + Report в Xcode, embed |
| P3.3 | `fetchRealScreenTimeStats()` ← App Group |
| P3.4 | UI Семья / Advanced показывает реальные цифры |
| P3.5 | (Рекомендуется) Shield Configuration — блокировка |
| P3.6 | Device QA parent + child |
| P3.7 | Включить claims + `allowsSystemFamilyControls` в **новой** App Store сборке |
| P3.8 | TestFlight → Submit **следующей** версии |

## 5. Две колонки: СЕЙЧАС vs ПОСЛЕ

| Тема | Сейчас (до/во время первой публикации) | После первой публикации + Assigned |
|------|----------------------------------------|-------------------------------------|
| Заявление Family Controls | **Не подаём** | **Подаём** (Account Holder) |
| Monitor / Report extensions | Не ставим в релиз | Ставим |
| Entitlement `family-controls` | Нет | Да |
| Статистика usage | Empty / честно | Реальные минуты |
| Лимиты/расписание/сон | Да (настройки ALADDIN) | Да + системное применение |
| Блокировка чужих apps | Нет (не обещаем) | Да (Shield), после QA |
| Store / письмо Apple | Без Screen Time claims | С фактами только после QA |
| Главный фокус | Согласовать **первую** сборку | Следующая версия = Screen Time |

## 6. Мини-чеклист владельца

- [ ] Сохранить номер/дату заявки  
- [ ] Дать GO агенту на фазу P3 только после Assigned

## 7. Одна фраза для себя

> **Сейчас:** публикуем ALADDIN без системного Screen Time, с честными лимитами-настройками.  
> **Потом:** после первой зелёной публикации пишем заявление Apple → ставим Monitor/Report → в следующей версии показываем реальную статистику.
