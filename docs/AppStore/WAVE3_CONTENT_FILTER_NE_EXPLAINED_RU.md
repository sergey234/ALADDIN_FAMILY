# Content Filter / Network Extension — простыми словами (WAVE3)

**VPN в ALADDIN iOS не делаем.**  
Ни Packet Tunnel, ни «встроенный VPN», ни замена Happ.

---

## 1. Что такое Network Extension (NE) одной фразой

**Network Extension** — это набор технологий Apple, которыми приложение может **участвовать в сети телефона** не как обычная кнопка в UI, а как системный «помощник».

У NE есть разные роли. Нам важна только одна:

| Роль NE | Делает | У нас в WAVE3 |
|---------|--------|----------------|
| **Content Filter** | Смотрит: «этому сайту/соединению — можно или блок?» | **Да — цель** |
| DNS Proxy | Подменяет ответы DNS (блокирует домены на уровне имён) | Опция позже, если Filter сложно |
| **Packet Tunnel (VPN)** | Гонит почти весь трафик в туннель | **Нет. Запрещено** |
| Personal VPN | Профиль VPN в Настройках | **Нет** |

Задача 6 в портале = подготовить **Content Filter**, не VPN.

---

## 2. Что такое Content Filter

Представьте турникет на входе в интернет на телефоне ребёнка:

1. Ребёнок открывает TikTok / Chrome / игру с веб-вью.  
2. Система спрашивает наш фильтр: «пускать этот адрес?»  
3. Фильтр смотрит **правила родителя** (блок 18+, азарт, конкретные сайты…).  
4. Ответ: **разрешить** или **запретить**.  

Фильтр **не** шифрует трафик «как VPN» и **не** гонит его на наш сервер-туннель.  
Он только говорит iOS: allow / drop по правилам семьи.

---

## 3. Чем это НЕ VPN (важно)

| | Content Filter (мы) | VPN / Packet Tunnel (не мы) |
|--|---------------------|-----------------------------|
| Задача | Блокировать вредные сайты/домены | Спрятать IP / обойти блокировки / весь трафик через сервер |
| Трафик | Остаётся обычным путём оператора | Уходит в туннель на VPS |
| В Настройках iOS | «Контент-фильтр» / Screen Time–связанный фильтр | Профиль VPN ON/OFF |
| У ALADDIN | Родительский контроль | **Нет** — VPN у семьи через Happ и т.п. снаружи |
| Риск для Review | Нормальный parental claim | «Это VPN-приложение» — другой класс, мы не туда |

Если в портале случайно включить **Packet Tunnel** — Apple может решить, что ALADDIN = VPN. Поэтому в инструкции: только Content Filter.

## 4. Что уже есть сейчас (без NE Filter)

### Safari Content Blocker (уже в приложении)

- Работает **только в Safari** (и иногда Safari-движок).  
- Родитель включает категории / списки → Safari режет рекламу/сайты по правилам блокера.  
- **Не** закрывает Chrome, TikTok in-app browser, многие приложения.

В UI Parental мы уже пишем честно: «сейчас Safari; системный фильтр — после Apple».

### Что умеем без Content Filter

- Блок в Safari.  
- Screen Time / Shield (лимиты приложений) — это **другое** (минуты/щит), не фильтр сайтов.  
- Геозоны, SOS, «я в порядке» — не про веб.

---

## 5. Что сможем после полной реализации Content Filter

По шагам продукта (не всё в один день):

### 5.1 Для родителя

1. Открыть Родительский контроль → фильтр контента.  
2. Выбрать режим:
   - **Только Safari** (как сейчас), или  
   - **Системный фильтр** (Content Filter) — когда флаг и entitlement готовы.  
3. Задать правила: категории / чёрный список доменов / белый список (по мере реализации).  
4. Правила уходят на телефон ребёнка (API + App Group).  
5. На телефоне ребёнка iOS просит разрешить фильтр (системный диалог).

### 5.2 Что реально блокируется (цель продукта)

| Сценарий | Safari CB сейчас | Content Filter после ship |
|----------|------------------|---------------------------|
| Сайт 18+ в Safari | Да | Да |
| Тот же сайт в Chrome | Часто **нет** | **Да** (где Apple даёт фильтру видеть поток) |
| Ссылка внутри соцсети / in-app browser | Часто **нет** | Часто **да** (зависит от ОС и типа потока) |
| Само приложение TikTok как app | Нет (это Screen Time/Shield) | Нет — для apps по-прежнему Screen Time |
| «Обойти блокировку страны / сменить IP» | Нет | **Нет и не будет** — это VPN, не наш продукт |

### 5.3 Чего не обещаем

- 100% блок всего интернета навсегда (есть обходы, DoH, новые приложения).  
- Шпионаж переписки / чтение HTTPS-тела «как прокси».  
- VPN, смену региона, ускорение YouTube.  
- MDM / корпоративный контроль устройства.

Честный claim: **родительский веб-фильтр шире Safari**, плюс Screen Time на приложения.

## 6. Как это устроено технически (коротко)

```text
Родитель в ALADDIN
    → правила (блок/allow доменов)
    → сервер MAIN :8002 (parental API)
    → телефон ребёнка (App Group)

Расширение Content Filter на телефоне ребёнка
    → читает правила
    → на каждый сетевой запрос (где система спрашивает): allow или drop
```

Флаг в коде: `AppStoreBuildPolicy.allowsSystemContentFilter = false`  
пока нет GO и готовности. Включаем только после entitlement + кода F2 + финальной сборки.

Ограничения Apple (упрощённо): на iOS полноценный content filter часто связан с **Screen Time / child / supervised** сценариями — не «любой взрослый телефон без семьи». Детали — в TN3134 Apple; продукт позиционируем как **семейный родительский контроль**.

Они открывают дорогу к реализации.

## 8. Порядок «что когда»

| Когда | Что |
|-------|-----|
| **Сейчас** | Safari CB работает; портал §6 без VPN; UI honesty F3 |
| **После portal / capability** | Можно писать target Filter (F2), CI profiles (F4) |
| **После Device QA ST + FC** | Фильтр логично жить рядом со Screen Time на детском |
| **Финальная сборка** | System filter в IPA при `allowsSystemContentFilter = true` + GO |
| **Никогда в WAVE3** | Packet Tunnel / in-app VPN |

---

## 9. Одна фраза для себя

**Content Filter** = системный «турникет» сайтов по правилам родителя.  
**VPN** = туннель всего трафика — **не делаем**.  
Сейчас у нас турникет в основном в Safari; после реализации NE Filter — турникет шире по системе, где Apple позволяет.
