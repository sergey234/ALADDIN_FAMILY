## 1. ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ - ТОЛЬКО СТАНДАРТНЫЕ iOS API

### A. Функции безопасности

#### 1. Локальная защита данных

**Framework: LocalAuthentication** (стандартный iOS API)
- **Файл:** `Core/Security/SecurityManager.swift`
- **Использование:** Биометрическая аутентификация для доступа к приложению (Face ID/Touch ID)
- **Пример работы:**
  1. Пользователь открывает приложение
  2. Система запрашивает биометрическую аутентификацию через LocalAuthentication
  3. Данные обрабатываются только на устройстве, никогда не передаются
  4. После успешной аутентификации пользователь получает доступ к приложению
- **Соответствие:** ✅ Стандартный API, не требует специальных разрешений

**Framework: CryptoKit** (стандартный iOS API)
- **Файл:** `Core/Security/SecurityManager.swift`
- **Использование:** Локальное шифрование данных пользователя (AES-256-GCM)
- **Пример работы:**
  1. Пользовательские данные (токены, настройки) шифруются локально на устройстве
  2. Используется AES-256-GCM алгоритм шифрования из CryptoKit
  3. Ключи шифрования хранятся в Keychain (Security framework)
  4. Зашифрованные данные могут быть отправлены на backend, но ключи никогда не покидают устройство
- **Соответствие:** ✅ Стандартный API, данные шифруются только на устройстве

**Framework: Security (Keychain Services)** (стандартный iOS API)
- **Файл:** `Core/Security/SecurityManager.swift`
- **Использование:** Безопасное хранение токенов, паролей, ключей шифрования
- **Пример работы:**
  1. Приложение сохраняет токены доступа в Keychain через Security framework
  2. Keychain обеспечивает аппаратную защиту данных (Secure Enclave на поддерживаемых устройствах)
  3. Данные доступны только самому приложению и его расширениям через App Groups
  4. При удалении приложения данные автоматически удаляются из Keychain
- **Соответствие:** ✅ Стандартный API, данные хранятся локально

#### 2. Сетевая коммуникация

**Framework: URLSession** (стандартный iOS API)
- **Файл:** `Core/Network/NetworkManager.swift`
- **Использование:** HTTPS коммуникация с backend сервером
- **Реализация:** SSL Pinning для валидации сертификатов
- **Пример работы:**
  1. Приложение устанавливает HTTPS соединение с backend сервером через URLSession
  2. SSL Pinning проверяет, что сертификат сервера соответствует ожидаемому
  3. Все данные передаются через зашифрованное HTTPS соединение (TLS 1.2+)
  4. Backend сервер получает только обезличенные метаданные (URL, домены, типы контента)
- **Соответствие:** ✅ Стандартный API, нет VPN функциональности

#### 3. Content Blocker Extension для Safari

**Framework: SafariServices (SFContentBlockerManager)** (стандартный iOS API)
- **Файл:** `Core/ContentBlocker/ContentBlockerManager.swift`
- **Extension:** `ALADDINContentBlocker/ActionRequestHandler.swift`
- **Использование:** Блокировка нежелательного контента в Safari браузере
- **Пример работы:**
  1. Родитель настраивает категории блокировки в приложении (взрослый контент, насилие, азартные игры)
  2. Приложение создает JSON правила блокировки согласно стандарту Apple Content Blocker
  3. Правила сохраняются в App Group (`group.com.aladdin.family`) для обмена с Extension
  4. SFContentBlockerManager активирует Content Blocker Extension
  5. Когда ребенок открывает Safari и пытается зайти на заблокированный сайт, Safari автоматически блокирует его согласно правилам
  6. Ребенок видит страницу "Сайт заблокирован" вместо контента
  7. Блокировка происходит полностью на устройстве, без нагрузки на сервер
- **Соответствие:** ✅ Стандартный iOS API, разрешенный Apple для всех разработчиков. Работает только в Safari, не требует специальных разрешений

**Что мы НЕ используем:**
- ❌ **NEVPNManager** - Не используется (NetworkExtension framework закомментирован в коде)
- ❌ **VPN функциональность** - Удалена из приложения согласно руководящим принципам Apple

#### 4. Backend анализ безопасности

**Файл:** `Core/Network/APIService.swift`
- **Endpoints:** `/protection/*`, `/analytics/threats`
- **Пример работы:**
  1. Приложение отправляет обезличенные метаданные (URL, домены, типы контента) на наш backend сервер
  2. Backend анализирует данные с использованием AI/ML (3,581+ функций безопасности) на стороне сервера, не на устройстве
  3. Backend определяет потенциальные угрозы (мошеннические сайты, фишинг, вредоносный контент)
  4. Результаты возвращаются в приложение как рекомендации и оповещения
  5. Пользователь получает уведомление о потенциальной угрозе
  6. Пользователь принимает обоснованное решение на основе рекомендаций
  7. **НЕТ блокировки или принудительного применения на системном уровне** - мы предоставляем только рекомендации

### B. Функции родительского контроля

#### 1. Интерфейс настроек

**Framework: SwiftUI** (стандартный iOS API)
- **Файл:** `Screens/07_ParentalControlScreen.swift`
- **Использование:** Пользовательский интерфейс для настроек родительского контроля
- **Пример работы:**
  1. Родитель открывает экран "Родительский контроль" в приложении
  2. SwiftUI отображает интерфейс с настройками (лимиты времени, категории контента, правила)
  3. Родитель настраивает предпочтения через стандартные SwiftUI компоненты (Toggle, Picker, Slider)
  4. Настройки сохраняются локально и синхронизируются с backend
- **Соответствие:** ✅ Стандартный API

**Framework: UserDefaults / @AppStorage** (стандартный iOS API)
- **Файл:** `ViewModels/ParentalControlViewModel.swift`
- **Использование:** Локальное хранение предпочтений пользователя
- **Пример работы:**
  1. Родитель настраивает правила (например, "блокировать взрослый контент")
  2. Настройки сохраняются локально в UserDefaults через @AppStorage
  3. При следующем открытии приложения настройки загружаются автоматически
  4. Настройки также синхронизируются с backend для использования на других устройствах семьи
- **Соответствие:** ✅ Стандартный API

#### 2. Backend аналитика и отчеты

**Файл:** `Core/Network/APIService.swift`
- **Endpoints:** `/api/v1/parental-control/*`, `/analytics`
- **Пример работы:**
  1. Родитель настраивает предпочтения в приложении (например, "отслеживать время использования приложений")
  2. Предпочтения хранятся на backend сервере
  3. Приложение отправляет метаданные активности (типы приложений, время использования, категории контента) на backend
  4. Backend предоставляет аналитику и отчеты (например, "ребенок использовал YouTube 2 часа сегодня")
  5. Приложение отображает отчеты родителям в удобном формате
  6. Родители получают уведомления о важных событиях (например, "ребенок пытался зайти на заблокированный сайт")
  7. Родители используют отчеты для общения с детьми и руководства их поведением
  8. **НЕТ принудительного применения на системном уровне** - родители используют отчеты для семейного общения

**Что мы НЕ используем:**
- ❌ **Screen Time API** - Не используется (мы предоставляем собственный мониторинг через backend аналитику)
- ❌ **PermissionKit framework** - Не используется (мы используем стандартные iOS запросы разрешений)

#### 3. Уведомления

**Framework: UserNotifications** (стандартный iOS API)
- **Файл:** `Core/Notifications/NotificationManager.swift`
- **Использование:** Локальные уведомления и Push Notifications через Apple Push Notification Service (APNs)
- **Пример работы:**
  1. Backend обнаруживает потенциальную угрозу или важное событие
  2. Backend отправляет Push Notification родителям через Apple Push Notification Service (APNs)
  3. Родители получают уведомление на устройство в течение 2-7 секунд
  4. Уведомление содержит информацию о событии (например, "ребенок пытался зайти на заблокированный сайт")
  5. Родитель может открыть приложение для просмотра детального отчета
- **Соответствие:** ✅ Стандартный API, требует явного согласия пользователя

#### 4. Опциональные службы геозон

**Framework: CoreLocation** (стандартный iOS API, опционально)
- **Использование:** Функции безопасности семьи (геозоны, обмен местоположением)
- **Разрешение:** Запрашивается с четким описанием в Info.plist
- **Пример работы:**
  1. Родитель включает функцию "Геозоны" в настройках
  2. Приложение запрашивает разрешение на использование геолокации с четким описанием: "Для функций безопасности семьи (геозоны, обмен местоположением)"
  3. Если пользователь дает согласие, приложение может отслеживать местоположение для создания геозон (например, "дом", "школа")
  4. Родитель получает уведомления, когда ребенок входит или выходит из геозоны
  5. Пользователь может отключить эту функцию в любой момент в настройках
- **Соответствие:** ✅ Стандартный API, требуется явное согласие пользователя

## 2. НАШ ПОДХОД: РЕКОМЕНДАТЕЛЬНАЯ БЕЗОПАСНОСТЬ И СЕМЕЙНОЕ РУКОВОДСТВО

### Как работает безопасность (пример полного цикла):

1. **Пользователь включает функции безопасности в приложении**
   - Пользователь открывает настройки безопасности
   - Включает опцию "Защита от мошеннических сайтов"

2. **Приложение шифрует данные локально (CryptoKit)**
   - Настройки пользователя шифруются локально на устройстве
   - Ключи шифрования хранятся в Keychain

3. **Зашифрованные данные отправляются на backend через HTTPS**
   - Приложение отправляет обезличенные метаданные (URL, домены) на backend
   - Соединение защищено SSL Pinning

4. **Backend анализирует с использованием AI/ML (3,581+ функций безопасности)**
   - Backend анализирует метаданные на сервере
   - Определяет потенциальные угрозы (фишинг, мошенничество, вредоносный контент)

5. **Результаты отправляются обратно как рекомендации**
   - Backend отправляет результаты анализа в приложение
   - Приложение отображает оповещения и рекомендации

6. **Приложение отображает оповещения и предложения**
   - Пользователь видит уведомление: "⚠️ Обнаружен потенциально опасный сайт"
   - Пользователь может просмотреть детальную информацию

7. **Пользователь принимает обоснованные решения**
   - Пользователь решает, следовать ли рекомендации
   - **НЕТ блокировки или принудительного применения на системном уровне**

### Как работает родительский контроль (пример полного цикла):

1. **Родитель настраивает правила в приложении**
   - Родитель открывает экран "Родительский контроль"
   - Настраивает правила: "блокировать взрослый контент", "лимит времени на игры: 1 час в день"

2. **Правила хранятся локально и на backend**
   - Правила сохраняются в UserDefaults локально
   - Правила также синхронизируются с backend для использования на других устройствах

3. **Backend предоставляет аналитику и отчеты**
   - Приложение отправляет метаданные активности на backend
   - Backend анализирует и создает отчеты: "ребенок использовал игры 1.5 часа сегодня"

4. **Родитель получает отчеты в приложении**
   - Родитель открывает приложение и видит отчет: "📊 Статистика за сегодня: игры - 1.5 часа (лимит: 1 час)"
   - Родитель получает Push Notification: "⚠️ Ребенок превысил лимит времени на игры"

5. **Родитель использует отчеты для руководства детьми**
   - Родитель обсуждает с ребенком превышение лимита
   - Родитель использует инструменты семейного общения в приложении

6. **Доступны инструменты семейного общения**
   - Приложение предоставляет функции для семейного общения (чат, обмен сообщениями)
   - Родители и дети могут общаться через приложение

**→ НЕТ принудительных ограничений или мониторинга на системном уровне**
