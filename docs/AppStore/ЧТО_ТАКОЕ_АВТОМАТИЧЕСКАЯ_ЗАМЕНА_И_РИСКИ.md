---

## 📖 ЧТО ТАКОЕ "АВТОМАТИЧЕСКАЯ ЗАМЕНА ЧЕРЕЗ IDE"

### Простым языком:

**IDE** = Xcode (программа для разработки)

**Автоматическая замена** = функция "Find & Replace" (Найти и Заменить)

### Как это работает:

1. Открываешь в Xcode: `Edit` → `Find` → `Find and Replace`
2. Вводишь: `VPNServer` (что искать)
3. Вводишь: `NetworkProtectionServer` (на что заменить)
4. Нажимаешь: `Replace All` (Заменить все)
5. Xcode автоматически заменяет **ВСЕ** упоминания `VPNServer` на `NetworkProtectionServer` **ОДНОВРЕМЕННО**

---

## ⚠️ РИСКИ АВТОМАТИЧЕСКОЙ ЗАМЕНЫ

### Риск 1: Замена в неправильных местах 🔴

**Проблема:**
- Xcode заменит `VPNServer` **ВЕЗДЕ**, включая:
  - Комментарии: `// VPNServer is used here` → `// NetworkProtectionServer is used here` ✅ (нормально)
  - Строки: `"VPNServer"` → `"NetworkProtectionServer"` ❌ (может сломать)
  - Backup файлы: тоже заменит ❌ (не нужно)
  - Tests: тоже заменит ⚠️ (можно, но не обязательно)

**Пример:**
```swift
// Было:
let message = "VPNServer connected"  // Строка для пользователя

// После автоматической замены:
let message = "NetworkProtectionServer connected"  // ❌ Плохо для пользователя!
```

---

### Риск 2: Замена частичных совпадений 🔴

**Проблема:**
- Если заменить `VPN`, то заменится:
  - `VPNServer` ✅ (нужно)
  - `VPNStatusResponse` ✅ (нужно)
  - Но также: `getVPNStatus()` → `getNetworkProtectionStatus()` ⚠️ (может быть не нужно)
  - И: `vpn_last_enabled_state` → `networkProtection_last_enabled_state` ❌ (сломает UserDefaults!)

**Пример:**
```swift
// Было:
@AppStorage("vpn_last_enabled_state") private var vpnLastEnabledState: Bool

// После автоматической замены "VPN" → "NetworkProtection":
@AppStorage("networkProtection_last_enabled_state") private var networkProtectionLastEnabledState: Bool
// ❌ Сломается! Старые данные не найдутся!
```

---

### Риск 3: Замена в backup файлах 🔴

**Проблема:**
- Xcode заменит и в backup файлах
- Backup файлы больше не будут backup'ами
- Потеряем возможность откатиться

---

### Риск 4: Невозможность проверить каждое изменение 🔴

**Проблема:**
- Заменяется все сразу
- Не видно, что именно изменилось
- Если что-то сломается - не понятно где
- Сложно откатить конкретное изменение

**Пример:**
```
Заменено 47 мест за 1 секунду
Ошибка компиляции!
Где ошибка? Не понятно, нужно искать вручную...
```

---

### Риск 5: Замена в документации/комментариях ⚠️

**Проблема:**
- Заменяется и в комментариях
- Может быть не нужно
- Или наоборот - нужно, но не контролируемо

## ✅ ПОЧЕМУ МЫ НЕ ИСПОЛЬЗУЕМ АВТОМАТИЧЕСКУЮ ЗАМЕНУ

### Наш подход: **ПОШАГОВАЯ ЗАМЕНА ПО 1 МЕСТУ**

**Преимущества:**

1. ✅ **Контроль каждого изменения**
   - Видим, что именно меняем
   - Понимаем контекст
   - Можем проверить правильность

2. ✅ **Проверка после каждого изменения**
   - Компилируем после каждого шага
   - Если ошибка - сразу видно где
   - Легко откатить конкретное изменение

3. ✅ **Не трогаем backup файлы**
   - Backup остаются backup'ами
   - Можем откатиться в любой момент

4. ✅ **Не трогаем строки/UserDefaults**
   - Не заменяем в строках для пользователя
   - Не заменяем ключи UserDefaults
   - Не ломаем существующие данные

5. ✅ **Видим прогресс**
   - Знаем, сколько сделано
   - Знаем, сколько осталось
   - Можем остановиться в любой момент

- Заменяем ТОЛЬКО это место

- Проверяем, что нет ошибок
- Переходим к следующему

- Компиляция проекта
- Поиск оставшихся упоминаний
- Тестирование функциональности
