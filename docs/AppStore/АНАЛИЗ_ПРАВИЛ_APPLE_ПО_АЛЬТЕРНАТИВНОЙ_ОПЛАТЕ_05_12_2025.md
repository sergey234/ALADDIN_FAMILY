# Анализ правил Apple по альтернативной оплате подписок

## Вопрос
Можно ли использовать "Оплата на сайте + активация кода" для подписок в iOS приложении?

---

## Результаты поиска в документации Apple

### Основное правило Apple (Guideline 3.1.3)

**Apple требует:**
- Все цифровые товары и услуги должны продаваться через In-App Purchase (IAP)
- Подписки должны быть доступны для покупки непосредственно в приложении через IAP
- Использование альтернативных методов оплаты внутри приложения запрещено

---

## Исключения и разрешённые случаи

### 1. Коды активации для уже купленных подписок

**Apple допускает:**
- Использование кодов активации для подписок, **уже приобретённых вне приложения**
- Пользователь может купить подписку на сайте, получить код и ввести его в приложении
- **НО:** Приложение не должно направлять пользователей на сайт для покупки
- **НО:** В приложении не должно быть ссылок на сайт или призывов к покупке вне приложения

### 2. Reader Apps (Приложения-читалки)

**Apple допускает:**
- Приложения, которые предоставляют доступ к контенту, приобретённому вне приложения
- Пользователь может войти в учётную запись и получить доступ к уже купленному контенту
- Это исключение для определённых категорий приложений

---

## Условия для использования кодов активации

### ✅ Разрешено:

1. **Пользователь сам инициирует покупку на сайте**
   - Приложение не направляет пользователя на сайт
   - Нет ссылок на сайт в приложении
   - Нет призывов к покупке вне приложения

2. **Код активации для уже купленной подписки**
   - Пользователь уже оплатил подписку на сайте
   - Код используется только для активации уже оплаченной подписки
   - Не для совершения покупки через приложение

3. **Доступ к уже купленному контенту**
   - Приложение предоставляет доступ к контенту, купленному вне приложения
   - Это не обход IAP, а активация уже оплаченной подписки

### ❌ Запрещено:

1. **Направление пользователей на сайт для покупки**
   - Ссылки на сайт в приложении
   - Призывы к покупке вне приложения
   - Кнопки "Купить на сайте"

2. **Обход IAP внутри приложения**
   - Предложение оплаты на сайте вместо IAP
   - Скрытие IAP и направление на сайт

3. **Прямая продажа через приложение**
   - Покупка подписки через приложение, но не через IAP

---

## Как правильно реализовать

### ✅ Правильный подход:

1. **В приложении:**
   - Предоставить IAP как основной способ оплаты
   - Предоставить возможность ввести код активации (для уже купленных подписок)
   - НЕ направлять пользователей на сайт
   - НЕ показывать ссылки на сайт

2. **На сайте:**
   - Пользователь может купить подписку на сайте
   - Получить код активации
   - Ввести код в приложении

3. **Обоснование для Apple:**
   - Код активации используется для активации уже оплаченной подписки
   - Это не обход IAP, а предоставление доступа к уже купленному контенту
   - Пользователь сам выбирает способ оплаты (IAP или сайт)

---

## Рекомендации для ответа Apple

### Вариант 1: Безопасный (рекомендуется)

**Объяснение:**
"Приложение предоставляет два способа активации подписки:
1. In-App Purchase через App Store (основной способ)
2. Код активации для подписок, уже приобретённых пользователем на нашем сайте

Код активации используется только для активации уже оплаченной подписки, а не для совершения покупки через приложение. Приложение не направляет пользователей на сайт для покупки - пользователь сам выбирает способ оплаты."

### Вариант 2: С акцентом на мультиплатформенность

**Объяснение:**
"Приложение предоставляет доступ к подпискам, приобретённым на нескольких платформах (iOS и Android). Код активации позволяет пользователям использовать одну подписку на всех устройствах. Приложение не направляет пользователей на сайт - код активации используется только для доступа к уже купленному контенту."

---

## Важные моменты для Apple Review

1. **Не упоминать в приложении:**
   - Ссылки на сайт для покупки
   - Призывы к покупке вне приложения
   - Сравнение цен IAP vs сайт

2. **Упоминать в ответе Apple:**
   - IAP - основной способ оплаты
   - Код активации - для уже купленных подписок
   - Приложение не направляет на сайт
   - Пользователь сам выбирает способ оплаты

3. **Техническая реализация:**
   - IAP должен быть доступен в приложении
   - Код активации - дополнительная функция
   - Оба способа предоставляют одинаковый доступ

---

## Итоговая рекомендация

### ✅ Можно использовать, если:

1. IAP доступен в приложении как основной способ
2. Код активации используется только для уже купленных подписок
3. Приложение не направляет пользователей на сайт
4. Нет ссылок на сайт в приложении
5. Пользователь сам инициирует покупку на сайте

### ❌ Нельзя использовать, если:

1. Приложение направляет пользователей на сайт
2. Есть ссылки на сайт в приложении
3. Приложение скрывает IAP и предлагает оплату на сайте
4. Код используется для обхода IAP

---

## Формулировка для ответа Apple

**Рекомендуемая формулировка:**

"Приложение предоставляет два способа активации подписки:

1. **In-App Purchase через App Store** (основной способ)
   - Покупка напрямую в приложении через App Store
   - Автоматическая активация подписки

2. **Код активации для уже купленных подписок**
   - Пользователь может приобрести подписку на нашем сайте (вне приложения)
   - Получить код активации по email
   - Ввести код в приложении для активации уже оплаченной подписки
   - Это позволяет пользователям использовать одну подписку на нескольких платформах (iOS и Android)

Важно: Приложение не направляет пользователей на сайт для покупки. Код активации используется только для активации уже оплаченной подписки, а не для совершения покупки через приложение. Пользователь сам выбирает способ оплаты (IAP или сайт)."
