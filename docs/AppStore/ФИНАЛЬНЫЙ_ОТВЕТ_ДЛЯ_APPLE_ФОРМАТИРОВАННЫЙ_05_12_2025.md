## ПУНКТ 1: FACE DATA (ДАННЫЕ ЛИЦА)

Замечание Apple:
"Мы нуждаемся в дополнительной информации о том, как приложение использует данные лица. Предоставьте ответы на 6 вопросов о сборе, использовании, хранении и передаче данных лица."

Что сделали:
Обновили Privacy Policy в приложении (раздел 7 "Face ID (Распознавание лица)") и в приложении.

Ответы на все 6 вопросов Apple:

1. Какие данные лица собирает приложение?
Приложение не собирает данные лица (face data). Мы используем только Face ID — встроенную функцию iOS для локальной аутентификации. Данные лица обрабатываются исключительно операционной системой iOS в Secure Enclave устройства. Мы не имеем доступа к данным лица пользователя.

2. Как используются эти данные?
Face ID используется только для аутентификации пользователя при входе в приложение. Данные лица не используются для каких-либо других целей. Обработка происходит локально на устройстве без передачи данных.

3. Передаются ли третьим лицам? Где хранятся?
Нет, данные лица не передаются третьим лицам. Данные хранятся только локально на устройстве в Secure Enclave — защищённой области процессора, к которой мы не имеем доступа. Данные не передаются на наши серверы или третьим лицам.

4. Как долго хранятся?
Данные лица хранятся только на устройстве до тех пор, пока:
- Пользователь не удалит приложение
- Пользователь не отключит Face ID в настройках устройства
- Пользователь не сбросит настройки устройства

Мы не храним данные лица на наших серверах.

5. Где в Privacy Policy это описано?
Раздел "Регистрация и аутентификация" (Registration and authentication) в Privacy Policy приложения, пункты 4-6. Также доступно на сайте: https://aladdin-ai.ru/privacy.html (раздел 7 "Face ID (Распознавание лица)").

6. Процитируйте конкретный текст из Privacy Policy:
Раздел 7 "Face ID (Распознавание лица)":
- Приложение использует Face ID для безопасной аутентификации пользователя.
- Данные лица НЕ собираются — приложение использует только встроенную функцию iOS для локальной аутентификации.
- Данные лица НЕ передаются третьим лицам — вся обработка происходит локально на устройстве в Secure Enclave.
- Данные лица НЕ хранятся на наших серверах — они остаются только на устройстве пользователя.
- Данные лица удаляются при удалении приложения или отключении Face ID в настройках устройства.
- Мы не имеем доступа к данным лица пользователя — они обрабатываются исключительно операционной системой iOS.

## ПУНКТ 2: КОД ПРИГЛАШЕНИЯ

Замечание Apple:
"Нужна информация о том, как пользователи получают код. Есть ли плата за код? Можно ли предоставить пример кода?"

Что сделали:
Код приглашения (Recovery Code) создаётся автоматически при создании новой семьи в приложении. Приложение использует анонимную регистрацию без сбора персональных данных (email, телефон, имя) для защиты приватности пользователей в соответствии с нашей политикой конфиденциальности.

Результат:

1. Как пользователи получают код?
Код приглашения создаётся автоматически при создании новой семьи в приложении:
- Пользователь нажимает "Добавить участника" → "Создать новую семью"
- После регистрации семьи система генерирует уникальный код в формате: FAM-XXXX-XXXX-XXXX
- Код отображается в модальном окне с возможностью копирования
- Пользователь может поделиться кодом через QR-код или скопировать текст

Важно: Наше приложение использует анонимную регистрацию без сбора персональных данных (email, телефон, имя) для защиты приватности пользователей. Регистрация происходит через:
- Выбор роли (родитель/ребёнок/пожилой)
- Выбор возрастной группы
- Код приглашения (QR-код) для присоединения к семье

Это позволяет пользователям использовать приложение без предоставления персональных данных, что соответствует нашей политике приватности.

2. Есть ли плата за код?
НЕТ, код приглашения бесплатный. Не требуется никакой оплаты для получения кода. Код создаётся автоматически при создании семьи.

3. Можно ли предоставить пример кода?
Да, пример кода для тестирования:
FAM-DEMO-CODE-2025

Этот код можно использовать для тестирования функции присоединения к семье в приложении.

## ПУНКТ 5: UIBACKGROUNDMODES LOCATION

Замечание Apple:
"Приложение объявляет поддержку location в UIBackgroundModes key в Info.plist, но мы не можем найти никаких функций, которые требуют постоянного местоположения. Apps that declare support for location in the UIBackgroundModes key must have features that require persistent location."

Что сделали:
Удалили location из UIBackgroundModes в Info.plist. Оставили только remote-notification для push-уведомлений. Приложение использует Significant-Change Location Service и Region Monitoring для функций родительского контроля, которые не требуют persistent location updates согласно документации Apple.

Результат:
UIBackgroundModes location:
Мы удалили location из UIBackgroundModes, так как приложение использует методы отслеживания местоположения, которые не требуют persistent location updates.

Объяснение использования методов:
Приложение использует следующие методы для функций родительского контроля:
1. Significant-Change Location Service — обновления при изменении местоположения на 500+ метров. Этот метод не требует location в UIBackgroundModes, так как обновления происходят только при значительных изменениях местоположения, а не постоянно.

2. Region Monitoring — отслеживание входов/выходов из геозон (дом, школа, секция). Этот метод также не требует location в UIBackgroundModes, так как система iOS автоматически отслеживает регионы в фоне.

Функции родительского контроля, использующие местоположение:
- Отслеживание местоположения детей (через Significant-Change Location Service)
- Геозоны (дом, школа, секция) — через Region Monitoring
- История перемещений
- Уведомления о перемещениях
- SOS-кнопка для экстренных ситуаций

Техническая реализация:
- Приложение использует NSLocationWhenInUseUsageDescription для получения местоположения когда приложение активно
- Для фонового отслеживания используется Significant-Change Location Service (обновления только при значительных изменениях местоположения, 500+ метров)
- Для геозон используется Region Monitoring (обновления при входе/выходе из зон)
- Оба метода работают в фоновом режиме без требования location в UIBackgroundModes

Изменения в коде:
- Info.plist — удалена строка location из UIBackgroundModes
- Теперь UIBackgroundModes содержит только remote-notification для push-уведомлений
