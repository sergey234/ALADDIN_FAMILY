```swift
        } else if let sourceView = sourceView {
            popover.sourceView = sourceView
            popover.sourceRect = sourceView.bounds
        } else {
            // Fallback: центр экрана
            // ...
        }
        popover.permittedArrowDirections = .any
    }
}
```

## 5. ✅ UIBACKGROUNDMODES LOCATION - ИСПРАВЛЕНО В КОДЕ

### 📝 ПРОБЛЕМА ОТ APPLE:
Приложение объявляет поддержку `location` в `UIBackgroundModes` в Info.plist, но Apple не нашла функций, требующих постоянного местоположения (persistent location).

**Требование Apple:** Если приложение объявляет `location` в `UIBackgroundModes`, оно должно иметь функции, требующие постоянного отслеживания местоположения.

### ✅ НАШЕ РЕШЕНИЕ:

**1. Что мы сделали:**
- ✅ Удалена строка `location` из `UIBackgroundModes` в `Info.plist`
- ✅ Оставлен только `remote-notification` для push-уведомлений

**2. Простым языком:**

**Что такое UIBackgroundModes:**
Это настройки, которые говорят iOS, что приложение хочет делать в фоновом режиме.

**Что было:**
```xml
<key>UIBackgroundModes</key>
<array>
    <string>location</string>        ← УДАЛЕНО
    <string>remote-notification</string>
</array>
```

**Что стало:**
```xml
<key>UIBackgroundModes</key>
<array>
    <string>remote-notification</string>  ← ТОЛЬКО ЭТО
</array>
```

**Почему удалили:**
- Apple требует, чтобы `location` в `UIBackgroundModes` использовался только для функций, требующих **постоянного** отслеживания (каждую секунду)
- Наше приложение использует **Significant-Change Location Service** и **Region Monitoring**, которые **не требуют** `location` в `UIBackgroundModes`

**3. Варианты для родительского контроля:**

**Вариант 1: Significant-Change Location Service (РЕКОМЕНДУЕТСЯ) ✅**
- Обновления при изменении местоположения на 500+ метров
- **НЕ требует** `location` в `UIBackgroundModes`
- Подходит для родительского контроля
- Экономит батарею

**Вариант 2: Region Monitoring (для геозон) ✅**
- Обновления при входе/выходе из геозон (дом, школа)
- **НЕ требует** `location` в `UIBackgroundModes`
- Подходит для геозон

**Вариант 3: When-In-Use Location ✅**
- Работает только когда приложение открыто
- **НЕ требует** `location` в `UIBackgroundModes`
- Подходит для просмотра местоположения в реальном времени

**Вариант 4: Persistent Location (НЕ РЕКОМЕНДУЕТСЯ) ❌**
- Постоянное отслеживание каждую секунду
- **Требует** `location` в `UIBackgroundModes`
- Сильно разряжает батарею
- Apple требует обоснование для использования

**4. Что у нас в приложении:**
- ✅ `NSLocationWhenInUseUsageDescription` — для использования местоположения когда приложение открыто
- ✅ `NSLocationAlwaysAndWhenInUseUsageDescription` — для использования в фоне (Significant-Change, Region Monitoring)
- ✅ Родительский контроль использует Significant-Change и Region Monitoring
- ✅ Эти функции **НЕ требуют** `location` в `UIBackgroundModes`

**5. На что ругается Apple:**
Apple ругается на то, что приложение **заявляет** о функции постоянного отслеживания (`location` в `UIBackgroundModes`), но **не использует** её. Это нарушение правил — нельзя заявлять о функциях, которых нет.

### 📄 ФАЙЛЫ:
- ✅ `Info.plist` — удалён `location` из `UIBackgroundModes`

**Требование Apple:** Если в Age Rating указаны In-App Controls, они должны быть в приложении. Иначе нужно установить "None".

### ✅ НАШЕ РЕШЕНИЕ:

**1. Что такое In-App Controls:**
- **In-App Controls** — это встроенные инструменты для родителей (например, встроенный браузер с фильтрацией)
- Это **НЕ то же самое**, что родительский контроль как функция приложения
- Apple ищет именно **встроенные инструменты** (встроенный браузер, встроенный видеоплеер с фильтрацией)

**2. Почему Apple не нашла функции:**
- У нас есть **родительский контроль** (отслеживание местоположения, блокировка приложений, контроль экранного времени)
- Но у нас **НЕТ** встроенных инструментов (встроенного браузера, встроенного видеоплеера)
- Apple ищет именно **In-App Controls** (встроенные инструменты), а не родительский контроль как функцию

**3. Что нужно сделать (РУЧНОЕ ИЗМЕНЕНИЕ):**

**Шаг 1: Войти в App Store Connect**
1. Войти в App Store Connect
2. Выбрать "My Apps"
3. Выбрать приложение "ALADDIN"

**Шаг 2: Изменить Age Rating**

2. Прокрутить до раздела "Age Rating"

**Шаг 3: Установить In-App Controls = None**

   - **Parental Controls:** None

**4. Где ещё указывать эту информацию:**
При отправке документов в App Review Information в поле "Notes" можно добавить:
> "Our app includes parental control features (location tracking, app blocking, screen time control), but does not include In-App Controls (built-in browser or video player with filtering). Age Rating has been updated to reflect this."

После активации подписки пользователь получает доступ к:

- Расширенной защите семьи
- Дополнительным функциям родительского контроля

**4. Какие платные функции не используют in-app purchase?**
**Оплата на сайте + активация кода:**

- Получает код активации
- Вводит код в приложении вручную
- Это альтернативный способ оплаты для пользователей Android или тех, кто предпочитает оплату на сайте
- Код активации вводится вручную в приложении (не через IAP)

**Обоснование:**
- Это альтернативный способ оплаты для пользователей, которые не могут или не хотят использовать IAP
- Код активации — это просто способ активации уже оплаченной подписки
- Пользователь может выбрать удобный способ оплаты: IAP или оплата на сайте
