# 🔍 УТОЧНЕНИЕ ЛОГИКИ: SessionExpired и обновление токенов

**Дата:** 2026-03-14  
**Вопрос:** Мы делаем ЭТАП 1 для обновления токенов?

---

## ⚠️ ВАЖНОЕ УТОЧНЕНИЕ

### **ЭТАП 1 НЕ обновляет токены автоматически!**

**ЭТАП 1 делает другое:**
- Когда токены **НЕ МОГУТ** быть обновлены автоматически
- Перенаправляет пользователя на экран входа
- Пользователь должен **ВРУЧНУЮ** войти заново
- После входа пользователь получает **НОВЫЕ** токены

---

## 🔄 ДВЕ РАЗНЫЕ СИСТЕМЫ

### **1. Автообновление токенов (УЖЕ РАБОТАЕТ):**

**Что делает:**
- Автоматически обновляет токены БЕЗ участия пользователя
- Использует `refreshToken` для получения нового `accessToken`

**Как работает:**
```
Пользователь делает действие
  → NetworkManager проверяет токен
    → Если токен истек → Пытается обновить через refreshToken
      → Если refreshToken валиден → Получает новый accessToken
        → ✅ Продолжает работу БЕЗ перенаправления
```

**Когда срабатывает:**
- Когда `accessToken` истек, но `refreshToken` еще валиден
- Автоматически, без участия пользователя

---

### **2. Перенаправление на вход (ЭТАП 1 - НОВОЕ):**

**Что делает:**
- Перенаправляет пользователя на экран входа
- Пользователь должен ВРУЧНУЮ войти заново

**Как работает:**
```
Пользователь делает действие
  → NetworkManager проверяет токен
    → Если токен истек → Пытается обновить через refreshToken
      → Если refreshToken ТОЖЕ истек → ❌ Не может обновить
        → ViewModel получает ошибку 401
          → Отправляет уведомление SessionExpired
            → ЭТАП 1: ALADDINApp получает уведомление
              → Очищает токены
                → Перенаправляет на экран входа
                  → Пользователь ВРУЧНУЮ входит заново
                    → Получает НОВЫЕ токены
```

**Когда срабатывает:**
- Когда `refreshToken` тоже истек (автообновление не сработало)
- Когда автообновление токенов не смогло обновить токены

---

## 📊 ПОЛНАЯ ЛОГИКА РАБОТЫ

### **СЦЕНАРИЙ 1: Автообновление токенов сработало**

```
Пользователь → Действие → NetworkManager проверяет токен
  → accessToken истек → refreshToken валиден
    → ✅ Автоматически обновляет токен
      → Продолжает работу БЕЗ перенаправления
        → Пользователь НЕ ЗНАЕТ, что токен обновился
```

**Результат:** ✅ Пользователь продолжает работу, токены обновлены автоматически

---

### **СЦЕНАРИЙ 2: Автообновление токенов НЕ сработало (нужен ЭТАП 1)**

```
Пользователь → Действие → NetworkManager проверяет токен
  → accessToken истек → refreshToken ТОЖЕ истек
    → ❌ Не может обновить токен автоматически
      → Возвращает ошибку 401
        → ViewModel получает unauthorized
          → Отправляет уведомление SessionExpired
            → ❌ БЕЗ ЭТАП 1: Никто не обрабатывает уведомление
              → Пользователь видит ошибку, но остается на экране
                → Пользователь НЕ МОЖЕТ войти заново

            → ✅ С ЭТАП 1: ALADDINApp обрабатывает уведомление
              → Очищает токены
                → Перенаправляет на экран входа
                  → Пользователь ВРУЧНУЮ входит заново
                    → Получает НОВЫЕ токены
                      → Может продолжать работу
```

**Результат БЕЗ ЭТАП 1:** ❌ Пользователь видит ошибку, но не может войти заново

**Результат С ЭТАП 1:** ✅ Пользователь автоматически перенаправляется на вход, может войти заново

---

## 🎯 ЗАЧЕМ НУЖЕН ЭТАП 1?

### **Проблема БЕЗ ЭТАП 1:**

1. **Автообновление токенов работает** → Обновляет токены автоматически
2. **НО:** Если `refreshToken` тоже истек → Автообновление НЕ сработает
3. **Результат:** Пользователь получает ошибку 401
4. **НО:** Никто не обрабатывает уведомление `SessionExpired`
5. **Результат:** Пользователь видит ошибку, но остается на экране
6. **Проблема:** Пользователь НЕ МОЖЕТ войти заново (нет перенаправления)

---

### **Решение С ЭТАП 1:**

1. **Автообновление токенов работает** → Обновляет токены автоматически
2. **НО:** Если `refreshToken` тоже истек → Автообновление НЕ сработает
3. **Результат:** Пользователь получает ошибку 401
4. **НО:** ЭТАП 1 обрабатывает уведомление `SessionExpired`
5. **Результат:** Пользователь автоматически перенаправляется на экран входа
6. **Решение:** Пользователь МОЖЕТ войти заново и получить новые токены

## ✅ ИТОГОВОЕ ОБЪЯСНЕНИЕ

### **ЭТАП 1 НЕ обновляет токены автоматически!**

**ЭТАП 1 делает:**
- Перенаправляет пользователя на экран входа
- Когда автообновление токенов НЕ СМОГЛО обновить токены
- Чтобы пользователь ВРУЧНУЮ вошел заново и получил НОВЫЕ токены

---

### **Две системы работают вместе:**

1. **Автообновление токенов (уже работает):**
   - Пытается обновить токены автоматически
   - Работает БЕЗ участия пользователя
   - Срабатывает, когда `refreshToken` валиден

2. **Перенаправление на вход (ЭТАП 1):**
   - Срабатывает, когда автообновление НЕ СМОГЛО обновить токены
   - Перенаправляет пользователя на экран входа
   - Пользователь ВРУЧНУЮ входит заново и получает НОВЫЕ токены

---

### **Зачем нужен ЭТАП 1?**

**БЕЗ ЭТАП 1:**
- Автообновление токенов работает ✅
- НО: Если автообновление не сработало → Пользователь видит ошибку ❌
- Проблема: Пользователь НЕ МОЖЕТ войти заново (нет перенаправления) ❌

**С ЭТАП 1:**
- Автообновление токенов работает ✅
- НО: Если автообновление не сработало → ЭТАП 1 перенаправляет на вход ✅
- Решение: Пользователь МОЖЕТ войти заново и получить новые токены ✅

## 🎯 ВЫВОД

### **ЭТАП 1 — это "запасной план":**

- **Основной план:** Автообновление токенов (уже работает)
- **Запасной план:** ЭТАП 1 - перенаправление на вход (когда основной план не сработал)

### **ЭТАП 1 критичен, потому что:**

- Без него пользователь НЕ МОЖЕТ войти заново, когда автообновление не сработало
- Без него пользователь остается "заблокированным" на экране с ошибкой
- С ним пользователь автоматически перенаправляется на вход и может войти заново
