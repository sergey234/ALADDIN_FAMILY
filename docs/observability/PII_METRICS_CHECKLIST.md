# Чеклист: PII в метриках и логах (obs-pii-audit-metrics)

Цель: в лейблах Prometheus, логах приложения и трассах **нет** персональных данных (email, телефон, полный хеш как идентификатор пользователя, координаты, содержимое файлов).

## Перед включением новых счётчиков / логов

- [ ] Имена метрик и **лейблы** содержат только технические значения: `domain`, `env`, `route`, `method`, `code`, `version`, `job`.
- [ ] Нет лейблов вида `user_email`, `device_id` в открытых метриках; при необходимости — только обезличенный `user_id` из внутреннего числового id, согласованный с DPO.
- [ ] `http_request_*` histograms/counters не включают query string с токенами.
- [ ] Логи ошибок БД: без параметров запроса с PII (использовать маскирование или категории ошибок).

## Периодический аудит

- [ ] `curl -s http://<gateway>:8002/metrics | grep -Ei 'email|phone|@|password|token='` — пусто.
- [ ] Выборка из Loki/ELK по ключевым словам PII на staging перед промоутом в prod.

## Исключения

Только с явным документированием и отдельным retention: отладочные профили **не** на прод‑scrape endpoints.
