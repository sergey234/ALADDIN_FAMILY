# Правило слоёв онбординга (iOS hero) — зафиксировано для команды

**Статус:** обязательно для дизайна, экспорта, Xcode и QA.  
**Единственная кодовая база онбординга:** `ALADDIN_NEW/mobile_apps/ALADDIN_iOS` (не `ALADDIN_PUSH187`).

---

## 1. Одна схема: что в PNG, что в коде

| Где | Что кладём | Примеры |
|-----|------------|---------|
| **PNG / Lottie** (`OnboardingHero_00` … `07`) | Только **сюжетная иллюстрация** (фон, персонажи, атмосфера) | Космос, семья, радар — без кнопок и без UI-текста |
| **SwiftUI** (`14_OnboardingScreen.swift` + chrome) | **Весь интерактивный UI** | Заголовки, описания, язык, точки, «Продолжить», согласия, «У меня есть код», «Восстановить» |

**В Figma:** слои `CHROME_*`, `TITLE_*`, `DESC_*`, `ROW_lang_*`, `BLOCK_final_legal` — **ориентир для вёрстки в коде**. Не запекать их в экспорт hero-PNG.

**Зачем:** иначе текст и кнопки окажутся и на картинке, и в приложении → двойной UI, локализация не работает, правка copy в Figma ломает визуал в билде.

---

## 2. Стек слоёв в приложении (не упрощать без причины)

Снизу вверх в `OnboardingScreen` (`ZStack`):

```
1. LinearGradient.backgroundGradient     ← запасной фон, если hero не загрузился
2. HeroAmbientLayerView                  ← PNG/Lottie, scaledToFill, ignoresSafeArea
3. HeroBottomReadableGradient            ← затемнение снизу для читаемости текста
4. mainOnboardingContent()               ← TabView, кнопки, тексты, согласия
```

| Слой | Файл | Можно трогать? |
|------|------|----------------|
| Hero | `Shared/Components/HeroAmbientPresentation.swift` | Да (fill, parallax, wash) |
| Виньетка | `HeroBottomReadableGradient` | Да (сила `strong`) |
| UI | `Screens/14_OnboardingScreen.swift` | Да |

**Запрещено без отдельного решения продукта:**

- Вешать на hero **`.opacity(0.4)`** (иллюстрации становятся «невидимыми»).
- Убирать градиент (1) или виньетку (3) «для простоты» — ломается читаемость и fallback.
- Вшивать в PNG кнопки, чекбоксы, юридический текст, индикаторы страниц.

**Зачем:** градиент страхует пустой asset; виньетка держит контраст белого текста; полная непрозрачность hero — осознанный выбор после build 199.

## 3. Репозитории: где вести онбординг

| Проект | Роль |
|--------|------|
| **`ALADDIN_iOS`** | **Единственная основа** — 8 шагов (язык + 7), hero, Figma pipeline |
| **`ALADDIN_PUSH187`** | Архив: emoji-онбординг, 7 страниц, без `OnboardingHero_*` — **не мержить обратно, не править как prod** |

**Зачем:** два UX (7 vs 8 экранов, с hero и без) → путаница в QA, симуляторе и при code review.
