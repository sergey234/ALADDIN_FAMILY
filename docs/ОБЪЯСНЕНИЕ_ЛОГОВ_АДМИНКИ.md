# 📋 ОБЪЯСНЕНИЕ ЛОГОВ В АДМИНКЕ

**Дата:** 04.12.2025  
**Вопрос:** В чем отличие между Payment Service, Nginx и System логами?

---

## 🔍 ТРИ ТИПА ЛОГОВ

### **1. 🖥️ Payment Service**

**Что это:**
- Логи самого приложения `payment_service` (FastAPI/Uvicorn)
- Показывает работу backend API

**Что показывает:**
- ✅ Запуск и остановка сервера
- ✅ HTTP запросы к API (GET, POST, PUT, DELETE)
- ✅ Ошибки приложения (500, 404, и т.д.)
- ✅ Информация о работе endpoints
- ✅ Ошибки базы данных
- ✅ Ошибки бизнес-логики

**Примеры:**
```
INFO:     Started server process [1485226]
INFO:     Application startup complete.
INFO:     94.231.139.26:0 - "GET /api/admin/metrics/system HTTP/1.0" 200 OK
ERROR:    [Errno 98] error while attempting to bind on address ('0.0.0.0', 8000): address already in use
```

**Где хранится:**
- `/tmp/payment_service.log` (если запущен вручную)
- `journalctl -u payment_service` (если запущен как systemd сервис)

**Когда смотреть:**
- Проблемы с API
- Ошибки при запросах
- Проблемы с запуском сервиса
- Отладка backend логики

---

### **2. 🌐 Nginx**

**Что это:**
- Логи веб-сервера Nginx
- Показывает работу фронтенда и проксирование запросов

**Что показывает:**
- ✅ Запросы к сайту (GET /, GET /admin, и т.д.)
- ✅ Ошибки 404, 403, 500
- ✅ Проблемы с SSL сертификатами
- ✅ Медленные запросы
- ✅ Блокировки по IP
- ✅ Проблемы с проксированием к API

**Примеры:**
```
2025-12-04 10:00:00 [error] 1234#0: *5678 connect() failed (111: Connection refused) while connecting to upstream
2025-12-04 10:00:01 [error] 1234#0: *5679 upstream timed out (110: Connection timed out)
```

**Где хранится:**
- `/var/log/nginx/error.log` - ошибки
- `/var/log/nginx/access.log` - все запросы (если включен)

**Когда смотреть:**
- Проблемы с доступом к сайту
- Ошибки 502, 503, 504
- Проблемы с SSL
- Медленная загрузка страниц
- Проблемы с проксированием

---

### **3. 🖥️ System**

**Что это:**
- Системные логи Linux (syslog)
- Показывает работу всей системы

**Что показывает:**
- ✅ Запуск/остановка системных сервисов
- ✅ Ошибки ядра Linux
- ✅ Проблемы с дисками
- ✅ Проблемы с сетью
- ✅ Ошибки systemd
- ✅ Проблемы с памятью
- ✅ Критические системные ошибки

**Примеры:**
```
Dec  4 10:00:00 server kernel: [12345.678] Out of memory: Kill process 1234
Dec  4 10:00:01 server systemd: Failed to start payment_service.service
Dec  4 10:00:02 server kernel: [12345.679] EXT4-fs error
```

**Где хранится:**
- `/var/log/syslog` - основные системные логи
- `/var/log/kern.log` - логи ядра
- `/var/log/auth.log` - логи авторизации

**Когда смотреть:**
- Критические системные ошибки
- Проблемы с дисками
- Проблемы с памятью
- Проблемы с сетью на уровне системы
- Проблемы с авторизацией

---

## 📊 СРАВНИТЕЛЬНАЯ ТАБЛИЦА

| Тип логов | Отвечает за | Когда смотреть | Где хранится |
|----------|-------------|----------------|--------------|
| **Payment Service** | Backend API | Ошибки API, проблемы с endpoints | `/tmp/payment_service.log` |
| **Nginx** | Веб-сервер | Проблемы с сайтом, SSL, проксирование | `/var/log/nginx/error.log` |
| **System** | Вся система | Критические ошибки, диск, память | `/var/log/syslog` |

## 🔧 ПРОБЛЕМА: ПОРТ 8000 ЗАНЯТ

**Что видно в логах:**
```
ERROR:    [Errno 98] error while attempting to bind on address ('0.0.0.0', 8000): address already in use
```

**Причина:**
- Множественные попытки запуска `payment_service`
- Старый процесс не был остановлен
- Порт 8000 уже занят другим процессом

**Решение:**
1. Найти процесс на порту 8000
2. Остановить старые процессы
3. Запустить один процесс

**Команды:**
```bash
# Найти процесс
lsof -i :8000

# Остановить все процессы payment_service
pkill -f "uvicorn main:app"

# Или остановить конкретный процесс
kill -9 <PID>

# Запустить один процесс
cd /opt/aladdin-backend && source venv/bin/activate && nohup python3 -m uvicorn main:app --host 0.0.0.0 --port 8000 > /tmp/payment_service.log 2>&1 &
```

## 💡 РЕКОМЕНДАЦИИ

### **Для отладки:**

1. **Проблемы с API:**
   - Смотрите **Payment Service** логи
   - Проверьте ошибки 500, 404

2. **Проблемы с сайтом:**
   - Смотрите **Nginx** логи
   - Проверьте ошибки 502, 503

3. **Критические проблемы:**
   - Смотрите **System** логи
   - Проверьте ошибки диска, памяти

### **Для мониторинга:**

- **Payment Service:** Регулярно проверяйте на ошибки API
- **Nginx:** Проверяйте на проблемы с доступностью
- **System:** Проверяйте на критические ошибки
