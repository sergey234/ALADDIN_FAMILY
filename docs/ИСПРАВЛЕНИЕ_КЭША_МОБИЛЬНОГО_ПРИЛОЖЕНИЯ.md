# ✅ ИСПРАВЛЕНИЕ: Отключение кэширования в мобильном приложении

**Дата:** 2026-03-14  
**Проблема:** Мобильное приложение кэширует API ответы через URLSession  
**Решение:** Отключить кэширование в NetworkManager

---

## 🔍 ПРОБЛЕМА

**Найдено в `NetworkManager.swift`:**
1. Строка 200: `config.requestCachePolicy = .returnCacheDataElseLoad` - использует кэш!
2. Строка 189-193: Создается `URLCache` с кэшированием (10MB memory, 50MB disk)
3. В запросах не установлены заголовки `Cache-Control: no-cache`

**Результат:**
- Мобильное приложение получает закэшированные ответы "SFM_PROXIED"
- Старые timestamp (`2026-03-15T15:06:18`)
- Не получает актуальные данные с сервера

---

## ✅ РЕШЕНИЕ

### **1. Изменена политика кэширования:**

**Было:**
```swift
config.requestCachePolicy = .returnCacheDataElseLoad
```

**Стало:**
```swift
config.requestCachePolicy = .reloadIgnoringLocalCacheData
```

### **2. Добавлены заголовки в каждый запрос:**

**Для всех методов (GET, POST, PUT, DELETE, PATCH):**
```swift
request.cachePolicy = .reloadIgnoringLocalCacheData
request.setValue("no-cache", forHTTPHeaderField: "Cache-Control")
request.setValue("no-cache", forHTTPHeaderField: "Pragma")
```

## 📝 ВАЖНО

**URLCache все еще создается, но не используется:**
- Кэш создается для совместимости с другими частями приложения
- Но политика `.reloadIgnoringLocalCacheData` гарантирует, что кэш не используется для API запросов

**Если нужно полностью отключить кэш:**
```swift
config.urlCache = nil  // Полностью отключить кэш
```
