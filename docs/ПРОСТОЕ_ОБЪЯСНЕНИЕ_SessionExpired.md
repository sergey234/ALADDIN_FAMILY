# 📖 ПРОСТОЕ ОБЪЯСНЕНИЕ: Обработка SessionExpired

**Дата:** 2026-03-14  
**Для кого:** Простое объяснение для понимания логики

---

## 🎯 ЧТО ЭТО ТАКОЕ?

### **Проблема в двух словах:**

**Сейчас:** Когда у пользователя истекает сессия (токен авторизации), приложение показывает ошибку, но **НЕ перенаправляет** пользователя на экран входа.

**Нужно:** Когда сессия истекает, приложение должно **автоматически** перенаправить пользователя на экран входа.

---

## 🔍 КАК ЭТО РАБОТАЕТ СЕЙЧАС?

### **Шаг 1: Пользователь делает действие**
```
Пользователь нажимает кнопку "Включить защиту"
```

### **Шаг 2: Приложение отправляет запрос на сервер**
```
Приложение → Сервер: "Включи защиту для пользователя"
```

### **Шаг 3: Сервер проверяет токен**
```
Сервер: "Проверяю токен... Ой, токен истек!"
Сервер → Приложение: "401 Unauthorized (токен истек)"
```

### **Шаг 4: Приложение получает ошибку**
```
Приложение: "Получена ошибка 401"
Приложение: "Отправляю уведомление SessionExpired"
```

### **Шаг 5: Уведомление отправляется, но НИКТО ЕГО НЕ СЛУШАЕТ**
```
NotificationCenter.post("SessionExpired")
  → ❌ НИКТО НЕ ОБРАБАТЫВАЕТ
    → Пользователь видит ошибку в UI
      → Пользователь остается на том же экране
        → Пользователь не может войти заново
```

---

## 💡 ЧТО НУЖНО СДЕЛАТЬ?

### **Добавить "слушателя" уведомления**

**Сейчас:**
```
Уведомление отправляется → Никто не слушает → Ничего не происходит
```

**Нужно:**
```
Уведомление отправляется → ALADDINApp слушает → Обрабатывает → Перенаправляет на вход
```

---

## 🛠️ ЭТАП 1: Базовая обработка

### **Что это такое?**

Это **самый простой способ** решить проблему. Мы добавляем код, который будет "слушать" уведомление `SessionExpired` и автоматически перенаправлять пользователя на экран входа.

---

### **Как это работает?**

#### **Шаг 1: Добавить "слушателя" в ALADDINApp**

**Что делаем:**
Добавляем код в `ALADDINApp.swift`, который будет "слушать" уведомление `SessionExpired`.

**Как это выглядит:**
```swift
// В ALADDINApp.swift:
.onReceive(NotificationCenter.default.publisher(for: NSNotification.Name("SessionExpired"))) { notification in
    // Этот код выполнится, когда придет уведомление SessionExpired
    print("⚠️ Получено уведомление: сессия истекла!")
}
```

**Простыми словами:**
- Это как подписаться на рассылку
- Когда приходит уведомление `SessionExpired`, выполняется код внутри `.onReceive`

---

#### **Шаг 2: Очистить токены**

**Что делаем:**
Удаляем старые токены из безопасного хранилища (Keychain).

**Как это выглядит:**
```swift
// Очищаем токены
KeychainManager.shared.delete(forKey: .authToken)
KeychainManager.shared.delete(forKey: .refreshToken)
```

**Простыми словами:**
- Токены — это как "пропуск" для входа в систему
- Когда сессия истекает, нужно удалить старый "пропуск"
- Пользователь должен получить новый "пропуск" после входа

---

#### **Шаг 3: Перенаправить на экран входа**

**Что делаем:**
Переключаем экран приложения на экран онбординга (входа).

**Как это выглядит:**
```swift
// Перенаправляем на экран онбординга
navigationManager.navigateToRoot(.onboarding)
```

**Простыми словами:**
- Это как переключить канал на телевизоре
- Вместо экрана с ошибкой показываем экран входа
- Пользователь может войти заново

---

### **Полный код ЭТАП 1:**

```swift
// В ALADDINApp.swift, в mainAppContent():
.onReceive(NotificationCenter.default.publisher(for: NSNotification.Name("SessionExpired"))) { notification in
    let message = notification.userInfo?["message"] as? String ?? "Сессия истекла"
    
    print("⚠️ ALADDINApp: Получено уведомление SessionExpired: \(message)")
    
    // ШАГ 2: Очищаем токены
    KeychainManager.shared.delete(forKey: .authToken)
    KeychainManager.shared.delete(forKey: .refreshToken)
    
    // ШАГ 3: Перенаправляем на экран онбординга
    navigationManager.navigateToRoot(.onboarding)
}
```

---

### **Как это работает в реальности:**

1. **Пользователь нажимает кнопку** → Приложение отправляет запрос
2. **Сервер отвечает 401** → Токен истек
3. **ViewModel отправляет уведомление** → `SessionExpired`
4. **ALADDINApp получает уведомление** → Выполняется код в `.onReceive`
5. **Токены очищаются** → Старые "пропуски" удаляются
6. **Экран переключается** → Показывается экран входа
7. **Пользователь видит экран входа** → Может войти заново

---

## 🛡️ ЭТАП 2: Защита от множественных обработок

### **Что это такое?**

Это **улучшение**, которое предотвращает ситуацию, когда несколько уведомлений обрабатываются одновременно.

---

### **Проблема:**

**Что может произойти:**
1. Пользователь нажимает кнопку "Включить защиту" → Отправляется запрос → Получена ошибка 401 → Отправлено уведомление `SessionExpired`
2. В то же время пользователь нажимает кнопку "Загрузить статистику" → Отправляется запрос → Получена ошибка 401 → Отправлено уведомление `SessionExpired`
3. **Результат:** Оба уведомления обрабатываются одновременно → Пользователь перенаправляется дважды → Может быть глюк

---

### **Решение:**

**Используем флаг (переключатель):**
```swift
@State private var isHandlingSessionExpired = false

.onReceive(NotificationCenter.default.publisher(for: NSNotification.Name("SessionExpired"))) { notification in
    // Проверяем: обрабатывается ли уже уведомление?
    guard !isHandlingSessionExpired else {
        print("⚠️ Уведомление уже обрабатывается, пропускаем")
        return // Выходим, ничего не делаем
    }
    
    // Включаем флаг: "Я обрабатываю уведомление"
    isHandlingSessionExpired = true
    
    // Обрабатываем уведомление
    KeychainManager.shared.delete(forKey: .authToken)
    KeychainManager.shared.delete(forKey: .refreshToken)
    navigationManager.navigateToRoot(.onboarding)
    
    // Через 2 секунды выключаем флаг: "Я закончил обработку"
    DispatchQueue.main.asyncAfter(deadline: .now() + 2) {
        isHandlingSessionExpired = false
    }
}
```

**Простыми словами:**
- Это как табличка "Занято" на двери туалета
- Если уведомление уже обрабатывается, второе уведомление игнорируется
- Через 2 секунды табличка убирается, можно обрабатывать снова

---

### **Как это работает:**

1. **Первое уведомление приходит:**
   - Флаг `isHandlingSessionExpired = false` → Можно обрабатывать
   - Устанавливаем флаг `isHandlingSessionExpired = true` → "Занято"
   - Обрабатываем уведомление
   - Через 2 секунды сбрасываем флаг → "Свободно"

2. **Второе уведомление приходит (в течение 2 секунд):**
   - Флаг `isHandlingSessionExpired = true` → "Занято"
   - Пропускаем обработку → Игнорируем уведомление

3. **Второе уведомление приходит (через 2 секунды):**
   - Флаг `isHandlingSessionExpired = false` → "Свободно"
   - Обрабатываем уведомление
