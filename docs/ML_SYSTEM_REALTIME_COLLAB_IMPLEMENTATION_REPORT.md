  - DONE: 1, 2, 4, 5

  - DEFERRED: 6
- Дополнительно внутри этих 7 задач закрыт большой слой инженерных подзадач (синхронизация, UI-индикаторы sync-state, reconnect-поведение, auth-флоу, smoke-гейты).

Главный итог: приложение стало заметно более "живым", предсказуемым при нестабильной сети и удобным в ежедневном использовании.

---

## 2) Статус 7 основных задач (план 1-7)

### Задача 1: AI Token Streaming + Resume после reconnect
Status: DONE

Что сделано:
- Потоковая выдача AI-токенов (SSE-подход).
- Обработка reconnect/ошибок, корректное завершение/отмена стрима.
- Чекпоинты стрима сохраняются офлайн.

Что это дало:
- Ответ AI появляется "по мере печати", а не только в конце.
- При сетевых рывках меньше потерь прогресса ответа.
- Пользователь видит более "человечный" и быстрый отклик ассистента.

---

### Задача 2: uploadMedia + медиа в семейном чате
Status: DONE

Что сделано:
- Загрузка медиа (image/video/voice), отображение в чате.
- Поддержка `mediaThumbnailUrl` во всех ключевых путях обновления сообщения.
- Усилен парсинг WS payload (разные форматы message/payload, snake/camel).

Что это дало:
- Чат стал реально мультимедийным.
- Превью/thumbnail работает стабильнее, меньше "пустых" карточек.
- Пользовательский UX в чате ближе к современным мессенджерам.

---

### Задача 3: Unified Offline Layer v2
Status: IN PROGRESS (почти завершено)

Что уже сделано:
- Введён `UnifiedOfflineStore` как центральный слой офлайна.
- Реализованы push/pull, pending, retry/backoff, базовая conflict-логика.
- Усилена sync identity политика (`user_id` обязателен, нет небезопасного guest fallback).
- `OfflineManager` и смежные потоки связаны с unified-слоем.

Что осталось:
- Формально закрыть legacy runtime-хвосты (где еще есть in-memory очередь как отдельный путь).
- Финально зафиксировать e2e P3 протокол (reconnect/conflict/identity) как completed.

Что это дало:
- Синхронизация стала централизованной и лучше контролируемой.
- Ниже риск "разъезда" данных между экранами.
- Сильнее защита от неправильной синхронизации "без пользователя".

---

### Задача 4: Presence (кто онлайн/печатает)
Status: DONE (v1 production-ready)

Что сделано:
- Обновления presence/typing через WS.
- Очистка stale typing при reconnect/disconnect.
- Connection status в UI.

Что это дало:
- Пользователю понятно, кто в сети и кто печатает сейчас.
- Меньше "призрачных" индикаторов "печатает...".
- Реальный эффект "живого" семейного чата.

---

### Задача 5: Sign in with Apple + Magic Links
Status: DONE (v1 production-ready)

Что сделано:
- API методы и модели для Apple/Magic Link.
- UI-кнопка Sign in with Apple.
- Запрос и consume magic-link токена через deep link.
- Нормализовано сохранение сессии после входа.

Что это дало:
- Быстрее и удобнее вход.
- Ниже трение для новых/возвращающихся пользователей.
- Более современный auth UX.

---

### Задача 6: Единый policy layer (декларативные правила доступа)
Status: DEFERRED

Состояние:
- Осознанно отложено, чтобы сосредоточиться на стабильности realtime/offline/auth.

Что это означает:
- Блок не потерян, но официально перенесён на отдельный цикл.

---

### Задача 7: Thin Reactive Layer (SyncEngine)
Status: IN PROGRESS (v1 core и широкий coverage уже сделаны)

Что сделано:
- Введён `SyncEngine` как единая шина sync-state.
- Домены и единый контракт состояний (`pending/syncing/synced/error/local/idle`).
- Подключены heavy и non-heavy экраны, а также модальные настройки.

Что осталось:
- Финальный регулярный аудит новых фич, чтобы каждая новая sync-операция публиковалась в `SyncEngine` по тому же контракту.

Что это дало:
- Единое поведение синхронизации на экранах.
- Меньше локального "зоопарка флагов".
- Легче дебажить, тестировать и масштабировать.

## 3) 12 внутренних задач (детализация внутри 7 крупных блоков)

Ниже практическая декомпозиция текущего цикла.  
Формат: `Статус -> задача -> результат`.

1. COMPLETED -> P3 push pending в full sync  
   Результат: pending-операции отправляются системно, а не случайно.

2. COMPLETED -> P3 AI checkpoint upsert/cleanup  
   Результат: офлайн-слой не разрастается мусором AI-чекпоинтов.

3. IN PROGRESS -> P3 end-to-end cleanup legacy tails  
   Результат: осталось формально закрыть последние legacy-хвосты.

4. COMPLETED -> P4 presence hardening (WS payload + reconnect edge cases)  
   Результат: стабильнее online/typing.

5. COMPLETED -> P4 presence UI final  
   Результат: статус соединения и typing отображаются предсказуемо.

6. COMPLETED -> P5 Sign in with Apple UI+API  
   Результат: быстрый вход через Apple ID.

7. COMPLETED -> P5 Magic Link UI+deep link+consume  
   Результат: вход по ссылке работает end-to-end.

8. COMPLETED -> P5 session normalization  
   Результат: единая и безопасная фиксация auth/refresh/user_id.

9. CANCELLED/DEFERRED -> P6 declarative policy layer  
   Результат: блок перенесён на следующий цикл.

10. COMPLETED -> P7 v1 SyncEngine core  
    Результат: появилась единая шина sync-state.

11. IN PROGRESS -> P7 coverage expansion across screens/views/modals  
    Результат: почти сплошное покрытие UI контрактом sync-state.

12. IN PROGRESS -> docs refresh + full green gate discipline  
    Результат: документы синхронизируются с фактическим кодом, green-gate поддерживается регулярно.

## 4) Что получили пользователи (практическая ценность)

### Функциональные плюсы
- Реальный streaming AI-ответов (ощущается быстрее).
- Живой семейный чат: presence, typing, медиа.
- Удобная авторизация (Apple + magic link).
- Стабильнее поведение при офлайне и восстановлении сети.

### UX плюсы
- Единые sync-индикаторы на экранах (понятно: "сохраняется/сохранено/ошибка").
- Меньше скрытых ошибок состояния.
- Более предсказуемая реакция UI при сетевых сбоях.

### Надёжность и качество
- Центральная синхронизация вместо разрозненных локальных путей.
- Автогейты (`phase8`) регулярно подтверждают работоспособность.
- Снижена вероятность "тихих" рассинхронизаций.
