# Handoff: онбординг (0 + 7) + Main — продюсерский паспорт, жёсткие правила, слои, приёмка

Документ для другой ML/разработческой системы: **неизменяемый смысл правил**, **слои UI**, **сюжет × эмоция**, **факт кода vs целевой арт**, **Main**, **имена ассетов (Figma ↔ Xcode)**, **Figma MCP**, **чеклисты**. Цель — **ничего не забыть** при передаче задачи.

**Канон имён в Xcode (сейчас):** `OnboardingHero_00` … `OnboardingHero_07`, `MainHero_ambient` — см. `HeroPresentation` в `Shared/Components/HeroAmbientPresentation.swift`. В Figma слои можно называть длиннее (`OnboardingHero_01_family` и т.д.); **в Asset Catalog при экспорте** — привести к канону или один раз поменять константу в коде.

## 1. Продуктовая структура

### 1.1 Онбординг

- **Шаг 0:** язык (`currentPage == 0`).
- **Шаги 1–7:** семь контентных страниц (`currentPage == 1…7`, внутри `onboardingPage` это `contentIndex == 0…6`).
- **Итого:** `8` вкладок TabView.

**Тексты:** только из `safeLocalized` / `loadPages` → `createFullPages` / `LocalizationManager` → `Text(page.title)`, `Text(page.description)` и аналоги на шаге языка. **Не дублировать сюжетный текст в PNG/3D.**

### 1.2 Main

- Отдельный экран после онбординга; **не** «страница 9 карусели».
- В Figma: **8 артбордов онбординга** + **полный макет Main** + **отдельный кадр героя Main** (см. §6).

### 1.3 Девять визуальных «героев»

| № | Смысл | Имя в Xcode (канон) |
|---|--------|---------------------|
| 1 | Язык + лампа | `OnboardingHero_00` |
| 2–8 | Контент 1…7 | `OnboardingHero_01` … `OnboardingHero_07` |
| 9 | Герой на Main | `MainHero_ambient` |

## 2. Жёсткие правила (смысл не менять без явного пересогласования)

| Правило | Зачем |
|----------|--------|
| Весь копирайт только в данных страниц: `loadPages` → `createFullPages` / `LocalizationManager` / ключи `safeLocalized` | Локализации, A/B текстов, правки без перерисовки арта. |
| Картинки / 3D / Lottie **без сюжетного текста** (максимум декоративный бренд-мотив, не замена заголовков) | Dynamic Type и переводы остаются в SwiftUI. |
| Иллюстрация / 3D = **фон или боковая зона**; текст = **карточка / материал с контрастом** | Длинные локали, RTL, XL — безопасно. |
| **Один** визуальный стиль (**мягкая 3D** или **2.5D**), не микс стилей персонажа | «Вау», а не визуальный шум. |
| База палитры: **индиго + золото**; на слайде **один** эмоциональный акцент **+** усиление существующего `page.color` | Не ломаем уже заданные цвета страниц, а **надстраиваем** систему. |
| **Один «дорогой» слой** на экран (blur XOR тяжёлая анимация XOR частицы XOR тяжёлый 3D) | Старые iPhone (A11–A12): без фризов и перегрева. |
| **Не делаем** отдельные ассеты `OnboardingHero_Minimal_*` для 2-страничного fallback | Продуктово — полноценные 7 страниц; fallback в коде остаётся технич. запасом без отдельной арт-ветки. |

## 3. Слои экрана — онбординг (TabView, без замены `Text(page.title)` / `Text(page.description)`)

Рекомендуемая целевая схема (вкладывается в существующий `onboardingPage` / `languageStepView`):

```text
ZStack {
  (1) Полноэкранно: градиент слайда + hero (Image / Lottie) — уже близко к HeroAmbientLayerView + фон
  (2) Очень слабо: виньет / зернистость — глубина, без шума
  (3) Карточка: полупрозрачность или лёгкий material / blur (только если не конфликтует с §2 «один дорогой слой»)
        → внутри: вордмарк где нужно, заголовок, описание — как сейчас
}
```

- **Индикаторы точек** и **нижние кнопки** — снаружи «карточки героя» или с **собственной** подложкой (чтобы не тонули на ярком фоне). Сейчас: `HeroBottomReadableGradient` + дальнейший тюнинг под макет.

**Особый случай:** `contentIndex == 6` (последний контентный слайд: `ScrollView` + кольцо иконки) — **усиливать фоном и светом**, не ломая вёрстку.

## 4. Идея-бренда и сюжет × цвет × эмоция × «вау»

**Фраза-союз:** «Один карман — один круг доверия» — не набор функций, а **один щит** с семьёй; Аладдин — **союзник родителей**, тёплый, уверенный; **лампа** — якорь волшебства и технологии.

| # | Сцена | Эмоция | Акцент цвета (к `page.color` / градиенту) | «Вау» (коротко, один мотив на слайд) |
|---|--------|--------|------------------------------------------|-------------------------------------|
| 0 | Язык + лампа | любопытство, «меня ждут» | янтарное золото + индиго | пульс лампы; при выборе языка — haptic (уже есть) + искры (графика, **без** новых строк в PNG) |
| 1 | Цифровой «дом» семьи | уют | бирюзово-синий «домашний неон» | силуэт телефона-кармана внизу кадра |
| 2 | ИИ-спутник | облегчение | сапфир + золото | лёгкий parallax двух слоёв (только при полном motion tier) |
| 3 | Дети под куполом | нежность | лавандово-розовый | купол = световая сетка, не «решётка» |
| 4 | Радар угроз | ясность, не страх | электрик-синий | **один** «ping» при входе на слайд |
| 5 | Детский мир | радость | солнечно-жёлтый | теплее, в бренд-рамках |
| 6 | Взрослые / фейки | собранность | сталь + пурпур на «фальш» | холод только на угрозе, не на семье |
| 7 | Приглашение + лампа снова | принадлежность | то же золото, что на 0 | тот же ритм лампы — замыкание круга → Main |

**Шоу-вау (что даём / что режем):**

- **Даём:** смена фона по слайду, **один** сильный мотив, haptics, Reduce Motion / Low Power / background.
- **Режем:** автозвук, длинное видео, «кино» > ~1 s на свайп, разный стиль персонажа, **текст в PNG**, три конкурирующих эффекта.

## 5. Где Аладдин — три уровня (факт кода vs цель после арта)

### 5.A Факт (как сейчас в `14_OnboardingScreen.swift`)

| Экран / шаг | Что видит пользователь | Уровень |
|-------------|-------------------------|---------|
| Шаг 0 `languageStepView` | 🌐 + список языков | Нет вордмарка/персонажа в центре — только глобус |
| Контент 1 (`contentIndex == 0`) | Сверху `OnboardingAladdinLogoView` — золотой **текстовый** вордмарк (`AppConfig.localizedAppMarketingName`) | **Бренд**, не сюжетный 3D-Аладдин |
| Контент 2–6 | Круг `page.color` + emoji `page.icon` | Символика, не иллюстрация Аладдина |
| Контент 7 (`contentIndex == 6`) | Иконка приложения в золотом кольце + текст | Нет отдельного персонажа |

### 5.B Цель (иллюстрация в hero-слое после Figma)

| # | Персонаж на иллюстрации | Примечание |
|---|-------------------------|------------|
| 0 | Не обязателен; лампа + силуэт в дымке | «Раскрыть» лицо на Main и на слайде 2 |
| 1 | Далёкий силуэт / отражение в окне цифрового дома | Без мелкой детализации |
| 2 | Главный кадр: Аладдин с улыбкой рядом с родителем | Пик доверия |
| 3 | В куполе — мягкий «дух защиты» (световая маска), не жёсткая фигура | Нежность |
| 4 | Мини-виньетка в HUD / голограмме | Бдительность без страха |
| 5 | В углу, машет ребёнку | Радость |
| 6 | Серьёзный спокойный взгляд; родитель против «фальши» | Не хоррор |
| 7 | Полуфигура + лампа как на 0, улыбка, приглашение | Замыкание → Main |

Идея: **не дублировать** полноценного Аладдина на каждом шаге — нарастание к центру и **хвост на Main**.

## 6. Main (`01_MainScreen.swift`) — роль героя и слои

**Роль:** после онбординга — ощущение «**герой остался со мной**», связка со слайдами 2 и 7, не рекламный баннер.

**Целевой ZStack (логика поверх текущего):**

```text
ZStack {
  (A) LinearGradient — при необходимости богаче/темнее к низу под контраст силуэта
  (B) Герой: якорь .bottom / .trailing, scale ~0.75–0.95, opacity ~0.35–0.55
      • idle: лёгкое «дыхание» / кивок 2–3 s, улыбка читаема
      • allowsHitTesting(false)
  (C) Тонкий виньет сверху — читаемость шапки
  (D) Существующий VStack с UI — логика и тексты без изменений по смыслу
}
```

**Технологии слоя B (выбрать одну основную дорожку продакшена):**

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| USDZ + `Model3D` / RealityView (iOS 17+) | настоящий 3D, свет | вес, редактор, **не** единственный путь |
| Псевдо-3D: многослойный PNG/WebP + лёгкий parallax | дёшево, предсказуемо | не объём |
| Lottie (rig 2.5D) idle smile | малый вес, контроль | не настоящий 3D |

**Reduce Motion:** статика или кроссфейд, **без** бесконечной петли idle.

**a11y:** `accessibilityHidden(true)` на декоре **или** одна фраза вроде «Декоративный персонаж Аладдин на фоне» — чтобы VoiceOver не дублировал десятки элементов.

**Контент:** карточки, списки, тарифы — **выше** по z-order; фон **не** ухудшает читаемость CTA. При длинном скролле Main — герой **привязан к экрану** (не к прокручиваемому контенту), иначе «плывёт».

**Сейчас в коде:** есть слой `HeroAmbientLayerView(slot: .mainDashboard)` под контентом; дальнейший шаг — довести до спеки **B/C** (якорь, масштаб, виньет, idle) после выбора технологии.

| Фаза | MCP | Содержание |

| **C** | Xcode | Встроить фоны в `languageStepView` / `onboardingPage`; виджет/модификатор фона Main; тест RU + длинная локаль + Dynamic Type XL + старый iPhone. |

### 7.1 Мастер-файл Figma — закрытие зазора «сетка / слои / спека → код»

Одна задача на дизайн-стороне, чтобы **ничего не потерять** между Figma и `14_OnboardingScreen` / `01_MainScreen`:

- **Один мастер-файл** (или одна страница внутри файла) с секцией **Onboarding** и секцией **Main**.
- **Ровно 8 фреймов** онбординга (393×852 или ваш эталон) + **1 фрейм** героя Main + **отдельно** полноэкранный макет Main (UI целиком).
- **Auto-layout** на фреймах: зона **hero (верх ~60%)** и зона **карточки текста (низ ~40%)** — **в пикселях/отступах согласовано с §3** этого документа; для `contentIndex == 6` — отдельный вариант композиции hero, не ломающий `ScrollView` + кольцо.
- **Имена фреймов/групп экспорта** = канон Xcode (`OnboardingHero_00` … `OnboardingHero_07`, `MainHero_ambient`) или явная таблица «имя в Figma → имя в каталоге».
- **Стили:** цветовые стили под индиго/золото + акценты сюжета; не смешивать несовместимые стили персонажа (см. §2).
- **Экспорт:** пресеты **@2x/@3x** (или вектор где уместно); при необходимости **Dark**-варианты; без сюжетного текста внутри растров героя.
- **WCAG:** в макете проверка контраста текста на карточке поверх каждого фона (или фиксация цвета карточки, гарантированно читаемого на всех 8 фонах).

Эта подсекция **дублирует смысл** отдельной задачи в Cursor TODO (`figma-master-file-spec`).

## 8. Чеклист приёмки (расширенный)

- [ ] Все строки онбординга — из локализации; **нет** сюжетного текста только в картинках.
- [ ] **8** уникальных фонов сюжета + **повтор мотива лампы** на 0 и 7 (узнавание).
- [ ] Main: 3D / псевдо-3D / Lottie Аладдин на заднем плане; **не** перехватывает тапы; a11y ок.
- [ ] Reduce Motion: нет бесконечного пульса / parallax там, где запрещено политикой tier.
- [ ] Старые iPhone: нет связки **тяжёлый blur + тяжёлая анимация + 3D** одновременно.
- [ ] Dynamic Type XL: финал с двумя чекбоксами + длинные локали.
- [ ] RTL: smoke; при приоритете арабского — зеркалирование асимметричных композиций.
- [ ] Тёмная тема / memory warning — по §9 старого чеклиста в конце документа.

## 12. Figma vs «Nano Banana 2» (или любой image-only AI): что вернее для этого проекта

| Критерий | Figma (мастер + экспорт) | Только генеративные картинки |
|-----------|-------------------------|------------------------------|
| Сетка, safe area, карточка под `Text`, отступы | **Да**, явно в макете | **Нет** — только если потом вручную вносите в код |
| Согласованность 9 кадров + Main в одной системе | **Да** (компоненты, стили, страница) | **Слабо** без жёсткого bible и пост-обработки |
| WCAG на карточке × 8 фонов | **Удобно** проверить в макете | После экспорта — отдельная проверка |
| Скорость первых концептов | Медленнее | **Быстрее** (идеи, mood) |
| Поставка в Xcode (`@2x/@3x`, имена) | **Прямой пайплайн** | Нужен шаг нормализации и нейминг |

**Верное решение для вашего мобильного приложения:** **Figma как источник правды по композиции и экспорту** + при желании **AI для иллюстраций** (в т.ч. «nano banana 2») как **сырьё или варианты**, которые потом **собираются, выравниваются и именуются** в Figma или в редакторе растра под §7.1. **Заменять Figma целиком только генерацией полноэкранов** — **нет** для продуктового UI; **да** для ускорения **hero-слоёв**, если вы принимаете доп. работу по выравниванию серии.
