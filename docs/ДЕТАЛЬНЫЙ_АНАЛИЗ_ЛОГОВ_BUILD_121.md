### Проблема #1: AppConfig.authToken теряется между инициализацией и переходом на Analytics

**Временная линия:**
1. **15:46:04** - `loadPersistedData()` устанавливает `AppConfig.authToken = token.token` ✅
2. **15:48:54** - При переходе на Analytics `AppConfig.authToken` = `nil` ❌
3. **Разница:** ~2 минуты 50 секунд

**Возможные причины:**
1. **Computed property проблема:**
   ```swift
   static var authToken: String? {
       get {
           if let keychainToken = KeychainManager.shared.loadString(forKey: .authToken) {
               return keychainToken
           }
           return UserDefaults.standard.string(forKey: AppConfig.UserDefaultsKeys.authToken)
       }
   }
   ```
   - Getter всегда читает из Keychain/UserDefaults
   - Если токен удалён из Keychain → getter вернёт `nil`
   - Но токен остался в `SubscriptionManager.currentToken` (в памяти)

2. **Что-то очистило Keychain:**
   - Проверить логи на наличие `delete(forKey: .authToken)` между 15:46:04 и 15:48:54
   - Проверить `KeychainAutoRecoveryService.repairTokensIfNeeded()`
   - Проверить обработчики `SessionExpired` notification

3. **Проблема синхронизации:**
   - `SubscriptionManager.storeToken()` устанавливает `AppConfig.authToken`
   - Но если токен загружается из Keychain в `loadPersistedData()`, он устанавливается один раз
   - Если потом что-то очищает Keychain, `AppConfig.authToken` getter вернёт `nil`

**Решение:**
- ✅ `TokenManager` уже восстанавливает токен из `SubscriptionManager` в `AppConfig`
- ⚠️ Но это происходит **после** того, как `AnalyticsViewModel` уже проверил токен
- 🔧 Нужно убедиться, что токен всегда синхронизирован

3. **Токен невалидный на сервере:**
   - Токен был создан для другого устройства

4. **Проблема с передачей токена:**
   - Токен не передаётся в заголовке `Authorization`

**Решение:**
- Проверить реальный `exp` в JWT payload
- Сравнить с текущим временем на сервере
