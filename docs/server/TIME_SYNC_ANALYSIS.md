# ⏰ JWT-010: Анализ синхронизации времени между клиентом и сервером

**Дата:** 2026-03-16  
**Проблема:** Разница во времени между клиентом и сервером может вызывать ложные ошибки "Token expired"

---

## 📊 Анализ проверки exp

### На клиенте (iOS):
```swift
// Core/Security/JWTTokenManager.swift
let expirationDate = Date(timeIntervalSince1970: exp)
let isExpired = expirationDate < Date()
```
- Использует локальное время устройства
- Нет учета разницы с сервером

### На сервере (Python):
```python
# app/auth/auth.py
payload = jwt.decode(token, JWT_SECRET, algorithms=[JWT_ALGORITHM])
```
- PyJWT автоматически проверяет `exp`
- По умолчанию НЕТ leeway (допуска разницы времени)

---

## ⚠️ Потенциальная проблема

Если время на клиенте опережает серверное:
- Клиент: токен валиден (еще не истек по локальному времени)
- Сервер: токен истек (уже истек по серверному времени)
- Результат: **Ошибка 401 "Token expired"**

---

## 🔧 Рекомендации

### 1. Добавить leeway на сервере (РЕКОМЕНДУЕТСЯ)
```python
# app/auth/auth.py
payload = jwt.decode(
    token, 
    JWT_SECRET, 
    algorithms=[JWT_ALGORITHM],
    options={"verify_exp": True},
    leeway=60  # 60 секунд допуска
)
```

### 2. Использовать serverTime на клиенте
Если сервер возвращает `serverTime` в ответах, использовать его для проверки exp.

**Действие:** Добавить leeway на сервере для защиты от разницы времени
