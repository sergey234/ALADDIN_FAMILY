# ✅ ПОЛНЫЙ ОТЧЕТ: Исправление проблемы JWT 401

**Дата:** 2026-03-17  
**Проблема:** Клиент: токен валиден (840 минут до истечения), Сервер: 401 "Невалидный или истекший токен"  
**Статус:** ✅ **РЕШЕНО**

---

## 🔍 Диагностика проблемы

### Обнаруженные проблемы:

1. **❌ КРИТИЧНО: Несоответствие JWT_SECRET**
   - `app/auth/auth.py`: `"your-secret-key-change-in-production"` (36 символов)
   - `backend/app/services/jwt_service.py`: `"aladdin-super-secret-key-change-in-production"` (47 символов)
   - **Последствие:** Токены создавались с одним секретом, декодировались с другим → **ОШИБКА 401**

2. **⚠️ Потенциальная проблема: Синхронизация времени**
   - Нет leeway для разницы времени между клиентом и сервером
   - Может вызывать ложные ошибки "Token expired"

3. **⚠️ Недостаточное логирование**
   - Нет детального логирования в `decode_token()` на сервере
   - Сложно диагностировать проблемы

---

## 🔧 Выполненные исправления

### ✅ JWT-003: Детальное логирование на сервере
**Файлы:**
- `app/auth/auth.py`
- `backend/app/services/jwt_service.py`

**Изменения:**
- Добавлено логирование попытки декодирования (preview токена, preview секрета)
- Добавлено детальное логирование ошибок (ExpiredSignatureError, InvalidTokenError)
- Логирование успешного декодирования с информацией о пользователе

**Результат:** Теперь можно видеть детальную информацию о каждой попытке декодирования токена

---

### ✅ JWT-004: Проверка JWT_SECRET
**Создан скрипт:** `docs/server/check_jwt_secret.py`

**Обнаружено:**
- Несоответствие секретов между файлами
- Отсутствие JWT_SECRET в переменных окружения

**Результат:** Выявлена критическая проблема

---

### ✅ JWT-010: Синхронизация времени
**Файлы:**
- `app/auth/auth.py`
- `backend/app/services/jwt_service.py`

**Изменения:**
- Добавлен `leeway=60` секунд в `jwt.decode()` для защиты от разницы времени

**Результат:** Защита от ложных ошибок "Token expired" из-за разницы времени

---

### ✅ JWT-011: Унификация JWT_SECRET (КРИТИЧНО!)
**Файлы:**
- `app/auth/auth.py`
- `backend/app/services/jwt_service.py`

**Изменения:**
- Оба файла теперь используют: `"aladdin-super-secret-key-change-in-production"`
- Оба файла используют `os.getenv("JWT_SECRET", ...)` для единообразия

**Результат:** ✅ **ПРОБЛЕМА РЕШЕНА!** Токены теперь создаются и декодируются с одним секретом
