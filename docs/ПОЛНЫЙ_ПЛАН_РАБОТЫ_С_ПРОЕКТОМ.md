# 📋 ПОЛНЫЙ ПЛАН РАБОТЫ С ПРОЕКТОМ

**Дата:** 29 ноября 2025  
**Цель:** Чёткий план работы с одним проектом в двух местах

---

## 🎯 ГЛАВНЫЙ ПРИНЦИП

### Один проект, две роли:

1. **Локальный Xcode** = Разработка + Финальная сборка
2. **GitHub Actions** = Автоматическая проверка

---

## 📋 ЭТАПЫ РАБОТЫ

### ЭТАП 1: РАЗРАБОТКА (Локально)

**Где:** Ваш Mac, Xcode

**Что делать:**
1. ✅ Открыть проект в Xcode
2. ✅ Внести изменения в код
3. ✅ Протестировать локально (симулятор/устройство)
4. ✅ Исправить ошибки
5. ✅ Закоммитить изменения
6. ✅ Запушить в GitHub

**Результат:**
- ✅ Код изменён и протестирован
- ✅ Изменения отправлены в GitHub

---

### ЭТАП 2: АВТОМАТИЧЕСКАЯ ПРОВЕРКА (GitHub Actions)

**Где:** GitHub Actions (автоматически)

**Что происходит:**
1. ✅ Workflow запускается автоматически при push
2. ✅ Проверяет компиляцию (без подписи)
3. ✅ Создаёт Archive для проверки структуры
4. ✅ Отправляет результаты

**Результат:**
- ✅ Статус: Success или Failure
- ✅ Логи сборки
- ✅ Артефакты (если успешно)

**Что проверять:**
- ✅ Компилируется ли код
- ✅ Нет ли критических ошибок
- ✅ Правильная ли структура проекта

---

### ЭТАП 3: ФИНАЛЬНАЯ СБОРКА (Локально)

**Где:** Ваш Mac, Xcode

**Когда:** После успешной проверки на GitHub

**Что делать:**
1. ✅ Открыть проект в Xcode
2. ✅ Product → Clean Build Folder
3. ✅ Product → Archive (с подписью)
4. ✅ Validate App
5. ✅ Distribute App → App Store Connect
6. ✅ Или экспорт IPA для Transporter

**Результат:**
- ✅ Archive с подписью создан
- ✅ Загружен в App Store Connect
- ✅ Готов к ревью

## ✅ ЧТО ГДЕ ДЕЛАТЬ

### Локальный Xcode:

**Разработка:**
- ✅ Написание кода
- ✅ Тестирование
- ✅ Отладка
- ✅ Исправление ошибок

**Сборка:**
- ✅ Archive с подписью
- ✅ Validate App
- ✅ Distribute App
- ✅ Экспорт IPA

**Подпись:**
- ✅ Настройка Signing & Capabilities
- ✅ Управление provisioning profiles
- ✅ Работа с сертификатами

### GitHub Actions:

**Проверка:**
- ✅ Автоматическая компиляция
- ✅ Проверка структуры
- ✅ Проверка зависимостей
- ✅ Создание артефактов

**НЕ делает:**
- ❌ Финальную сборку для App Store
- ❌ Подпись (нет доступа к Apple Developer Portal)
- ❌ Загрузку в App Store Connect (только проверка)

## 🎯 ПРАВИЛА РАБОТЫ

### Правило 1: Всегда коммитить и пушить

**После изменений:**
1. ✅ Коммитить изменения
2. ✅ Пушить в GitHub
3. ✅ Проверять результаты GitHub Actions

### Правило 2: Проверять перед финальной сборкой

**Перед App Store:**
1. ✅ Убедиться, что GitHub Actions проверка прошла
2. ✅ Нет ошибок компиляции
3. ✅ Только потом собирать финальный билд

### Правило 3: Исправлять ошибки локально

**Если GitHub Actions показал ошибки:**
1. ✅ Открыть проект в Xcode
2. ✅ Исправить ошибки
3. ✅ Протестировать
4. ✅ Закоммитить и запушить
5. ✅ Проверить снова

## 📋 КОНКРЕТНЫЙ ПЛАН СЕЙЧАС

### Шаг 1: Проверить компиляцию на GitHub

**Что делать:**
1. ✅ Дождаться завершения workflow "Build Only (No Upload)"
2. ✅ Проверить статус (Success/Failure)
3. ✅ Посмотреть логи, если есть ошибки

**Ожидаемый результат:**
- ✅ Компиляция успешна (без подписи)
- ✅ Archive создан (без подписи, для проверки структуры)

### Шаг 2: Если компиляция успешна

**Что делать:**
1. ✅ Открыть проект в Xcode
2. ✅ Product → Clean Build Folder
3. ✅ Product → Archive (с подписью)
4. ✅ Validate App
5. ✅ Distribute App → App Store Connect

**Ожидаемый результат:**
- ✅ Archive с подписью создан
- ✅ Загружен в App Store Connect

### Шаг 3: Если есть ошибки компиляции

**Что делать:**
1. ✅ Открыть проект в Xcode
2. ✅ Исправить ошибки
3. ✅ Протестировать
4. ✅ Закоммитить и запушить
5. ✅ Повторить Шаг 1
