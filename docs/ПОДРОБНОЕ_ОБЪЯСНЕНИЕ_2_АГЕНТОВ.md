## 🗑️ АГЕНТ 1: PERSONAL DATA CLEANUP

### 🎯 ЧТО ЭТО ТАКОЕ?

**Personal Data Cleanup** - это расширение существующего `data_protection_manager.py`, которое автоматически находит и удаляет персональные данные пользователя с брокерских сайтов (сайтов, которые собирают и продают персональные данные).

### 🔍 ПРОБЛЕМА, КОТОРУЮ РЕШАЕТ

**Проблема:**
- Ваши персональные данные (email, телефон, имя, адрес) попадают на брокерские сайты
- Эти сайты собирают данные из открытых источников и продают их
- Любой может найти ваши данные через эти сайты
- Удаление данных вручную - долгий и сложный процесс

**Решение:**
- Автоматический поиск ваших данных на брокерских сайтах
- Автоматическая отправка запросов на удаление
- Отслеживание процесса удаления
- Уведомления о статусе удаления

---

### 🔧 ПРИНЦИП ДЕЙСТВИЯ

#### Шаг 1: Поиск данных на брокерских сайтах

**Как это работает:**

1. **Пользователь предоставляет данные:**
   ```python
   user_data = {
       "email": "user@example.com",
       "phone": "+79991234567",
       "name": "Иван Иванов",
       "address": "Москва, ул. Ленина, 1"
   }
   ```

2. **Агент проходит по списку брокерских сайтов:**
   ```python
   broker_sites = [
       "whitepages.com",
       "spokeo.com",
       "peoplefinder.com",
       "2gis.ru",
       "avito.ru",
       # ... и другие (100+ сайтов)
   ]
   ```
   
   **📋 Полный список всех брокерских сайтов (100+):**
   См. документ: `docs/ПОЛНЫЙ_СПИСОК_БРОКЕРСКИХ_САЙТОВ.md`
   
   **Регионы:**
   - 🇷🇺 Россия и СНГ: ~15-20 сайтов (2GIS, Avito, Яндекс, VK и др.)
   - 🇪🇺 Европа: ~25-30 сайтов (Pipl, Infobel Pro, LexisNexis, UKPhonebook и др.)
   - 🇺🇸 США и Канада: ~50+ сайтов (Whitepages, Spokeo, PeopleFinders, Intelius и др.)
   - 🌍 Глобальные: ~10-15 платформ (Google, Facebook, LinkedIn, Pipl и др.)

3. **Для каждого сайта:**
   - Выполняет поиск данных (через API или веб-скрапинг)
   - Проверяет, найдены ли данные пользователя
   - Сохраняет результат

4. **Возвращает список сайтов, где найдены данные:**
   ```python
   found_sites = [
       {
           "site": "whitepages.com",
           "data_found": ["email", "phone", "name"],
           "url": "https://whitepages.com/person/12345"
       },
       {
           "site": "spokeo.com",
           "data_found": ["email", "address"],
           "url": "https://spokeo.com/ivan-ivanov"
       }
   ]
   ```

**Технические детали:**
- Использует HTTP запросы для поиска
- Парсит HTML страницы для извлечения данных
- Сравнивает найденные данные с данными пользователя
- Использует алгоритмы сопоставления (fuzzy matching) для учета опечаток

#### Шаг 2: Автоматическое удаление данных

**Как это работает:**

1. **Пользователь выбирает сайты для удаления:**
   ```python
   sites_to_remove = ["whitepages.com", "spokeo.com"]
   ```

2. **Для каждого сайта агент определяет метод удаления:**

   **Вариант A: API удаления (если доступен)**
   ```python
   # Отправка HTTP запроса через API
   response = requests.post(
       "https://whitepages.com/api/remove-data",
       json={
           "email": "user@example.com",
           "reason": "GDPR request"
       },
       headers={"Authorization": "Bearer API_KEY"}
   )
   ```

   **Вариант B: Форма на сайте**
   ```python
   # Автоматическое заполнение формы
   # 1. Открыть страницу удаления
   # 2. Заполнить форму (email, причина удаления)
   # 3. Отправить форму
   # 4. Подтвердить удаление (если требуется)
   ```

   **Вариант C: Email запрос**
   ```python
   # Отправка email с запросом на удаление
   email_body = """
   Здравствуйте,
   
   Прошу удалить мои персональные данные:
   Email: user@example.com
   Телефон: +79991234567
   
   Основание: GDPR / 152-ФЗ
   """
   send_email("privacy@whitepages.com", "Data Removal Request", email_body)
   ```

3. **Сохранение ID запроса:**
   ```python
   removal_requests = [
       {
           "request_id": "req_12345",
           "site": "whitepages.com",
           "status": "pending",
           "requested_at": "2025-12-13T10:00:00",
           "expected_completion": "2025-12-20T10:00:00"
       }
   ]
   ```

**Технические детали:**
- Использует библиотеки для работы с формами (BeautifulSoup, Selenium)
- Обрабатывает различные форматы ответов (JSON, HTML, email)
- Сохраняет шаблоны запросов для каждого типа сайта
- Соблюдает юридические требования (GDPR, 152-ФЗ)

---

#### Шаг 3: Отслеживание процесса удаления

**Как это работает:**

1. **Периодическая проверка статуса:**
   ```python
   # Каждый день проверяем статус всех запросов
   for request in pending_requests:
       status = check_removal_status(request["request_id"])
       
       if status == "completed":
           # Данные удалены
           notify_user("Данные удалены с whitepages.com")
       elif status == "failed":
           # Ошибка удаления
           retry_removal(request)
   ```

2. **Статусы удаления:**
   - `pending` - запрос отправлен, ожидает обработки
   - `processing` - запрос обрабатывается
   - `completed` - данные удалены
   - `failed` - ошибка при удалении
   - `expired` - срок удаления истек

3. **Повторные запросы:**
   - Если данные не удалены через 7 дней - повторный запрос
   - Максимум 3 повторных запроса
   - Уведомление пользователю о проблеме

4. **Отчет пользователю:**
   ```python
   report = {
       "total_sites_scanned": 50,
       "sites_with_data": 12,
       "removal_requests_sent": 12,
       "completed": 8,
       "pending": 3,
       "failed": 1,
       "completion_percentage": 66.7
   }
   ```

**Технические детали:**
- Использует планировщик задач (cron или asyncio)
- Хранит статусы в базе данных или in-memory
- Отправляет уведомления через систему уведомлений ALADDIN

### 🔐 БЕЗОПАСНОСТЬ И ПРИВАТНОСТЬ

1. **Шифрование данных:**
   - Персональные данные шифруются перед отправкой
   - Используется AES-256

2. **Минимизация данных:**
   - Отправляются только необходимые данные для удаления
   - Не сохраняются полные данные пользователя

3. **Соблюдение законов:**
   - GDPR (для международных сайтов)
   - 152-ФЗ (для российских сайтов)
   - Правильные формулировки запросов

4. **Логирование:**
   - Логируются только действия, не персональные данные
   - Автоматическое удаление логов через 30 дней

## 🚑 АГЕНТ 2: ROADSIDE ASSISTANCE

### 🎯 ЧТО ЭТО ТАКОЕ?

**Roadside Assistance** - это агент, который предоставляет службу помощи на дороге 24/7. Пользователь может вызвать помощь прямо из приложения ALADDIN, и агент автоматически связывается с партнерской службой помощи.

### 🔍 ПРОБЛЕМА, КОТОРУЮ РЕШАЕТ

**Проблема:**
- Случилась поломка на дороге (прокол колеса, сел аккумулятор, закончился бензин)
- Нужно найти службу помощи
- Нужно объяснить проблему по телефону
- Нужно ждать помощи, не зная когда приедет

**Решение:**
- Одна кнопка в приложении для вызова помощи
- Автоматическое определение местоположения
- Автоматическая отправка запроса партнеру
- Отслеживание статуса помощи в реальном времени
- Уведомления о прибытии помощи

---

### 🔧 ПРИНЦИП ДЕЙСТВИЯ

#### Шаг 1: Вызов помощи

**Как это работает:**

1. **Пользователь нажимает кнопку "Вызвать помощь" в приложении**

2. **Приложение автоматически определяет местоположение:**
   ```swift
   // iOS автоматически получает GPS координаты
   let location = CLLocation(
       latitude: 55.7558,
       longitude: 37.6173
   )
   ```

3. **Пользователь выбирает тип проблемы:**
   - 🚗 Буксировка (TOWING)
   - 🔋 Запуск двигателя (JUMP_START)
   - 🛞 Замена колеса (TIRE_CHANGE)
   - 🔓 Открытие замка (LOCKOUT)
   - ⛽ Доставка топлива (FUEL_DELIVERY)

4. **Приложение отправляет запрос на сервер:**
   ```json
   POST /api/roadside-assistance/call
   {
       "user_id": "user123",
       "problem_type": "TIRE_CHANGE",
       "location": {
           "latitude": 55.7558,
           "longitude": 37.6173,
           "address": "Москва, Ленинградский проспект, 10"
       },
       "description": "Прокол переднего левого колеса",
       "vehicle_info": {
           "make": "Toyota",
           "model": "Camry",
           "year": 2020
       }
   }
   ```

5. **Агент на сервере:**
   - Выбирает партнера (по местоположению или настройкам)
   - Формирует запрос для партнера
   - Отправляет запрос через API партнера

---

#### Шаг 2: Интеграция с партнером

**Как это работает:**

**Пример интеграции с Росгосстрах:**

1. **Агент формирует запрос:**
   ```python
   request_data = {
       "service_type": "TIRE_CHANGE",
       "location": {
           "latitude": 55.7558,
           "longitude": 37.6173,
           "address": "Москва, Ленинградский проспект, 10"
       },
       "customer": {
           "name": "Иван Иванов",
           "phone": "+79991234567",
           "policy_number": "RGS-123456"
       },
       "vehicle": {
           "make": "Toyota",
           "model": "Camry"
       }
   }
   ```

2. **Отправка запроса через API партнера:**
   ```python
   response = requests.post(
       "https://api.rosgosstrah.ru/roadside-assistance/request",
       json=request_data,
       headers={
           "Authorization": "Bearer PARTNER_API_KEY",
           "Content-Type": "application/json"
       }
   )
   ```

3. **Партнер возвращает ID запроса:**
   ```json
   {
       "request_id": "RGS-2025-12-13-001234",

           "name": "Автопомощь 24/7",

           "vehicle_number": "А123БВ777"
       }
   }
   ```

4. **Агент сохраняет информацию:**
   ```python
   assistance_request = {
       "request_id": "RGS-2025-12-13-001234",
   ```

#### Шаг 3: Отслеживание статуса помощи

**Как это работает:**

1. **Периодическая проверка статуса (каждые 30 секунд):**
   ```python
   # Агент проверяет статус у партнера
   status = requests.get(
       f"https://api.rosgosstrah.ru/roadside-assistance/{request_id}/status",
       headers={"Authorization": "Bearer PARTNER_API_KEY"}
   )
   ```

2. **Статусы помощи:**
   - `pending` - запрос создан, ожидает диспетчера
   - `dispatched` - диспетчер назначил службу помощи
   - `on_way` - служба помощи в пути
   - `arrived` - служба помощи прибыла на место
   - `in_progress` - помощь оказывается
   - `completed` - помощь оказана, проблема решена
   - `cancelled` - запрос отменен

3. **Уведомления пользователю:**
   ```python
   if status == "dispatched":
       notify_user("Служба помощи назначена. Ожидаемое время прибытия: 16:45")
   
   if status == "on_way":
       notify_user("Служба помощи в пути. Водитель: Иван, телефон: +79991111111")
   
   if status == "arrived":
       notify_user("Служба помощи прибыла на место!")
   ```

4. **Обновление статуса в приложении:**
   - Приложение автоматически обновляет статус
   - Показывает карту с местоположением службы помощи (если доступно)
   - Показывает контактный телефон водителя

---

#### Шаг 4: Отмена запроса

**Как это работает:**

1. **Пользователь нажимает "Отменить" в приложении**

2. **Приложение отправляет запрос:**
   ```json
   POST /api/roadside-assistance/cancel
   {
       "request_id": "RGS-2025-12-13-001234"
   }
   ```

3. **Агент отправляет запрос на отмену партнеру:**
   ```python
   requests.post(
       f"https://api.rosgosstrah.ru/roadside-assistance/{request_id}/cancel",
       headers={"Authorization": "Bearer PARTNER_API_KEY"}
   )
   ```

4. **Партнер подтверждает отмену:**
   ```json
   {
       "status": "cancelled",
       "cancellation_fee": 0,  // или сумма штрафа, если уже выехали
       "cancelled_at": "2025-12-13T16:25:00"
   }
   ```
