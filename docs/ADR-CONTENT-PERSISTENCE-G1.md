# ADR: хранение локального кеша контента (G1)

**Статус:** accepted  
**Дата:** 2026-04-26  
**Связь:** `docs/GAP_CLOSURE_PLAN_PHASES_1_8_ML_HANDOFF.md` (G1, Wave 0)

## Контекст

Каталог и прогресс (`ContentManifest`, `ContentProgress`) должны переживать перезапуск, не терять целостность и иметь путь миграции. Ранее в плане фигурировал «CoreData»; в коде используется один JSON-файл `content-db-v1.json` в Application Support.

## Решение (на текущую волну)

1. **Канон на ближайший релиз:** оставляем **файловый снимок** (`ContentDatabase` → JSON в `content-db-v1.json`) как реализацию G1 **уровня MVP+**, с явной **версией схемы** внутри снимка (уже через `PersistedContentSnapshot` / `manifest` + `progressById`).

2. **Следующий шаг (не блокер W0, но зафиксирован):** либо **GRDB/SQLite** с миграциями и индексами, либо **JSON v2** с `schemaVersion` + миграцией при старте, либо **CoreData** с правилами лёгких миграций. Выбор фиксируется отдельным ADR, когда появятся требования к запросам по 10k+ items или аналитике на диске.

3. **Источник правды для каталога** остаётся **серверный манифест**; локальное хранилище — **кеш** после успешной валидации/подписи (G3) и sync (G2).

## Последствия

- iOS: расширять только через осознанные изменения DTO/схемы и тесты миграции.
- Документация: этот ADR снимает расхождение «заявлено CoreData / факт JSON» до внедрения следующего варианта.
