## 🔍 КАК РАБОТАЕТ ПОИСК ДАННЫХ

### Текущая реализация:

**Поиск происходит:**
- ✅ **По запросу пользователя** - когда пользователь нажимает кнопку "Сканировать" в приложении
- ✅ **Принудительный поиск** - всегда выполняется, если пользователь явно запросил

**API Endpoint:**
```
POST /api/data-cleanup/scan
```

**Как это работает:**
1. Пользователь открывает приложение
2. Переходит в раздел "Очистка данных"
3. Нажимает кнопку "Сканировать сайты"
4. Приложение отправляет запрос на `/api/data-cleanup/scan`
5. Агент ищет данные на всех брокерских сайтах
6. Возвращает список найденных сайтов

## ⏰ ПЕРИОДИЧЕСКИЙ ПОИСК (НОВАЯ ФУНКЦИЯ)

### Что добавлено:

**Периодический мониторинг:**
- ✅ Автоматическая проверка раз в N дней (по умолчанию 30 дней)
- ✅ Кэширование результатов
- ✅ Пропуск поиска, если не прошло достаточно времени
- ✅ Настройка интервала через конфигурацию

**Конфигурация:**
```python
{
    "enable_periodic_scan": false,  # Включить периодический поиск
    "scan_interval_days": 30        # Интервал в днях (по умолчанию 30)
}
```

## 🎯 РЕЖИМЫ РАБОТЫ

### Режим 1: Только по запросу (по умолчанию)

**Настройка:**
```json
{
    "enable_periodic_scan": false
}
```

**Как работает:**
- Поиск выполняется **только** когда пользователь явно запрашивает
- Нет автоматических проверок
- Пользователь полностью контролирует процесс

**Когда использовать:**
- ✅ Если пользователь хочет сам решать, когда искать данные
- ✅ Если нужно экономить ресурсы сервера
- ✅ Если поиск платный или ограничен

---

### Режим 2: Периодический мониторинг

**Настройка:**
```json
{
    "enable_periodic_scan": true,
    "scan_interval_days": 30
}
```

**Как работает:**
- Автоматическая проверка каждые 30 дней (или другой интервал)
- Если пользователь запрашивает поиск раньше - выполняется принудительно
- Результаты кэшируются до следующего поиска

**Пример:**
```
День 1: Пользователь запросил поиск → Поиск выполнен
День 15: Пользователь запросил поиск → Поиск выполнен (принудительно)
День 30: Автоматический поиск → Поиск выполнен
День 35: Пользователь запросил поиск → Возвращаются кэшированные результаты
День 60: Автоматический поиск → Поиск выполнен
```

**Когда использовать:**
- ✅ Если нужно автоматически отслеживать появление новых данных
- ✅ Если данные могут появиться на сайтах снова
- ✅ Если пользователь хочет "забыть" о проблеме

---

## 📊 СРАВНЕНИЕ РЕЖИМОВ

| Параметр | Только по запросу | Периодический мониторинг |
|----------|------------------|--------------------------|
| **Инициация** | Пользователь | Автоматически |
| **Частота** | По требованию | Каждые N дней |
| **Ресурсы** | Минимум | Больше (но контролируемо) |
| **Контроль** | Полный | Частичный |
| **Кэширование** | Да | Да |
| **Уведомления** | Нет | Можно добавить |

## 🔧 НОВЫЕ API ENDPOINTS

### 1. Получить статус поиска

```
GET /api/data-cleanup/scan-status?user_id=user123
```

**Ответ:**
```json
{
    "status": "success",
    "scan_status": {
        "last_scan": "2025-12-13T10:00:00",
        "days_since_scan": 5.2,
        "next_scan_in_days": 24.8,
        "sites_found": 3,
        "scan_enabled": true,
        "scan_interval_days": 30
    }
}
```

**Использование:**
- Показывает, когда был последний поиск
- Показывает, когда будет следующий поиск
- Показывает, включен ли периодический мониторинг

---

### 2. Запустить периодический поиск

```
POST /api/data-cleanup/periodic-scan
{
    "user_id": "user123",
    "email": "user@example.com",
    "name": "Иван Иванов"
}
```

**Ответ (если поиск выполнен):**
```json
{
    "status": "success",
    "user_id": "user123",
    "sites_found": 3,
    "sites": [...]
}
```

**Ответ (если поиск пропущен):**
```json
{
    "status": "skipped",
    "message": "Поиск не требуется. Еще не прошло достаточно времени с последнего поиска.",
    "scan_status": {
        "last_scan": "2025-12-13T10:00:00",
        "days_since_scan": 5.2,
        "next_scan_in_days": 24.8
    }
}
```

**Использование:**
- iOS приложение может вызывать этот endpoint периодически
- Если прошло достаточно времени - поиск выполнится
- Если нет - вернутся кэшированные результаты

## 💡 РЕКОМЕНДАЦИИ ПО ИСПОЛЬЗОВАНИЮ

### Для пользователей:

**Рекомендуемый интервал:**
- **Минимум:** 30 дней (раз в месяц)
- **Оптимально:** 30-60 дней
- **Максимум:** 90 дней (раз в квартал)

**Почему:**
- Новые данные обычно появляются не очень часто
- Поиск на 100+ сайтах занимает время и ресурсы
- 30 дней - хороший баланс между актуальностью и нагрузкой

---

### Для разработчиков:

**Настройка через переменные окружения:**
```bash
# Включить периодический поиск
export DATA_CLEANUP_ENABLE_PERIODIC_SCAN=true

# Интервал в днях
export DATA_CLEANUP_SCAN_INTERVAL_DAYS=30
```

**В коде:**
```python
config = {
    "enable_periodic_scan": os.getenv("DATA_CLEANUP_ENABLE_PERIODIC_SCAN", "false").lower() == "true",
    "scan_interval_days": int(os.getenv("DATA_CLEANUP_SCAN_INTERVAL_DAYS", "30"))
}
```

## 🔄 ИНТЕГРАЦИЯ С iOS

### Вариант 1: Background Tasks (рекомендуется)

**Использовать iOS Background Tasks для периодического вызова:**

```swift
// В BackgroundTaskManager.swift
BGTaskScheduler.shared.register(
    forTaskWithIdentifier: "com.aladdin.datacleanup.scan",
    using: nil
) { task in
    self.handleDataCleanupScan(task: task as! BGAppRefreshTask)
}

func handleDataCleanupScan(task: BGAppRefreshTask) {
    task.expirationHandler = {
        task.setTaskCompleted(success: false)
    }
    
    Task {
        // Вызываем периодический поиск
        await APIService.shared.triggerPeriodicDataCleanupScan()
        task.setTaskCompleted(success: true)
    }
}
```

**Расписание:**
- Выполняется раз в 30 дней (или по настройке)
- iOS сам решает оптимальное время
- Экономит батарею

---

### Вариант 2: При открытии приложения

**Проверять при каждом открытии приложения:**

```swift
// В AppDelegate или SceneDelegate
func applicationDidBecomeActive() {
    // Проверяем статус поиска
    APIService.shared.getDataCleanupScanStatus { status in
        if let daysSince = status.daysSinceScan,
           daysSince >= status.scanIntervalDays {
            // Запускаем периодический поиск
            APIService.shared.triggerPeriodicDataCleanupScan()
        }
    }
}
```

**Плюсы:**
- Простая реализация
- Работает всегда, когда приложение открыто

**Минусы:**
- Поиск может начаться в неподходящее время
- Может замедлить запуск приложения
