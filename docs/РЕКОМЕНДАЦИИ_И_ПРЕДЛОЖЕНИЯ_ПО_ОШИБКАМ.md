### 🔴 1. ComponentError.networkError

**Проблема:** Используется с параметром, но определен без параметра

**Рекомендация:** ✅ **Добавить параметр String**

**Почему:**
- Более информативно (можно передать детали ошибки)
- Соответствует другим case (apiError, configurationError имеют параметры)
- Проще для отладки

**Как исправить:**
```swift
// БЫЛО:
case networkError

// СТАНЕТ:
case networkError(String)
```

**Обновить errorDescription:**
```swift
case .networkError(let message):
    return "Ошибка сети: \(message)"
```

**Время:** 5 минут  
**Риск:** Низкий (простое изменение)

### 🔴 3. ComponentStatus не находит ComponentConfiguration

**Проблема:** Порядок компиляции файлов

**Рекомендация:** ✅ **Проверить Build Phases в Xcode**

**Почему:**
- Swift компилирует файлы в порядке добавления в проект
- ComponentStatus должен компилироваться после ComponentConfiguration

**Как исправить:**
1. Открыть Xcode
2. Выбрать проект → Build Phases → Compile Sources
3. Убедиться что `ComponentConfiguration.swift` идет ПЕРЕД `ComponentStatus.swift`
4. Если нет - перетащить файлы в правильном порядке

**Альтернатива:** Добавить forward declaration (не рекомендуется)

**Время:** 3 минуты  
**Риск:** Низкий (просто перестановка)

### 🟠 4. @MainActor в Mock классах

**Проблема:** Mock классы наследуются от @MainActor классов

**Рекомендация:** ✅ **Убрать @MainActor с Mock классов**

**Почему:**
- Mock классы для тестов не должны быть @MainActor
- Тесты могут запускаться не на главном потоке
- Проще тестировать

**Как исправить:**
```swift
// БЫЛО:
@MainActor
class MockComponentStatusService: ComponentStatusService {
    // ...
}

// СТАНЕТ:
class MockComponentStatusService: ComponentStatusService {
    // Убрать @MainActor
    // Обернуть вызовы в MainActor.run если нужно
}
```

**Время:** 10 минут  
**Риск:** Средний (нужно проверить все вызовы)

### 🟠 5. Result<NetworkError> vs ComponentError

**Проблема:** Несовместимость типов ошибок

**Рекомендация:** ✅ **Создать extension для конвертации**

**Почему:**
- Не нужно менять RetryManager (он используется везде)
- Не нужно менять все ViewModels
- Простое решение

**Как исправить:**
```swift
// Добавить extension:
extension ComponentError {
    func toNetworkError() -> NetworkError {
        switch self {
        case .networkError(let message):
            return .noConnection
        case .apiError(let message):
            return .badRequest(message)
        case .componentNotFound(let id):
            return .notFound("Component \(id) not found")
        // ... остальные case
        default:
            return .unknown(self)
        }
    }
}

// Использовать:
let result = await retryManager.execute {
    try await self.statusService.updateStatus(...)
}.mapError { $0.toNetworkError() }
```

**Время:** 15 минут  
**Риск:** Средний (нужно протестировать конвертацию)

```swift
    }

```

### 2. Улучшить ToastManager

**Предложение:** Добавить автоматическое скрытие

**Преимущества:**
- Лучший UX

```swift
func showSuccess(_ message: String, duration: TimeInterval = 3.0) {
```

### 3. Создать протоколы для Mock классов

**Предложение:** Использовать протоколы вместо наследования

- Нет проблем с @MainActor
- Легче тестировать
- Более гибко

**Реализация:**
```swift
protocol ComponentStatusServiceProtocol {
    func getStatus(for componentId: String) async throws -> ComponentStatus
}

class ComponentStatusService: ComponentStatusServiceProtocol {
    // ...
}

class MockComponentStatusService: ComponentStatusServiceProtocol {
    // Нет наследования, только протокол
}
```
