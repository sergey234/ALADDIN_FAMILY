# Алгоритм приёмки одной страницы Figma (OB_00 … OB_07 + Main)

**Назначение:** после каждой правки фрейма в Figma агент (или человек) **обязан** пройти этот чеклист **до** перехода к следующей странице.

**Мастер-план (все TODO, порядок, ссылки на файлы):** `docs/ONBOARDING_MASTER_IMPLEMENTATION_PLAN.md`. Цель — синхронизация с **живым приложением**, **планом** и **каноном имён**, без «сдал на глаз».

**Эталоны (не менять порядок сверки):**

| Приоритет | Источник | Что берём |
|-----------|----------|-----------|
| 1 | `Screens/14_OnboardingScreen.swift` (+ `01_MainScreen.swift` для Main) | Вёрстка, отступы, структура, что в TabView vs chrome |
| 2 | `Core/Localization/LocalizationManager.swift` (RU) + fallback в `14_OnboardingScreen` | **Точные строки** заголовков/описаний/кнопок |
| 3 | `docs/ONBOARDING_NINE_SCREENS_REFERENCE.md` | Индексы, ассеты, ключи, особенности слайда |
| 4 | `docs/ONBOARDING_FIGMA_FRAME_CHECKLIST.md` | Имена фреймов, слои, зоны |
| 5 | `docs/ONBOARDING_MAIN_HERO_HANDOFF.md` §1.4–1.8, §4–5 | Зоны 60/40/chrome, сюжет, §1.8 «не ломать» |
| 6 | `docs/ALADDIN_Onboarding_Prompts.md` | Сюжет героя (в растре без текста) |
| 7 | Симулятор Xcode | Финальный Visual QA (скрин vs Figma) |

**Правило:** Figma — эталон **композиции и экспорта**, не новый копирайт. Тексты в макете = строки из кода (RU для базового макета).

---

## Порядок работы на одну страницу (Definition of Done)

```text
A. Подготовка (5 мин)
B. Сборка / правка фрейма в Figma
C. Автоматическая сверка (агент: metadata + код + этот файл)
D. Visual QA в симуляторе (человек или агент со скрином)
E. Галочки в таблицах + переход к N+1
```

**Не начинать OB_(N+1), пока OB_N не имеет статус «Принято» по §E внизу.**
