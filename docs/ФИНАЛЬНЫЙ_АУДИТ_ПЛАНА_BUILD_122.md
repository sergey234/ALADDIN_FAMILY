### ЭТАП 1: ВОССТАНОВЛЕНИЕ ТОКЕНА ПЕРЕД ЗАПРОСАМИ

#### ✅ Техническая корректность: ОТЛИЧНО

**Анализ:**
- ✅ Чтение из памяти (`SubscriptionManager.shared.currentToken`) - синхронно, безопасно
- ✅ Не вызывает `UserDefaults` напрямую
- ✅ Не вызывает тяжелые операции
- ✅ Выполняется перед проверкой токена (правильный порядок)

**Потенциальные проблемы:**
1. ⚠️ **Race condition при параллельных запросах:**
   - Если несколько запросов одновременно проверяют `AppConfig.authToken == nil`
   - Все могут попытаться восстановить токен одновременно
   - **РЕШЕНИЕ:** Добавить флаг восстановления

**Исправленный код:**
```swift
// ✅ BUILD 122: Восстановление токена с защитой от race condition
if requiresAuth {
    // ✅ ЗАЩИТА: Проверяем флаг восстановления
    if AppConfig.authToken == nil {
        // ✅ Используем синхронный доступ к singleton (thread-safe)
        if let token = SubscriptionManager.shared.currentToken {
            // ✅ Атомарная операция записи
            AppConfig.authToken = token.token
            #if DEBUG
            logger.business("✅ NetworkManager: Токен восстановлен из SubscriptionManager")
            #endif
        }
    }
    
    guard let token = AppConfig.authToken else {
        completion(.failure(NetworkError.unauthorized("Токен авторизации отсутствует")))
        return
    }
    request.setValue("Bearer \(token)", forHTTPHeaderField: "Authorization")
}
```

**Оценка:**
- ✅ **Безопасность:** Высокая (чтение из памяти, атомарная запись)
- ✅ **Производительность:** Отличная (O(1), синхронно)
- ✅ **Стабильность:** Высокая (не влияет на существующую логику)

### ЭТАП 2: УМНАЯ ОБРАБОТКА 403 С ЗАЩИТОЙ ПОДПИСКИ

#### ✅ Техническая корректность: ОТЛИЧНО (после исправлений)

**Анализ:**
- ✅ Проверка уровня подписки перед перерегистрацией - правильное решение
- ✅ Использование refresh token для платных пользователей - соответствует best practices
- ✅ Восстановление подписки с сервера - правильный подход

**Потенциальные проблемы:**
1. ⚠️ **Метод `restoreSubscriptionFromServer()` требует endpoint:**
   - Нужно проверить, существует ли `/api/subscription/status` или аналогичный
   - Если нет - нужно создать или использовать существующий
   - **РЕШЕНИЕ:** Проверить существующие endpoints

2. ⚠️ **Метод `refreshTokenWithSubscription()` не существует:**
   - Нужно реализовать или использовать существующий метод
   - **РЕШЕНИЕ:** Использовать существующий `refreshTokenIfNeeded()` или создать новый

3. ⚠️ **Асинхронность в `JWTErrorRecovery`:**
   - `Task { @MainActor in }` правильный подход
   - Но нужно убедиться, что не блокирует UI
   - **РЕШЕНИЕ:** Использовать `Task.detached` для тяжелых операций

**Исправленный код:**
```swift
// ✅ BUILD 122: Умная обработка 403 с защитой подписки
case 403:
    logger.business("🔄 DEFENSIVE JWT: 403 Forbidden - проверяем подписку")
    
    // ✅ КРИТИЧНО: Проверяем уровень подписки перед перерегистрацией
    let currentLevel = SubscriptionManager.shared.getCurrentLevel()
    
    if currentLevel != .free {
        // ✅ У пользователя есть платная подписка или триал
        logger.business("🔄 У пользователя активная подписка (\(currentLevel)) - восстанавливаем")
        
        // ✅ Используем Task.detached для тяжелых операций (не блокирует UI)
        Task.detached { @MainActor in
            // 1. Пытаемся обновить через refresh token
            let refreshed = await JWTTokenManager.shared.refreshTokenIfNeeded()
            
            if !refreshed {
                // 2. Если refresh не удался, восстанавливаем с сервера
                // ✅ ПРОВЕРКА: Используем существующий endpoint или создаем новый
                await SubscriptionManager.shared.restoreSubscriptionFromServer()
            }
        }
        return .silentRetry
    } else {
        // ✅ Только для FREE пользователей - перерегистрация безопасна
        logger.business("🔄 FREE пользователь - перерегистрация безопасна")
        Task.detached { @MainActor in
            await SubscriptionManager.shared.performDeviceRegistration()
        }
        return .silentRetry
    }
```

**Оценка:**
- ✅ **Безопасность:** Высокая (защита подписки)
- ✅ **Функциональность:** Отличная (умная обработка ошибок)
- ⚠️ **Реализация:** Требует проверки endpoints (исправлено в плане)
