# Семья API: что сохранить перед работой и план выката

Короткий чеклист для команды: **зафиксировать текущее состояние**, затем идти по этапам из `docs/server/BACKEND_FAMILY_JOIN_AND_ADD_GATE.md` и смоука `docs/FAMILY_API_SMOKE_REGIMEN.md`.

---

## Часть A. Что сохранить / зафиксировать **до** правок на сервере

1. **iOS-репозиторий (без обязательной ветки/тега)**  
   - Закоммиченные отпечатки: **`docs/FAMILY_MOBILE_SNAPSHOT_BASELINE.md`** (SHA256 по ключевым файлам).  
   - Полные копии тех же путей + `openapi.json`: **`./scripts/snapshot_family_mobile_sources.sh`** → `docs/backup/family-mobile-snapshot-*` (каталоги снимков в **`.gitignore`**; при необходимости скопируйте папку на диск/архив вручную).  
   - Инструкция: **`docs/FAMILY_MOBILE_SNAPSHOT_README.md`**.

2. **Снимок API «как было»** (чтобы сравнить после выката)  
   - Сохранить ответы в файлы **вне** репозитория или в приватный архив:  
     `GET …/openapi.json`, при наличии JWT — пробный `POST /api/family/join` (ожидаемый 404/ошибку до фикса) и `GET /api/family/stats`.  
   - Не класть JWT и пароли в git.

3. **Бэкенд**  
   - Тег или ветка в репозитории бэкенда с текущим прод-коммитом.  
   - Бэкап критичных файлов перед правкой (по вашему runbook): например `app/routers/family.py`, сервисы семьи, `subscription_limits.py`.

4. **Ссылки на канон** (ничего не теряется при смене чата)  
   - ТЗ бэкенда: `docs/server/BACKEND_FAMILY_JOIN_AND_ADD_GATE.md`  
   - Смоук: `docs/FAMILY_API_SMOKE_REGIMEN.md`  
   - Канон iOS+прод: `docs/REGISTRATION_AND_TARIFF_MAIN_SCREEN_ML_REFERENCE.md`

## Часть B. План реализации (простыми словами)

### Этап 1 — Сервер (обязательное для join)

- Реализовать **`POST /api/family/join`** с телом как у iOS (`JoinFamilyRequest`: `family_id`, `role`, `age_group`, `personal_letter`, `device_type`), ответ в формате, который уже ждёт клиент (семья + `your_member_id` и т.д.).  
- Локально: `python3 -m py_compile` на изменённых файлах, перезапуск сервиса по вашему гайду.  
- Сразу проверить: один успешный join с тестового клиента или curl (с JWT).

### Этап 2 — Сервер (желательно для «не пустить лишнего»)

- В **`POST /api/family/add`**: перед добавлением строки в БД — посчитать участников семьи и сравнить с лимитом тарифа (`getMaxFamilyMembersFor` или аналог); при переполнении — **409** с понятным `detail`.

### Этап 3 — После выката на тест / прод

- Снять **новый** `openapi.json` с того же хоста, что считаете источником правды.  
- В iOS-репо: заменить или обновить `docs/release/current/openapi.json` (или задокументировать URL скрипта обновления).  
- Пройти **`docs/FAMILY_API_SMOKE_REGIMEN.md`** целиком: создать семью → stats → join вторым пользователем → add → remove → снова stats; числа должны совпасть с главным экраном в приложении.

### Этап 4 — Приложение

- Сборка с текущего iOS-кода, тест на **реальном устройстве**: ввод кода приглашения, главная, счётчики членов и слоты.  
- При расхождении — логи Xcode по шагам смоука + сырой ответ `family/stats` и `members`.

### Этап 5 — Продукт (по необходимости)

- Проверить тексты тарифа: «устройства» vs «члены семьи», чтобы не путали после смены лимита Personal на 2 **человека** в ростере.

---

## Порядок одной фразой

**Сохранить git/теги и снимок API → сделать POST join (+ опционально gate на add) на сервере → выкат → новый OpenAPI в репо → смоук по документу → проверка в приложении на устройстве.**
