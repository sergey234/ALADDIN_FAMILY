# 🚨 SETTINGS SCREEN CRASH - ПОЛНЫЙ АНАЛИЗ И ПЛАН ИСПРАВЛЕНИЙ

## 📋 ОБЩАЯ ИНФОРМАЦИЯ

**Дата анализа:** 20 февраля 2026 года
**Проблема:** Бесконечная рекурсия типов Swift в SettingsScreen
**Статус:** Активная диагностика (тестируем гипотезы)
**Версия приложения:** BUILD 67 (1.0.0)

---

## 🔥 ПРОБЛЕМА - ПРОСТЫМ ЯЗЫКОМ

Представьте компьютерную программу, которая пытается сосчитать до 10, но каждый раз, когда доходит до числа 3, она забывает что считала и начинает заново. И так бесконечно. Это и есть наша проблема.

**SwiftUI пытается нарисовать экран Settings, но в процессе рисования что-то вызывает повторное рисование, которое снова вызывает повторное рисование... и так до бесконечности.** В итоге программа "зависает" и iOS убивает приложение.

### Технические детали:
- **Тип ошибки:** `EXC_BAD_ACCESS (SIGSEGV)`
- **Причина:** `Thread stack size exceeded due to excessive recursion`
- **Где происходит:** SettingsScreen в SwiftUI
- **Последствия:** Приложение крашится через 1-2 секунды после открытия Settings

---

## 📊 ЧТО ПОКАЗЫВАЮТ LOGИ КРАША

### Основные симптомы:
```
Exception Type: EXC_BAD_ACCESS (SIGSEGV)
Exception Subtype: KERN_PROTECTION_FAILURE
Exception Message: Thread stack size exceeded due to excessive recursion
```

### Stack trace показывает:
1. **100+ повторений** функций типа `swift_getTypeByMangledName`
2. **Swift runtime** пытается разрешить типы бесконечно
3. **Последний адрес** в `ScrollView.init` и `ZStack.init`
4. **Наши адреса в коде:** `0x100b7f360`, `0x100ffd280`, `0x100ff8bd4`

### Что это значит простыми словами:
- SwiftUI пытается создать экран
- В процессе создания происходит что-то, что заставляет SwiftUI пересоздать экран
- Пересоздание снова вызывает ту же проблему
- Получается замкнутый круг смерти

## 🎯 НАША ТЕКУЩАЯ ГИПОТЕЗА

### Что мы думаем:
Проблема может быть в двух компонентах:
1. **`initializeProtectionLevel()` функция** - содержит сложную логику
2. **`@State cardBackgroundView`** - сложная View структура в @State

### Почему мы так думаем:
```swift
// Функция initializeProtectionLevel() делает:
let tariff = tariffManager.currentTariff           // Доступ к синглтону
let card = tariff.createCard(localizationManager)  // Работа с @EnvironmentObject
cachedProtectionLevel = calculateSomething()       // Изменение @State переменных

// @State cardBackgroundView содержит:
AnyView(RoundedRectangle(...).overlay(...))        // Сложная View структура
```

### Логика тестирования:
```
Если отключить эти компоненты → приложение не крашится
    → Значит проблема в них
    
Если приложение крашится → проблема в другом месте
```

## ❌ ЕСЛИ НАША ГИПОТЕЗА НЕ ПОДТВЕРДИТСЯ

**Значит проблема НЕ в этих компонентах**

### 🔍 Возможные другие причины:

#### 1. **@EnvironmentObject localizationManager в других местах**
```swift
// Пример проблемы:
struct SomeView: View {
    @EnvironmentObject var localizationManager: LocalizationManager
    
    var body: some View {
        Text(localizationManager.localized("key"))  // Может вызывать перерисовку
    }
}
```

#### 2. **Другие @State переменные в SettingsScreen**
```swift
// SettingsScreen имеет много @State:
@State private var isBiometricEnabled: Bool = false
@State private var showProfileEdit: Bool = false
@State private var selectedTheme: ThemeMode = .system
@State private var cachedProtectionLevel: Double = 25.0
// ... и еще 15+ @State переменных

// Любая из них может вызывать проблемы при инициализации
```

#### 3. **Computed properties в самих менеджерах**
```swift
// tariffManager.currentTariff может содержать:
class TariffManager {
    var currentTariff: Tariff {
        // Сложные вычисления
        // Доступ к другим менеджерам
        // Циклические зависимости
    }
}
```

#### 4. **Проблемы в ScrollView/ZStack компонентах SwiftUI**
```swift
// Наш SettingsScreen использует:
ScrollView(.vertical, showsIndicators: false) {
    VStack(spacing: Spacing.l) {
        ZStack {
            // Много вложенных View
        }
    }
}

// SwiftUI может иметь проблемы с:
// - Слишком глубокой иерархией View
// - Циклическими зависимостями в layout
// - Проблемами с GeometryReader или similar
```

#### 5. **Архитектурные проблемы (циклические зависимости между View)**
```swift
// Возможная проблема:

    └── NavigationManager (@EnvironmentObject)

            └── SettingsScreen зависит от NavigationManager
```
