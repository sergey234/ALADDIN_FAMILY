## 🎩 ЧЕРНАЯ ШЛЯПА: КРИТИЧЕСКОЕ МЫШЛЕНИЕ И РИСКИ

### Что может пойти не так:

#### Риск #1: Calendar.current - не единственная проблема

**Проблема:**
- Даже если мы установим статический Calendar, может быть другая причина рекурсии
- ICU библиотека может читать из UserDefaults через другие механизмы

**Вероятность:** 🟡 40%

**Митигация:**
- Добавить логирование для отслеживания всех обращений к UserDefaults
- Проверить, не используется ли Calendar.current в других местах

---

#### Риск #2: Глобальный флаг может не сработать

**Проблема:**
- Если View пересоздается в разных потоках, глобальный флаг может не помочь
- NSLock может вызвать deadlock в определенных ситуациях

**Вероятность:** 🟡 30%

**Митигация:**
- Использовать actor вместо NSLock для thread-safety
- Добавить timeout для предотвращения deadlock

---

#### Риск #3: .task {} может вызываться из разных контекстов

**Проблема:**
- Если View пересоздается из разных мест, .task {} может вызываться многократно
- Глобальный флаг может не защитить от этого

**Вероятность:** 🟡 35%

**Митигация:**
- Использовать UUID для отслеживания каждого вызова
- Добавить проверку, что View не пересоздается

---

#### Риск #4: Форматирование на main thread может вызвать блокировку

**Проблема:**
- Если форматирование занимает много времени, это может заблокировать UI
- На реальных устройствах это может вызвать проблемы

**Вероятность:** 🟢 20%

**Митигация:**
- Форматирование должно быть быстрым (статический форматтер)
- Добавить timeout для форматирования

---

#### Риск #5: Другие места с похожими проблемами

**Проблема:**
- Могут быть другие View с похожими проблемами
- Могут быть другие форматтеры без статического Calendar

**Вероятность:** 🔴 60%

**Митигация:**

### Альтернативные решения:

#### Альтернатива #1: Использовать actor вместо NSLock

**Преимущества:**
- Более современный подход (Swift Concurrency)
- Автоматическая thread-safety
- Нет риска deadlock

**Недостатки:**
- Требует больше изменений в коде
- Может быть избыточным для простой задачи

**Рекомендация:** Использовать как альтернативу, если NSLock не сработает

---

#### Альтернатива #2: Использовать debounce для updateExpirationTextCache

**Преимущества:**

- Простое решение
- Не требует глобального флага

**Недостатки:**
- Может задержать обновление UI
- Не решает корневую проблему

**Рекомендация:** Использовать как дополнительную защиту
