**Дата:** 2026-02-06  
**Вопрос:** Нужны ли Mock для продакшена? Есть ли альтернативы?

---

## ⚠️ ВАЖНОЕ УТОЧНЕНИЕ: MOCK В ТЕСТАХ ≠ MOCK В ПРОДАКШЕНЕ

### **❌ НЕПРАВИЛЬНОЕ ПОНИМАНИЕ:**

```
Mock в тестах = Mock данные в продакшене ❌
```

### **✅ ПРАВИЛЬНОЕ ПОНИМАНИЕ:**

```
Mock в тестах = ТОЛЬКО для тестов, НЕ попадает в продакшен ✅
```

---

## 🔍 КАК ЭТО РАБОТАЕТ

### **1. В ПРОДАКШЕНЕ (Release Build):**

```swift
// Core/Config/AppConfig.swift
static let useMockAPI: Bool = false  // ✅ ВСЕГДА false в продакшене

// Core/Network/APIService.swift
static var shared: APIService {
    #if DEBUG
    if AppConfig.useMockAPI {
        return MockAPIService.mockShared  // ← НЕ выполнится в Release
    }
    #endif
    
    // ✅ В Release ВСЕГДА выполняется это:
    return APIService(networkManager: sharedNetworkManager)  // ← Реальный API
}
```

**Результат:**
- ✅ В продакшене **ВСЕГДА** используется реальный API
- ✅ MockAPIService **НЕ попадает** в продакшен билд
- ✅ `#if DEBUG` гарантирует, что Mock код удаляется при компиляции Release

## 🎯 АЛЬТЕРНАТИВНЫЕ ВАРИАНТЫ ТЕСТИРОВАНИЯ ДЛЯ ПРОДАКШЕНА

### **✅ ВАРИАНТ 1: INTEGRATION ТЕСТЫ С РЕАЛЬНЫМ API (РЕКОМЕНДУЕТСЯ)**

**Что это:**
- Тесты с реальным сервером
- Проверка полного цикла: iOS → API → SFM → Ответ

**Преимущества:**
- ✅ Тестирует реальную интеграцию
- ✅ Находит проблемы интеграции
- ✅ Проверяет работу с реальным сервером

**Недостатки:**
- ⚠️ Нужен работающий сервер
- ⚠️ Медленнее unit тестов
- ⚠️ Зависит от доступности сервера

**У вас уже есть:**
- ✅ `Tests/Integration/ComponentAPITests.swift`
- ✅ `Tests/Integration/ComponentAPIIntegrationTests.swift`

**Пример:**
```swift
// Tests/Integration/PaymentQRIntegrationTests.swift
class PaymentQRIntegrationTests: XCTestCase {
    func testCreateQRPayment_WithRealAPI() {
        // ✅ Используем РЕАЛЬНЫЙ API
        let apiService = APIService.shared  // Реальный, не Mock!
        let viewModel = PaymentQRViewModel(apiService: apiService)
        
        let expectation = expectation(description: "Payment created")
        
        viewModel.createQRPayment { result in
            switch result {
            case .success:
                expectation.fulfill()
            case .failure(let error):
                XCTFail("Payment creation failed: \(error)")
            }
        }
        
        wait(for: [expectation], timeout: 10.0)
    }
}
```

### **✅ ВАРИАНТ 2: E2E (END-TO-END) ТЕСТЫ**

**Что это:**
- Полные пользовательские сценарии
- От нажатия кнопки до получения результата

**Преимущества:**
- ✅ Тестирует полный пользовательский опыт
- ✅ Находит проблемы в реальных сценариях
- ✅ Проверяет интеграцию всех компонентов

**Недостатки:**
- ⚠️ Медленные (минуты)
- ⚠️ Хрупкие (могут падать при изменениях UI)
- ⚠️ Сложные в поддержке

**Пример:**
```swift
// Tests/E2E/PaymentFlowE2ETests.swift
class PaymentFlowE2ETests: XCTestCase {
    func testCompletePaymentFlow() {
        let app = XCUIApplication()
        app.launch()
        
        // 1. Войти в приложение
        app.buttons["Войти"].tap()
        
        // 2. Выбрать тариф
        app.buttons["Family Plan"].tap()
        
        // 3. Нажать "Оплатить"
        app.buttons["Оплатить"].tap()
        
        // 4. Проверить, что QR-код появился
        XCTAssertTrue(app.images["QR Code"].exists)
        
        // 5. Проверить статус платежа
        waitForElement(app.staticTexts["Ожидание оплаты"], timeout: 5.0)
    }
}
```
