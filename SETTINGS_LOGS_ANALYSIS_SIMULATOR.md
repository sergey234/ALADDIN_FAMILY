## 🎯 ВОЗМОЖНЫЕ ПРИЧИНЫ КРАША НА РЕАЛЬНОМ УСТРОЙСТВЕ

### **ПРИЧИНА #1: Проблемы с производительностью (ВЫСОКАЯ ВЕРОЯТНОСТЬ - 60%)**

**Описание:**
- Body вычисляется **5 раз** подряд
- Каждый раз рендерится **все 5 секций**
- Это может вызвать проблемы с памятью на реальном устройстве

**Признаки:**
- На симуляторе работает (больше ресурсов)
- На реальном устройстве крашится (меньше ресурсов)

**Решение:**
- Оптимизировать перерисовки
- Использовать `@State` для кэширования значений
- Использовать `LazyVStack` вместо `VStack`

---

### **ПРИЧИНА #2: Проблемы с доступом к менеджерам в RELEASE (СРЕДНЯЯ ВЕРОЯТНОСТЬ - 40%)**

**Описание:**
- На симуляторе менеджеры доступны сразу
- В RELEASE сборке может быть задержка инициализации
- Частые вызовы `safeCurrentTariff` и `safeLanguageCode` могут обращаться к неготовым менеджерам

**Признаки:**
- На симуляторе все работает
- На реальном устройстве крашится при доступе к менеджерам

**Решение:**
- Добавить проверки готовности менеджеров
- Кэшировать значения вместо частых вызовов computed properties

---

### **ПРИЧИНА #3: Проблемы с `systemComponentsSection()` (НИЗКАЯ ВЕРОЯТНОСТЬ - 20%)**

**Описание:**
- Если пользователь админ на реальном устройстве, секция рендерится
- Секция делает API вызовы, которые могут крашиться
- В логах нет упоминаний об этой секции (пользователь не админ на симуляторе)

**Признаки:**
- На симуляторе секция не рендерится (пользователь не админ)
- На реальном устройстве секция рендерится (пользователь админ) и крашится

**Решение:**
- Добавить защиту для API вызовов в `systemComponentsSection()`
- Добавить проверки готовности API

---

### **ПРИЧИНА #4: Проблемы с памятью (СРЕДНЯЯ ВЕРОЯТНОСТЬ - 35%)**

**Описание:**
- Множественные перерисовки создают много объектов в памяти
- На реальном устройстве меньше памяти, чем на симуляторе
- Может произойти краш из-за нехватки памяти

**Признаки:**
- На симуляторе работает (больше памяти)
- На реальном устройстве крашится (меньше памяти)

**Решение:**
- Оптимизировать использование памяти
- Использовать `@State` для кэширования
- Освобождать ресурсы в `onDisappear`
