## 🔍 АНАЛИЗ ЛОГИКИ ВЫБОРА ПОЛЬЗОВАТЕЛЯ

### **1. Как выбирается пользователь**

**Файл:** `Shared/Components/Modals/DrivingReportsModal.swift`

**Механизм:**
```swift
@AppStorage("driving_reports_selected_user_id") private var selectedUserId: String = ""
```

**Логика:**
1. ✅ При первом открытии: `selectedUserId` пустой (`""`)
2. ✅ Загружаются пользователи через `loadUsers()`:
   - API: `APIService.shared.getFamilyMembers()`
   - Fallback: `UserDefaults` (ключ `"family_members_list"`)
   - Если пусто: используется `"current"`
3. ✅ Устанавливается `currentUserId`:
   - Первый родитель (`role == "parent"`)
   - Или первый член семьи
   - Или `"current"` если список пуст
4. ✅ При выборе пользователя:
   - Сохраняется в `@AppStorage("driving_reports_selected_user_id")`
   - Вызывается `loadReports()` для загрузки данных

**Проблема 1:** ❌ При первом запуске `selectedUserId` пустой, но `currentUserId` может быть установлен. Нет синхронизации между ними.

**Код (строки 61-66):**
```swift
UserSelectorView(
    selectedUserId: Binding(
        get: { selectedUserId.isEmpty ? nil : selectedUserId },
        set: { newValue in
            selectedUserId = newValue ?? currentUserId  // ✅ Сохраняется правильно
            loadReports()
        }
    ),
    ...
)
```

**Вывод:** ✅ Логика выбора пользователя работает правильно.

## ❌ ПРОБЛЕМА: ОШИБКА АВТОРИЗАЦИИ

### **Ошибка:**
```
"Не удалось загрузить отчет о вождении Не авторизирован Токен авторизации отсутствует"
```

### **Причина:**

**1. NetworkManager проверяет токен:**
```swift
// Core/Network/NetworkManager.swift (строки 243-249)
if requiresAuth {
    guard let token = AppConfig.authToken else {
        completion(.failure(NetworkError.unauthorized("Токен авторизации отсутствует")))
        return
    }
    request.setValue("Bearer \(token)", forHTTPHeaderField: "Authorization")
}
```

**2. APIService НЕ передает requiresAuth:**
```swift
// Core/Network/APIService.swift (строки 1841-1854)
func getDrivingReports(userId: String?, period: String, completion: @escaping (Result<[DrivingReport], Error>) -> Void) {
    // ...
    networkManager.get(endpoint: endpoint, completion: completion)
    // ❌ ПРОБЛЕМА: Не передается requiresAuth, используется значение по умолчанию true
}
```

**3. Ошибка обрабатывается в ViewModel:**
```swift
// ViewModels/DrivingReportsViewModel.swift (строки 62-77)
let networkError = NetworkError.from(error)

if case .notFound = networkError {
    // Не показываем ошибку для 404
    errorMessage = nil
    return
}

if networkError.isCritical || !networkError.isRetryable {
    let errorKey = "driving_reports_error_load_failed"
    let errorFormat = localizationManager.localized(errorKey)
    errorMessage = String(format: errorFormat, networkError.localizedDescription)
    // ❌ ПРОБЛЕМА: Ошибка unauthorized считается критической и показывается пользователю
}
```

**4. Ошибка отображается в UI:**
```swift
// Shared/Components/Modals/DrivingReportsModal.swift (строки 131-136)
.overlay(alignment: .bottom) {
    if let error = viewModel.errorMessage {
        errorBanner(message: error)  // ❌ Красный баннер внизу экрана
            .padding(.bottom, Spacing.l)
    }
}
```

## 🔍 АНАЛИЗ ЛОГИКИ РАБОТЫ СТРАНИЦЫ

### **1. Загрузка пользователей (`loadUsers()`)**

**Логика:**
1. ✅ Загружает список членов семьи через API
2. ✅ Преобразует в `UserOption` для `UserSelectorView`
3. ✅ Устанавливает `currentUserId` (первый родитель или первый член)
4. ✅ Fallback на UserDefaults если API недоступен
5. ✅ Fallback на `"current"` если список пуст

**Проблема 3:** ❌ Если API возвращает ошибку авторизации, пользователи не загружаются, но ошибка не обрабатывается явно.

### **2. Загрузка отчетов (`loadReports()`)**

**Логика:**
1. ✅ Загружает статистику (`getDrivingStats`) и отчеты (`getDrivingReports`) параллельно
2. ✅ Обновляет `stats` и `reports` при успехе
3. ✅ Обрабатывает ошибки:
   - 404 (notFound) - не показывает ошибку (нормально, если нет данных)
   - Критические ошибки - показывает ошибку
   - Временные ошибки - не показывает ошибку

**Проблема 4:** ❌ Ошибка `unauthorized` считается критической и показывается пользователю, хотя это проблема авторизации, а не данных.

## ❌ ОБНАРУЖЕННЫЕ ПРОБЛЕМЫ

### **ПРОБЛЕМА 1: Ошибка авторизации показывается как критическая**

**Где:** `ViewModels/DrivingReportsViewModel.swift` (строки 74-77)

**Проблема:**
- Ошибка `unauthorized` считается критической (`isCritical == true`)
- Показывается красный баннер внизу экрана
- Но это проблема авторизации, а не данных

**Решение:**
- Обработать `unauthorized` отдельно
- Показать понятное сообщение или перенаправить на авторизацию

---

### **ПРОБЛЕМА 2: Нет проверки токена перед загрузкой**

**Где:** `Shared/Components/Modals/DrivingReportsModal.swift` (строки 117-121)

**Проблема:**
- Загружаются пользователи и отчеты без проверки токена
- Если токена нет, обе операции завершаются ошибкой

**Решение:**
- Проверить токен перед загрузкой
- Показать сообщение или перенаправить на авторизацию

---

### **ПРОБЛЕМА 3: Неправильная инициализация selectedUserId**

**Где:** `Shared/Components/Modals/DrivingReportsModal.swift` (строки 24, 119)

**Проблема:**
- При первом запуске `selectedUserId` пустой (`""`)
- `currentUserId` устанавливается в `loadUsers()`, но `selectedUserId` не синхронизируется
- Используется `nil` вместо `currentUserId` при загрузке отчетов

**Решение:**
- После загрузки пользователей установить `selectedUserId = currentUserId` если он пустой

---

### **ПРОБЛЕМА 4: Ошибка авторизации при загрузке пользователей не обрабатывается**

**Где:** `Shared/Components/Modals/DrivingReportsModal.swift` (строки 487-500)

**Проблема:**
- Если API возвращает ошибку авторизации, используется fallback на UserDefaults
- Но ошибка не логируется явно
- Пользователь не знает, что данные могут быть устаревшими

**Решение:**
- Обработать ошибку авторизации отдельно
- Показать предупреждение или использовать только кэшированные данные
