## 🎯 ИСТИННАЯ ПРИЧИНА КРАША

### 🔴 ГИПОТЕЗА #1: `displayFormatter.string(from:)` вызывается в `body` View

**Вероятность:** 🔴 **95%**

**Проблема:**
- В `MainScreen` есть статический `displayFormatter`
- Он используется в `updateExpirationTextCache()` через `Self.displayFormatter.string(from: date)`
- Но если `displayFormatter.string(from:)` вызывается где-то еще в `body` View напрямую
- И это вызывает обновление View
- Это может вызвать рекурсию

**Где искать:**
- Все места в `MainScreen.body`, где используется форматирование даты
- Все computed properties в `MainScreen`, которые используют форматтеры
- Все места, где `cachedExpirationText` используется в `body`

---

### 🔴 ГИПОТЕЗА #2: `displayFormatter` используется в computed property

**Вероятность:** 🔴 **90%**

**Проблема:**
- Если есть computed property, которая использует `displayFormatter`
- И эта computed property вызывается из `body` View
- И обновление View вызывает computed property снова
- Это может вызвать рекурсию

**Где искать:**
- Все computed properties в `MainScreen`
- Все computed properties, которые используют форматтеры
- Все computed properties, которые вызываются из `body`

---

### 🔴 ГИПОТЕЗА #3: Рекурсия через обновление `cachedExpirationText`

**Вероятность:** 🟡 **80%**

**Проблема:**
- `updateExpirationTextCache()` обновляет `cachedExpirationText` через `MainActor.run`
- Если `cachedExpirationText` используется в `body` View
- И обновление `@State` вызывает перерисовку View
- И перерисовка View вызывает `.task {}` снова (если есть проблема с `.task {}`)
- Это может вызвать рекурсию

**Где искать:**
- Все места, где `cachedExpirationText` используется в `body`
- Все места, где `updateExpirationTextCache()` вызывается
- Проверить, не вызывается ли `.task {}` многократно
