## 📊 ИСТОРИЯ ИЗМЕНЕНИЙ

### 🔴 BUILD 91: Первое исправление рекурсии

**Проблема:**
- Была computed property `subscriptionExpirationText`, которая читала из `@AppStorage`
- Это вызывало рекурсию через `UserDefaults`

**Решение:**
- Заменили computed property на `@State private var cachedExpirationText`
- Добавили функцию `updateExpirationTextCache()` для обновления кеша
- Вызывали функцию в `.onAppear {}`

**Проблема этого решения:**
- `.onAppear {}` вызывается при каждом обновлении View
- Обновление `@State` вызывает перерисовку View
- Это может вызвать рекурсию, если View обновляется часто

---

### 🔴 BUILD 92: Попытка исправить рекурсию

**Проблема:**
- Рекурсия продолжалась из-за `.onChange()` и `.id()` модификаторов
- Эти модификаторы вызывали обновление View при изменении `@AppStorage`

**Решение:**
- Убрали `.onChange(of: subscriptionExpiresAtIso)`
- Убрали `.id()` модификаторы
- Оставили вызов `updateExpirationTextCache()` в `.onAppear {}`

**Проблема этого решения:**
- `.onAppear {}` все еще вызывается при каждом обновлении View
- Если View обновляется по другой причине, это может вызвать рекурсию

- Это увеличило вероятность рекурсии

**Вывод:**
- Проблема усугубилась из-за изменений в поведении SwiftUI
- Нужно использовать более безопасные подходы
