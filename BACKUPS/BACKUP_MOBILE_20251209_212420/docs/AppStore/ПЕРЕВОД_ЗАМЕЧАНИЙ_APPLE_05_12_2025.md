## 💥 ПРОБЛЕМА 4: Guideline 2.1 - Производительность (КРАШ)

**Описание проблемы:**
Приложение крашится (вылетает) во время ревью. Приложения, которые крашатся, негативно влияют на пользователей.

**Шаги, приводящие к крашу:**
- Нажатие на кнопку "Поделиться" (share button).

**Детали устройства для ревью:**
- Тип устройства: iPad Air 11-inch (M3)
- Версия ОС: iPadOS 26.1

**Что нужно сделать:**
Протестируйте приложение на поддерживаемых устройствах, чтобы выявить краши и проблемы со стабильностью перед повторной отправкой на ревью. Логи краша прикреплены, чтобы помочь решить эту проблему:

1. **Полностью символизируйте отчёт о краше.** См. Adding Identifiable Symbol Names to a Crash Report (Добавление идентифицируемых символических имён в отчёт о краше).
2. **Сопоставьте отчёт о краше с общим шаблоном.** На основе шаблона предпримите конкретные действия для дальнейшего расследования краша. См. Identifying the Cause of Common Crashes (Определение причины общих крашей).
3. **После того, как основные причины краша будут определены, внесите соответствующие изменения в бинарный файл, чтобы решить проблему.**
4. **Протестируйте приложение на устройстве, чтобы убедиться, что оно работает как ожидается.**

**Ресурсы:**
- Для получения дополнительной информации об отчётах о крашах см. Diagnosing Issues Using Crash Reports and Device Logs (Диагностика проблем с использованием отчётов о крашах и логов устройств).
- Для получения информации о тестировании приложений и подготовке их к ревью см. Testing a Release Build (Тестирование релизной сборки).

## 📍 ПРОБЛЕМА 5: Guideline 2.5.4 - Производительность - Требования к программному обеспечению (Location)

**Описание проблемы:**
Приложение объявляет поддержку location (местоположения) в ключе UIBackgroundModes в вашем файле Info.plist, но мы не можем найти никаких функций, которые требуют постоянного местоположения. Приложения, которые объявляют поддержку location в ключе UIBackgroundModes в вашем файле Info.plist, должны иметь функции, которые требуют постоянного местоположения.

**Что нужно сделать:**
Если в приложении есть функция, которая требует постоянного местоположения, ответьте на это сообщение и сообщите нам, как найти эту функцию.

Если приложению не требуются постоянные обновления местоположения в реальном времени, пожалуйста, удалите настройку "location" из ключа UIBackgroundModes. Вы можете использовать службу значительных изменений местоположения (significant-change location service) или службу мониторинга географических регионов (region monitoring location service), если постоянные обновления местоположения в реальном времени не требуются для функций приложения.

**Ресурсы:**
- Узнайте больше о требованиях к программному обеспечению в guideline 2.5.4.
- Ознакомьтесь с документацией по Starting the Significant-Change Location Service (Запуск службы значительных изменений местоположения) и Monitoring Geographical Regions (Мониторинг географических регионов).

## 🏥 ПРОБЛЕМА 7: Guideline 2.5.1 - Производительность - Требования к программному обеспечению (HealthKit)

**Описание проблемы:**
Бинарный файл вашего приложения включает ссылки на компоненты HealthKit, но приложение, похоже, не включает никаких основных функций, которые требуют данных о здоровье или фитнесе.

Предназначение HealthKit обычно заключается в обмене данными о здоровье или фитнесе с другими приложениями или устройствами как часть основной функциональности приложения.

**Что нужно сделать:**
Чтобы решить эту проблему, пожалуйста, удалите любую функциональность HealthKit из приложения, а также любые ссылки на взаимодействие этого приложения с HealthKit из приложения или его метаданных. Это включает удаление любых ключей, связанных с HealthKit, в файлах Info.plist или InfoPlist.strings вашего приложения, а также удаление любых вызовов API HealthKit, включая вызовы из сторонних платформ, из приложения.

**Ресурсы:**
Узнайте больше о фреймворке HealthKit.
