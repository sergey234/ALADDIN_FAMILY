# 🔍 АНАЛИЗ: УСТАРЕВШАЯ СИСТЕМА СБОРКИ (Legacy Build System)

## 📖 ЧТО ЭТО ТАКОЕ?

**Устаревшая система сборки (Legacy Build System)** - это старая система сборки Xcode, которая использовалась до Xcode 10.

**Современная система сборки (New Build System)** - новая система, введенная в Xcode 10 и ставшая по умолчанию.

## 🔧 КАК ИСПОЛЬЗОВАТЬ?

Добавить флаг в команду `xcodebuild`:
```bash
xcodebuild archive \
  -project ALADDIN.xcodeproj \
  -scheme ALADDIN \
  -UseModernBuildSystem=0 \  # ← Устаревшая система
  ...
```

## ✅ ПЛЮСЫ УСТАРЕВШЕЙ СИСТЕМЫ:

1. **Может обходить баги современной системы**
   - Иногда более стабильна для старых проектов
   - Может лучше работать с некоторыми конфигурациями

2. **Может помочь в CI/CD**
   - Некоторые проблемы с подписью решаются проще
   - Может лучше обрабатывать provisioning profiles

3. **Проверенная временем**
   - Используется годами, меньше неожиданных проблем

## ❌ МИНУСЫ УСТАРЕВШЕЙ СИСТЕМЫ:

1. **Устарела**
   - Apple не рекомендует использовать
   - Может быть удалена в будущих версиях Xcode

2. **Может быть медленнее**
   - Не оптимизирована для современных проектов
   - Может дольше собирать большие проекты

3. **Не поддерживает новые функции**
   - Некоторые новые возможности Xcode могут не работать
   - Может не поддерживать последние улучшения

4. **Не решает нашу проблему**
   - Наша проблема не в системе сборки
   - Проблема в том, что Xcode не видит provisioning profiles из-за Automatic signing

## 🎯 НАША ПРОБЛЕМА:

**Реальная проблема:** Xcode не может найти provisioning profiles, потому что:
1. Проект настроен на `CODE_SIGN_STYLE = Automatic` в `project.pbxproj`
2. Xcode игнорирует параметры Manual signing из командной строки
3. xcconfig файл не всегда переопределяет настройки проекта полностью

## 📋 ПЛАН ДЕЙСТВИЙ:

### ВАРИАНТ 1: Использовать устаревшую систему сборки (БЫСТРОЕ РЕШЕНИЕ)

**Плюсы:**
- ✅ Быстро попробовать
- ✅ Может помочь обойти проблему
- ✅ Не требует изменения проекта

**Минусы:**
- ❌ Временное решение
- ❌ Не решает корневую проблему
- ❌ Устаревшая технология

**Действия:**
1. Добавить флаг `-UseModernBuildSystem=0` в команду `xcodebuild`
2. Проверить, помогает ли это
3. Если помогает - использовать как временное решение

### ВАРИАНТ 2: Изменить настройки проекта (ПРАВИЛЬНОЕ РЕШЕНИЕ)

**Плюсы:**
- ✅ Решает корневую проблему
- ✅ Использует современную систему сборки
- ✅ Долгосрочное решение

**Минусы:**
- ❌ Требует изменения `project.pbxproj`
- ❌ Может повлиять на локальную сборку
- ❌ Нужно синхронизировать изменения

**Действия:**
1. Изменить `CODE_SIGN_STYLE = Automatic` на `CODE_SIGN_STYLE = Manual` в `project.pbxproj`
2. Установить `PROVISIONING_PROFILE_SPECIFIER` для каждого таргета
3. Сохранить изменения
4. Проверить, что локальная сборка все еще работает

### ВАРИАНТ 3: Комбинированный подход (РЕКОМЕНДУЕТСЯ)

**Плюсы:**
- ✅ Использует современную систему сборки
- ✅ Не требует изменения проекта
- ✅ Использует xcconfig для переопределения

**Минусы:**
- ❌ Может не работать, если Xcode упорно игнорирует параметры

**Действия:**
1. Улучшить xcconfig файл
2. Добавить больше параметров в командную строку
3. Попробовать установить профили через `security` команду
4. Если не поможет - перейти к ВАРИАНТУ 2

## 💡 РЕКОМЕНДАЦИЯ:

**Для начала:** Попробовать ВАРИАНТ 1 (устаревшая система сборки) как быстрый тест.

**Если не поможет:** Перейти к ВАРИАНТУ 2 (изменить настройки проекта) - это правильное решение.

**Если не хотите менять проект:** Попробовать ВАРИАНТ 3 (комбинированный подход) с улучшенным xcconfig.

## 🔍 ВЫВОД:

Устаревшая система сборки - это **временное решение**, которое может помочь обойти проблему, но **не решает корневую причину**. 

**Корневая причина:** Проект настроен на Automatic signing, и Xcode игнорирует параметры Manual signing.

**Правильное решение:** Изменить настройки проекта на Manual signing или найти способ заставить Xcode использовать параметры из командной строки/xcconfig.
