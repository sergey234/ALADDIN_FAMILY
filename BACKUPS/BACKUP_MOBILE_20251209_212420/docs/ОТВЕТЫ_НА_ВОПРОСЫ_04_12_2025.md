## 1. 🔍 RAM И ПОСЕТИТЕЛИ

### **Вопрос:** Когда будет увеличиваться количество посетителей - RAM будет увеличиваться?

### **Ответ:**

**НЕТ, RAM не будет увеличиваться пропорционально посетителям!**

**Почему:**
- RAM используется для **процессов на сервере**, а не для каждого посетителя
- Каждый посетитель делает HTTP-запрос → сервер обрабатывает → ответ → соединение закрывается
- RAM используется только для **работающих процессов** (payment_service, nginx, api_gateway)

**Что влияет на RAM:**
1. **Количество worker-процессов** (сейчас api_gateway использует 12 workers = ~1.6GB)
2. **Количество одновременных запросов** (но это временно, после обработки память освобождается)
3. **Размер кэша** (если используется Redis или in-memory кэш)
4. **Размер базы данных в памяти** (если БД загружена в RAM)

**При увеличении нагрузки:**
- Если запросов станет очень много → можно увеличить количество workers
- Но обычно достаточно 4-6 workers для среднего трафика
- RAM будет использоваться более эффективно, но не расти линейно

**Рекомендация:**
- Сейчас RAM используется на 65% - это нормально
- Если нагрузка вырастет, можно оптимизировать api_gateway (уменьшить workers с 12 до 4-6)
- Это освободит ~800MB RAM для других процессов

## 2. 📊 `/api/admin/users/list` - ЧТО ЭТО?

### **Вопрос:** Что значит `/api/admin/users/list` - детальный список пользователей?

### **Ответ:**

Это **backend endpoint**, который возвращает **детальную информацию о всех пользователях**.

**Что возвращает:**
```json
{
  "users": [
    {
      "alias": "user123",
      "total_payments": 3,
      "paid_payments": 2,
      "last_payment_date": "2025-12-04T10:30:00Z",
      "latest_expires_at": "2026-12-04T10:30:00Z",
      "is_active": true
    },
    ...
  ],
  "total": 100,
  "limit": 100,
  "offset": 0
}
```

**Параметры:**
- `limit` - количество записей на странице (по умолчанию 100)
- `offset` - смещение для пагинации (по умолчанию 0)
- `search` - поиск по alias пользователя

**Использование:**
- В админке на странице "Пользователи" будет отображаться полный список
- Можно искать пользователей по ID (alias)
- Можно видеть все подписки каждого пользователя

**✅ СОЗДАН!** Endpoint готов и работает.

## 4. 📋 `/api/admin/logs` - ЦЕНТРАЛИЗОВАННОЕ ЛОГИРОВАНИЕ

### **Вопрос:** Делаем `/api/admin/logs` - централизованное логирование?

### **Ответ:**

**✅ ДА, СОЗДАН!**

**Что возвращает:**
```json
{
  "service": "payment_service",
  "logs": [
    "2025-12-04 01:30:00 INFO: Payment created",
    "2025-12-04 01:29:00 WARNING: Slow query",
    ...
  ],
  "total": 100,
  "note": "Логи получены с сервера"
}
```

**Параметры:**
- `service` - название сервиса (payment_service, nginx, system)
- `limit` - количество строк логов (по умолчанию 100)
- `level` - фильтр по уровню (info, warning, error, debug)

**Как работает:**
- Пытается получить логи через `journalctl` или `tail`
- Если не получается (не на сервере) - возвращает инструкцию
- В будущем можно подключить к централизованному логированию (ELK, Loki, etc.)

**Использование:**
- В админке на странице "Логи" можно выбрать сервис
- Автообновление логов каждые 5 секунд
- Фильтрация по уровню

## 5. 🎁 БЕСПЛАТНЫЕ ПОДПИСКИ ДЛЯ ДРУЗЕЙ

### **Вопрос:** Я смогу в админке моим друзьям по ID делать бесплатные подписки на год или навсегда? Как это у нас работает и как это можно реализовать?

### **Ответ:**

**✅ ДА, РЕАЛИЗОВАНО!**

### **Как это работает:**

1. **Создание бесплатной подписки:**
   - Админ входит в админку
   - Переходит на страницу "Пользователи"
   - Находит пользователя по ID (alias) или создает нового
   - Нажимает "Создать бесплатную подписку"
   - Выбирает срок: **год** или **навсегда**
   - Система создает Payment со статусом "paid" и ActivationCode

2. **Endpoint для создания:**
   ```
   POST /api/admin/subscriptions/create-free
   Параметры:
   - alias: ID пользователя (например, "friend123")
   - tariff_id: "yearly" или "lifetime"
   - duration_years: количество лет (опционально, по умолчанию 1 год)
   ```

3. **Что происходит:**
   - Создается Payment с `amount=0` и `status="paid"`
   - Создается ActivationCode с кодом типа `ALDN-XXXX-XXXX`
   - Для "yearly" - срок действия 1 год (или указанное количество лет)
   - Для "lifetime" - срок действия до 2100 года (фактически навсегда)

4. **Пользователь получает:**
   - Код активации (можно скопировать и отправить другу)
   - Код работает как обычный код активации
   - Пользователь вводит код в приложении → подписка активируется

### **Как использовать в админке:**

**Вариант 1: Через API напрямую**
```bash
curl -X POST "https://aladdin-ai.ru/api/admin/subscriptions/create-free" \
  -H "X-Admin-Key: YOUR_ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "alias": "friend123",
    "tariff_id": "lifetime"
  }'
```

**Вариант 2: Добавить кнопку в админку (можно сделать позже)**
- На странице "Пользователи" добавить кнопку "Создать бесплатную подписку"
- Форма с выбором срока (год/навсегда)
- После создания показать код активации

### **Проверка подписок пользователя:**

**Endpoint:**
```
GET /api/admin/subscriptions/user/{alias}
```

**Возвращает:**
```json
{
  "alias": "friend123",
  "subscriptions": [
    {
      "payment_id": "...",
      "tariff_id": "lifetime",
      "amount": 0,
      "status": "paid",
      "activation_code": "ALDN-XXXX-XXXX",
      "expires_at": "2100-12-31T23:59:59Z",
      "is_active": true
    }
  ],
  "total": 1,
  "active_count": 1
}
```

### **Безопасность:**

- ✅ Требуется админ-ключ
- ✅ Только авторизованные администраторы могут создавать бесплатные подписки
- ✅ Все действия логируются
