# 📋 ПОЧЕМУ appstore.yml запускается только при тегах v*?

**Дата:** 30 ноября 2025  
**Вопрос:** Почему appstore.yml не запускается при push в master, а только при тегах?

---

## 🎯 ПРИЧИНЫ

### 1. ✅ КОНТРОЛЬ ЗАПУСКА

**Теги v* = релиз версии**

- Тег создается только когда готов релиз
- Не запускается случайно при каждом push
- Только когда действительно нужно загрузить в App Store

**Пример:**
```bash
# Обычный коммит - НЕ запускает appstore.yml
git commit -m "Fix bug"
git push origin master

# Создание тега - ЗАПУСКАЕТ appstore.yml
git tag -a "v1.0.0" -m "Release"
git push origin --tags
```

---

### 2. ✅ ЭКОНОМИЯ РЕСУРСОВ

**Сборка для App Store:**
- Долгая (15-30 минут)
- Использует много ресурсов GitHub Actions
- Стоит денег (если есть лимиты)

**Если бы запускался при каждом push:**
- Каждый коммит = 30 минут сборки
- Много потраченных ресурсов
- Долгое ожидание

**С тегами:**
- Только когда нужен релиз
- Экономия ресурсов
- Быстрее для разработки

---

### 3. ✅ ИЗБЕЖАНИЕ КОНФЛИКТОВ

**Проблема вчера:**
- `build-only.yml` запускался при push в master
- Конфликтовал с другими workflows
- Пустая трата времени

**С тегами:**
- `appstore.yml` запускается только при тегах
- Не конфликтует с другими workflows
- Четкое разделение ответственности

---

### 4. ✅ БЕЗОПАСНОСТЬ

**Защита от случайной загрузки:**

- Нельзя случайно загрузить в App Store
- Только осознанно через тег
- Защита от ошибок разработчиков

**Пример проблемы:**
```
Если бы запускался при каждом push:
- Разработчик делает push с багом
- Автоматически загружается в App Store
- Пользователи получают багованную версию ❌
```

**С тегами:**
- Тег создается только после проверки
- Осознанное решение о релизе
- Безопасность ✅

## ⚠️ ПОЧЕМУ НЕ ПРИ PUSH В MASTER?

### Проблемы если бы запускался при push:

1. **Каждый коммит = сборка**
   - Разработчик делает 10 коммитов в день
   - 10 сборок по 30 минут = 5 часов
   - Пустая трата времени и ресурсов

2. **Конфликты с другими workflows**
   - `build-only.yml` тоже запускается при push
   - Два workflow одновременно = конфликт
   - Проблемы с ресурсами

3. **Риск случайной загрузки**
   - Разработчик делает push с багом
   - Автоматически загружается в App Store
   - Пользователи получают багованную версию

4. **Нет контроля версий**
   - Непонятно какая версия загружена
   - Нет истории релизов
   - Сложно отследить
