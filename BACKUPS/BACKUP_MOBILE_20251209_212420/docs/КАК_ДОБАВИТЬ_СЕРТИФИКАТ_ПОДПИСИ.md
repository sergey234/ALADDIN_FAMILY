# 🔐 КАК ДОБАВИТЬ СЕРТИФИКАТ ПОДПИСИ В GITHUB ACTIONS

## 🚨 ПРОБЛЕМА

Ошибка при сборке:
```
No signing certificate "iOS Distribution" found
```

## ✅ РЕШЕНИЕ

Нужно экспортировать сертификат из Keychain и добавить в GitHub Secrets.

---

## 📋 ПОШАГОВАЯ ИНСТРУКЦИЯ

### ШАГ 1: Найти сертификат в Keychain

1. Откройте **Keychain Access** (⌘+Space → "Keychain Access")
2. В левом меню выберите **"login"** → **"My Certificates"**
3. Найдите сертификат **"iPhone Distribution"** или **"Apple Distribution"**
   - Обычно называется: `Apple Distribution: SERGEY KHLYSTOV (6CJVBBUGSN)`
   - Или: `iPhone Distribution: SERGEY KHLYSTOV (6CJVBBUGSN)`

### ШАГ 2: Экспортировать сертификат

1. **Правый клик** на сертификат → **"Export..."**
2. Выберите формат: **"Personal Information Exchange (.p12)"**
3. Сохраните как: `distribution_certificate.p12`
4. **Введите пароль** для защиты .p12 файла (запомните его!)

### ШАГ 3: Кодировать в base64

Откройте Terminal и выполните:

```bash
cd ~/Desktop
base64 -i distribution_certificate.p12 | tr -d '\n' > distribution_certificate_base64.txt
```

### ШАГ 4: Добавить в GitHub Secrets

1. Откройте: https://github.com/sergey234/ALADDIN_FAMILY/settings/secrets/actions
2. Нажмите **"New repository secret"**
3. Добавьте два секрета:

   **Секрет 1:**
   - Name: `IOS_DISTRIBUTION_CERTIFICATE`
   - Value: содержимое файла `distribution_certificate_base64.txt` (скопируйте весь текст)

   **Секрет 2:**
   - Name: `IOS_DISTRIBUTION_CERTIFICATE_PASSWORD`
   - Value: пароль, который вы ввели при экспорте .p12

### ШАГ 5: Проверить

Запустите workflow "Build and Upload to App Store" снова.

---

## ⚠️ ВАЖНО

- **Не делитесь** паролем от .p12 файла
- **Не коммитьте** .p12 файл в Git
- **Удалите** .p12 файл после добавления в GitHub Secrets

---

## 🔍 АЛЬТЕРНАТИВА (БЕЗ СЕРТИФИКАТА)

Если у вас нет доступа к сертификату, можно использовать **автоматическую подпись**:

1. Убедитесь, что добавлены **App Store Connect API ключи**:
   - `APP_STORE_CONNECT_API_KEY`
   - `APP_STORE_CONNECT_ISSUER_ID`
   - `APP_STORE_CONNECT_API_KEY_ID`

2. Workflow автоматически переключится на автоматическую подпись с `-allowProvisioningUpdates`
