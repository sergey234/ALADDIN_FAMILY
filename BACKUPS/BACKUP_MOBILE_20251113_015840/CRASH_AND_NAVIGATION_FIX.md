# 🔧 ИСПРАВЛЕНИЕ КРАША ТАРИФОВ И НАВИГАЦИИ ПРОФИЛЯ

**Дата:** 29 октября 2025  
**Проблемы:**
1. Приложение крашится при выборе тарифа
2. Навигация из профиля работает неправильно

---

## 🚨 ПРОБЛЕМА 1: КРАШ ПРИ ВЫБОРЕ ТАРИФА

### Причина:
- Использование `do-catch` для создания простого объекта `Tariff` (не может выбросить исключение)
- `DispatchQueue.main.async` с `[self]` может вызывать проблемы
- Сложная структура кода может приводить к крашам

### ✅ Исправление:

**Убрано:**
- `do-catch` блок (не нужен для создания `Tariff`)
- `DispatchQueue.main.async { [self] in }` для QR-оплаты
- Сложная логика с fallback

**Добавлено:**
- Простое прямое присваивание для QR-оплаты
- Упрощённый `Task` для IAP
- Безопасная проверка массива tariffs

---

## 🚨 ПРОБЛЕМА 2: НАВИГАЦИЯ ИЗ ПРОФИЛЯ

### Причина:
- Использовалось `navigationManager.navigateTo(.settings)` вместо возврата назад
- Это создавало новый переход вместо возврата
- Не использовался `dismiss()` для NavigationLink

### ✅ Исправление:

**Было:**
```swift
navigationManager.navigateTo(.settings)
```

**Стало:**
```swift
// 1. Сначала пытаемся dismiss (для NavigationLink)
dismiss()

// 2. Если не сработало - используем goBack()
DispatchQueue.main.asyncAfter(deadline: .now() + 0.1) {
    if self.navigationManager.currentScreen == .profile {
        if self.navigationManager.canGoBack {
            self.navigationManager.goBack()
        } else {
            self.navigationManager.navigateTo(.main)
        }
    }
}
```

**Логика:**
1. Сначала `dismiss()` - если профиль открыт через NavigationLink
2. Если через 0.1 сек мы всё ещё на профиле - используем `goBack()`
3. Если нет истории - возвращаемся на главную
