# 🚨 ИНСТРУКЦИЯ: НАСТРОЙКА EXCEPTION BREAKPOINT

## ПРОБЛЕМА: Логи не появляются = краш ДО выполнения кода!

Если логи НЕ появляются - значит SwiftUI крашится при создании view структуры,
**ДО** того как выполняется наш код.

---

## ✅ РЕШЕНИЕ: Exception Breakpoint

### ШАГ 1: Открыть Breakpoint Navigator
1. В Xcode нажмите **⌘8** (или View → Navigators → Breakpoint Navigator)
2. В левой панели появится список breakpoints

### ШАГ 2: Создать Exception Breakpoint
1. Нажмите кнопку **"+"** внизу левой панели
2. Выберите **"Exception Breakpoint"**
3. Появится новый breakpoint в списке

### ШАГ 3: Настроить Breakpoint
1. Правый клик на Exception Breakpoint
2. Выберите **"Edit Breakpoint..."**
3. Проверьте что:
   - ✅ **Exception:** `All` (или `Objective-C`)
   - ✅ **Break:** `On Throw` и `On Catch`

### ШАГ 4: Запустить приложение
1. Запустите приложение (⌘R)
2. Откройте экран тарифов
3. Нажмите на тариф
4. **Приложение ОСТАНОВИТСЯ на точном месте краша!**

### ШАГ 5: Посмотреть где остановилось
1. В Xcode появится зеленая стрелка → это место краша
2. Сверху в Xcode будет показано:
   - Файл и номер строки
   - Стек вызовов
   - Значения переменных

### ШАГ 6: Скопировать информацию
1. Посмотрите на **строку где остановилось** (зеленая стрелка)
2. Посмотрите на **переменные** в левой панели (Variables)
3. Посмотрите на **стек вызовов** (Call Stack) в правой панели
4. Сделайте скриншот или запишите:
   - **Файл и строка где краш**
   - **Что написано в строке**
   - **Значения переменных**

---

## 📋 ЧТО ОТПРАВИТЬ МНЕ:

После остановки на Exception Breakpoint:

1. **Файл и номер строки:**
   ```
   Например: PaymentQRViewModel.swift:140
   ```

2. **Код в этой строке:**
   ```
   Например: let networkManager = NetworkManager()
   ```

3. **Сообщение об ошибке (если есть):**
   ```
   Например: Thread 1: EXC_BAD_ACCESS
   ```

4. **Значения переменных:**
   - Посмотрите в левой панели Variables
   - Какие переменные nil или имеют странные значения

---

## 🔍 АЛЬТЕРНАТИВА: Если Exception Breakpoint не помогает

### Способ A: Проверить Simulator Logs
1. Откройте **Console.app** (в macOS)
2. Найдите процесс ALADDIN
3. Поищите ошибки там

### Способ B: Использовать Device Logs
1. В Xcode: **Window → Devices and Simulators**
2. Выберите симулятор
3. Нажмите **"View Device Logs"**
4. Найдите последний crash log

### Способ C: Проверить DerivedData
Иногда логи сохраняются в:
```
~/Library/Developer/Xcode/DerivedData/ALADDIN-*/Logs/
```

---

**ВАЖНО:** Exception Breakpoint покажет ТОЧНОЕ место краша, даже если логи не работают!
