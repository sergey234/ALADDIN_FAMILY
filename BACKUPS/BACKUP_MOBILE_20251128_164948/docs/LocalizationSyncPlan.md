# План синхронизации локализации ALADDIN iOS

## Цель
Обеспечить полное соответствие русских и английских переводов в `LocalizationManager.swift`, а также внедрить процесс, предотвращающий расхождения в будущем.

## Текущая проблема
- Русский блок содержит 1960 ключей.
- Английский блок содержит 1585 ключей.
- 388 ключей есть только в русском блоке (`child_*`, `faq_*`, `profile_*`, `payment_qr_*`, `analytics_*`, `devices_*`, `onboarding_*`, `privacy_*`, `ai_*`, `edit_profile_*`).
- 13 ключей есть только в английском блоке (`analytics_activity_by_devices`, `payment_qr_error_title`, `privacy_policy_section_rights`, и т.д.).

## Этапы работ
1. **Инвентаризация ключей**
   - Сформировать списки `RU \ EN` и `EN \ RU` (уже получены скриптом сравнения).
   - Группировать отсутствующие ключи по префиксам для удобства распределения.

2. **Восстановление английских переводов**
   - Для каждой группы (`child_*`, `faq_*`, `profile_*`, `payment_qr_*`, `analytics_*`, `devices_*`, `onboarding_*`, `privacy_*`, `ai_*`, `edit_profile_*`) добавить недостающие строки в английский блок.
   - Проверять смысл и консистентность терминологии (Child Interface, FAQ, Profile, QR Payments, Analytics и т.д.).

3. **Восстановление русских переводов**
   - Добавить 13 недостающих русских ключей (данные разделы аналитики, платежей и политики конфиденциальности).

4. **Валидация**
   - Запустить `python3 scripts/check_localization_duplicates.py`.
   - Запустить скрипт сравнения ключей (Python one-liner либо отдельный файл).
   - Убедиться, что множества ключей идентичны.

5. **Документация**
   - Обновить гайд по локализации с описанием нового процесса (добавление строк в оба языка, запуск проверок, чек-лист). 
   - Описать в этом файле текущее состояние, шаги и ответственных.

6. **Автоматизация**
   - Добавить скрипт проверки равенства ключей в `scripts/` (например, `check_localization_sync.py`).
   - Включить скрипт в pre-commit/CI и описать запуск в документации.

7. **Регулярный контроль**
   - Запланировать периодическую проверку (например, еженедельно и перед релизом).
   - Вести отчёт `localization_sync_report.md` с датой проверки и результатом.

## Практика работы с `LocalizationManager.swift`

1. **Строгая структура в одном файле**
   - Сохраняем порядок блоков `.russian`, `.english`, `.chinese`, `.arabic`.
   - Каждый блок начинается комментарием с названием секции и заканчивается пустой строкой.
   - Добавление/изменение ключей делаем только внутри соответствующего блока.

2. **Единые проверки перед коммитом**
   - `python3 scripts/check_localization_duplicates.py`
   - `python3 scripts/check_localization_keysets.py` (проверяет, что множества ключей во всех языках совпадают).
   - Скрипты должны выполняться локально и в CI.

3. **Фиксация статистики ключей**
   - В конце каждого блока поддерживаем комментарий вида `// keys: russian=XXXX`, `// keys: english=YYYY`.
   - При изменении файла обновляем значения с помощью скрипта.

4. **Правила ревью**
   - Любой PR с изменениями локализации проверяется на наличие переводов в обоих языках.
   - При расхождении > 50 строк между текущей версией и эталоном — блок восстанавливаем из бэкапа и вносим правки заново.

5. **Бэкап и эталон**
   - Храним последнюю проверенную версию рядом (`LocalizationManager.swift.backup`).
   - Перед мёрджем сравниваем текущий файл с эталоном; большие расхождения устраняем до слияния.

6. **Документация для исполнителей**
   - Обновляем этот документ и `LOCALIZATION_BEST_PRACTICES.md` при появлении новых правил.
   - В чек-листах релиза добавляем пункт «локализация синхронизирована и проверки выполнены».

## Профилактика
- Любой PR с новыми строками должен содержать переводы на оба языка.
- Проверка на совпадение ключей — обязательная часть код-ревью.
- Ввести чек-лист: «Локализация обновлена и проверена».
- При необходимости использовать таблицу/JSON для переводчиков и генерировать Swift-код автоматически.
