# Инструкция по работе с `LocalizationManager.swift`

Документ для автоматизированной (ML) системы, которая будет поддерживать локализации в мобильном приложении ALADDIN iOS.

## 1. Главный файл локализации
- Основной файл: `mobile_apps/ALADDIN_iOS/Core/Localization/LocalizationManager.swift`.
- Внутри него словарь `translations` с блоками языков: `.russian`, `.english`, `.chinese`, `.arabic` (в таком порядке).
- Мы **не** делим локализации на разные файлы, поэтому все правила ниже обязательны, чтобы не ломать структуру.

## 2. Структура и правила редактирования
1. **Порядок блоков не менять**: `.russian` → `.english` → `.chinese` → `.arabic`.
2. Каждый блок начинается комментарием (`// <Section>`) и заканчивается пустой строкой.
3. Любое изменение вносится строго внутри нужного блока. Ключи не должны «переезжать» в другой язык.
4. После завершения правок сохраняем комментарии со статистикой ключей (пример: `// keys: russian=1875`).

## 3. Скрипты проверки (обязательные)
Запускать **перед каждым коммитом/мерджем**:
```bash
python3 scripts/check_localization_duplicates.py
python3 scripts/check_localization_keysets.py
```
- `check_localization_duplicates.py` — ищет дубликаты ключей внутри каждого языка.
- `check_localization_keysets.py` — проверяет, что множества ключей во всех языках совпадают (паритет).

> ⚠️ Если любой скрипт возвращает ошибку — правки отклоняются, файл возвращается в рабочее состояние, скрипты запускаются снова.

## 4. Процесс внесения изменений
1. **Подготовка**
   - Снять копию файла: `cp LocalizationManager.swift LocalizationManager.swift.backup`.
   - Убедиться, что бэкап `BACKUP_MOBILE_20251108_1800` доступен: он хранит эталон английского блока.

2. **Редактирование**
   - Добавлять новые ключи **одновременно** в `.russian` и `.english`. Для китайского и арабского — по возможности.
   - Проверять, что ключи отсортированы по логике секций (FAQ, Onboarding, Payments и т.д.).

3. **Очистка и синхронизация**
   - Проверить наличие дублей и удалить их. Примеры проблемных блоков:
     - `protection_feature_*`
     - `faq_*`
     - `add_member_*`
   - Если большой блок случайно переместился (как было с английским FAQ), восстанавливать из бэкапа: удобнее `git checkout <backup> -- Core/Localization/LocalizationManager.swift` или брать блок из `BACKUP_MOBILE_20251108_1800`.

4. **Валидация**
   - Запустить оба скрипта.
   - Проверить, что счётчики ключей равны (обычно `ru ≈ en ≈ 1875`, `zh ≈ 69`, `ar ≈ 73`).
   - Обновить комментарии `// keys: <locale>=<count>` внутри файла.

5. **Финальный чек-лист перед PR**
   - Запуск скриптов выполнен (логи приложены в CI).
   - Нет предупреждений `duplicate key` при запуске приложения.
   - Изменения локализованы минимум на двух языках (ru/en).
   - Документация обновлена, если меняется процесс.

## 5. Восстановление английского блока (если «поехал»)
Иногда русский блок начинает содержать английские строки. Тогда делать так:
1. Открыть `BACKUP_MOBILE_20251108_1800/Core/Localization/LocalizationManager.swift`.
2. Вырезать блок `.english: [ ... ]` целиком.
3. Заменить текущий блок `.english` на копию из бэкапа.
4. Снова пройти весь процесс валидации (удаление дублей в `.russian`, скрипты и т.д.).

## 6. Автоматизация и CI
- Добавить задачу `make check-localization`, которая запускает оба скрипта.
- В CI (GitHub Actions и другие) включить этот шаг в обязательные проверки.
- При расхождении > 50 строк между `main` и рабочей веткой — отклонить PR и предложить восстановить файл из эталона, потом вносить правки заново.

## 8. Типичные ошибки и как их избегать
| Ошибка | Причина | Решение |
|--------|---------|---------|
| `Fatal error: Dictionary literal contains duplicate keys` | Один и тот же ключ встречается дважды в одном блоке | Запустить `check_localization_duplicates.py`, удалить дубли, перезапустить |
| Английские строки попали в русский блок | Неправильная вставка/редактирование | Восстановить русский блок вручную, перенести строки обратно в `.english` |
| Разное количество ключей в языках | Новые строки добавлены только в одном блоке | Внести переводы в остальные блоки, запустить `check_localization_keysets.py` |
| Симулятор вылетает при старте | Повреждён словарь локализации | Сравнить с бэкапом, восстановить секции, повторить проверки |

## 9. Рекомендации на будущее
- Рассмотреть генерацию `LocalizationManager.swift` из JSON/CSV, чтобы исключить ручные ошибки (пока по требованиям остаёмся в одном файле).
- Раз в неделю формировать отчёт `localization_sync_report.md` (даты проверок, кто вносил изменения, результаты скриптов).
- Всегда держать актуальную версию инструкций синхронизации (добавлять новые правила в `LocalizationSyncPlan.md`).
