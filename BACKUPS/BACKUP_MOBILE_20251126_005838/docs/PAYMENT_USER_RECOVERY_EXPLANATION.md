# 🔍 ОБЪЯСНЕНИЕ: Поиск пользователя и восстановление платежей

## ❓ ВОПРОС
**Убрана логика поиска пользователя по alias (колонка отсутствует) - эта логика убрана! А как мы если что будем искать пользователя если с платежом что то пойдет не так!?**

---

## ✅ ОТВЕТ

### 1. Два разных типа поиска

#### A. Поиск пользователя в таблице `users` (для реферальной программы)
**Проблема:** В таблице `users` нет колонки `alias`

**Решение:** 
- Для анонимных платежей (без user_id) реферальная программа обрабатывается позже
- При подтверждении платежа, если user_id станет известен, реферальная программа обработается
- Это нормально - не все платежи сразу связаны с зарегистрированными пользователями

#### B. Поиск платежа по `user_alias` + `pin` (для восстановления кода активации)
**Это РАЗНАЯ задача!**

**Логика:**
- `user_alias` и `pin` используются для **восстановления кода активации**
- Платежи ищутся **напрямую в таблице `payments`** по `user_alias`
- Это НЕ связано с таблицей `users`

---

## 🔄 КАК РАБОТАЕТ ВОССТАНОВЛЕНИЕ

### Сценарий: Пользователь потерял код активации

1. **Пользователь вводит на сайте:**
   - `user_alias`: "testuser123"
   - `pin`: "1234"

2. **Сервер ищет в таблице `payments`:**
   ```sql
   SELECT payment_id, tariff_id, amount, status, created_at, paid_at
   FROM payments
   WHERE user_alias = 'testuser123'
     AND status = 'paid'
   ORDER BY paid_at DESC
   LIMIT 1
   ```

3. **Сервер возвращает:**
   - Информацию о платеже
   - Код активации (если он был сгенерирован)

## 🔐 БЕЗОПАСНОСТЬ

### Текущая реализация:
- ✅ Поиск по `user_alias` в таблице `payments`
- ⚠️ PIN пока не проверяется (можно добавить хеширование)

### Рекомендации для улучшения:
1. **Сохранить хеш PIN в таблице `payments`:**
   ```sql
   ALTER TABLE payments ADD COLUMN pin_hash VARCHAR(255);
   ```

2. **Проверять PIN при восстановлении:**
   ```python
   import hashlib
   pin_hash = hashlib.sha256(pin.encode()).hexdigest()
   # Проверка при поиске платежа
   ```

## 📊 СТРУКТУРА ДАННЫХ

### Таблица `payments`:
- `user_alias` - псевдоним пользователя (для восстановления)
- `pin` - НЕ сохраняется (можно добавить `pin_hash`)
- `payment_id` - уникальный идентификатор платежа
- `status` - статус (pending, paid, failed, expired, cancelled)

### Поиск платежей:
- ✅ По `user_alias` - для восстановления кода активации
- ✅ По `payment_id` - для проверки статуса
- ✅ По `status` - для фильтрации
