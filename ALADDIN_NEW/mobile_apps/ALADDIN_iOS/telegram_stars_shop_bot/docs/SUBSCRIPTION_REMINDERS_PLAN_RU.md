## 0. Зафиксированные решения продукта

| Вопрос | Решение |
|--------|---------|
| Реферал в текстах | **«+3 дня»** за нового пользователя (пригласившему) |
| Конфиг дней | Выровнять `VPN_REFERRAL_REFERRER_DAYS` → **3** (было 14); friend days — отдельно согласовать/оставить 7 или тоже 3 |
| Платные окна | **d7 оставляем** + welcome + **d3** + **d1** + **h6** + expired |
| Пробник окна | **~1 день** + **~6 часов** + **после окончания** (не «за 2/3 дня» — trial ≈72ч) |
| Email / SMS | **Не делаем** — нет сбора ПД (телефон/email) |
| Главный канал пуша | **Telegram-бот** (`sendMessage` в личку) |
| Без ПД дополнительно | Soft UI в боте + баннер на get. + Happ `announce` / `subscription-userinfo` |

## 1. Как уведомляют Telegram-сервисы (практика) и что берём мы

Отрасль (VPN/subscription-боты, n8n-reminders, Subscrypts и т.п.):

1. **Личка бота** — основной канал: cron/loop → `sendMessage(telegram_user_id)`.  
2. **Повтор при 429 / временных ошибках** — `retry_after`, 2–3 попытки.  
3. **Идемпотентность** — флаг «уже отправили kind» в БД.  
4. **Soft-nudge при входе** — если пользователь открыл `/start` / VPN в день X.  
5. **Отзыв доступа на бэкенде** — независимо от пуша (`vpn_expired` по `paid_until`).

**У нас уже есть:** п.1–3 частично (`vpn_expiry_notify` + `vpn_trial_reminder` + `vpn_expiry_notices`), expire worker в VPN API, Happ headers `expire` + глобальный `announce`.

**Чего нет у Telegram «из коробки» без ПД:** SMS, email, системный iOS-push мимо бота, гарантия доставки если пользователь **забанил бота**.

### Каналы без ПД (канон для AiMonkey)

| Приоритет | Канал | ПД? | Когда |
|-----------|-------|-----|-------|
| **P0** | Telegram DM бота | нет (только `telegram_user_id`) | все окна напоминаний |
| **P0** | Soft UI «Моя подписка» / модалка при входе в бот | нет | всегда видно; усилить в день окончания |
| **P1** | Баннер на **get.** (сессия web) | нет | пользователь открыл сайт |
| **P1** | **Happ** через `/sub`: `subscription-userinfo` expire + **персональный** announce «осталось N» / «доступ закрыт» | нет | клиент обновил подписку |
| — | Email / SMS | нужны ПД | **out of scope** |

**Итог:** да, уведомления **в Telegram можем и должны** — это наш основной и лучший канал без ПД. Fallback без телефона = soft UI + Happ announce + get., не SMS.

### Платный (`account_kind != trial`)

| Kind | Когда | Copy (суть) |

| `expired` | `vpn_expired` | «подписка завершена» |

### Пробный (`account_kind == trial`)

| Kind | Когда | Copy (суть) |
|------|-------|-------------|
| `welcome` | после активации trial | «пробный период активен до …» |
| `trial_d1` | ~20–28 ч до конца | «остался ~1 день» |

Единые кнопки на всех: `[Продлить подписку]` `[Пригласить друга]` (+3 дня в тексте реф-экрана).

## 4. Архитектура (лучшая для нас)

```
┌─────────────────────┐
│ Background loops     │  interval ~15m (h6+trial) + daily sweep ok внутри
│ subscription_notify  │
└──────────┬──────────┘
           │ читает vpn.db paid_until / account_kind / status
           ▼
┌─────────────────────┐     sendMessage      ┌──────────────┐
│ shop.db              │ ───────────────────► │ Telegram DM  │
│ vpn_expiry_notices   │                      └──────────────┘
│ + retry fields       │
└─────────────────────┘
           │
           ├── soft UI: handlers vpn / start («Моя подписка»)
           ├── get. banner (partner SPA) при days_left ≤ 3
           └── Happ: /sub headers expire + per-user announce (vpn-api)
```

**Не** собираем телефон/email.  
**Не** переименовываем `paid_until` в БД.

Практично: развить существующие `vpn_expiry_notify.py` + `vpn_trial_reminder.py` + общий `vpn_subscription_notify_ux.py` (тексты/кнопки), а не третий параллельный мир.

## 6. Инварианты

1. Не писать пользователю про сбор телефона/email ради пушей.  
2. Основной push = Telegram DM; доступ режется по `paid_until` даже если DM не дошёл.  
3. В UI/пушах реферал = **+3 дня** (согласовано с конфигом referrer).  
4. Платный d7 **не убирать**.  
5. Даты в текстах — **Москва**.  
6. Не смешивать `/o/` и `/sub/`.  
7. После оплаты/реф-бонуса `paid_until` только **наращивается** (stack), не обрезается.

## 8. Ревью «6 шляп» + гибридный канон

### Белая (факты)
- Уже есть 2 loop’а, `paid_until`, дедуп notices, статус-блок, stack продления, Happ `expire` в `/sub`.
- Дыры: h6 paid, единые кнопки, MSK в copy, welcome-kind, soft «Моя подписка», retry/лог.
- Реферал в проде **14/7**, продуктово хотим **+3** у пригласившего.

### Красная (ощущения)
- 12 задач в «фазе A» = риск утонуть и долго без выкладки.
- Резкий 14→3 дней реферала может разозлить активных амбассадоров.
- Много пушей подряд (d7+d3+d1+h6+expired) без soft UI = «спам-бот».

### Чёрная (риски)
- Полный «единый engine» с нуля ломает работающие trial/paid loops.
- `h6` + старый `d0` в один день = двойное сообщение.
- PK `(tid, kind)` без сброса после оплаты → вечный «уже слали d3».
- Per-user Happ announce (n16) — отдельная сложность VPN API, слабый ROI пока есть `expire` header.
- Hardcode «+3» в текстах при конфиге 14 = ложь пользователю.

### Жёлтая (плюс текущего направления)
- TG DM без ПД — правильный основной канал.
- Опора на существующий код — быстрее и безопаснее.
- Soft UI + get./Happ как pull — закрывает «бота забанили».
- d7 оставить — ранний winback без спама в последние сутки.

### Зелёная (альтернативы) → **гибрид (выбираем)**

| Крайность | Гибрид (наш канон) |
|-----------|-------------------|
| Один новый mega-scheduler | **Оставить 2 loop’а**, общий модуль **текстов/кнопок** |
| Только push | **Push (TG) + Pull** (экран подписки / вход в бот) |
| Сразу 4 канала | P0: TG+soft → P1: get. → later: Happ announce |
| Hardcode «+3» | Copy берёт **число из settings**; на проде ставим **3** |
| Ломать d0 и h6 вместе | **h6 вместо d0** в последние часы (один shot) |
| n08 и n09 раздельно | **Один экран** «Моя подписка»; при days≤1 / expired — тот же экран первым |

**Гибрид каналов:** не «мульти-push fanout», а **один push-канал (Telegram) + несколько pull-поверхностей** (бот UI, get., Happ expire). Это лучший баланс доставки, ПД и трудозатрат.

### Синяя (процесс)
- Лучшее решение для нас = **гибрид выше**, не «идеальное ТЗ Миши 1:1».
- Сначала A0 (copy/окна/кнопки) → выкладка → A1 (welcome/h6/подписка/reset) → B (retry) → later каналы.
- Метрика успеха смоука: тестовый paid и trial получили нужные kinds без дублей; после оплаты kinds сбрасываются; реф показывает фактические дни из env.
