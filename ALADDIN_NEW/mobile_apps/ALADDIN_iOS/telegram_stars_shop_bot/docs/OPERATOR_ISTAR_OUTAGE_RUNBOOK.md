# Оператор: сбой iStar / застрявшие заказы

## Как понять, что iStar лежит

- В личку админам приходит: **«iStar недоступен (ошибка поиска получателя)»** или **«Автовыдача на паузе»**.
- В карточке заказа (`/admin` → заказ): статус `paid`, блок **Автовыдача** с ошибкой `istar_http_500` / `recipient/search`.
- Баланс TON может быть в норме — это **не** «мало TON», а сбой API iStar.

## Что делает бот сам

1. **5xx не тратит попытку** — лимит 5 попыток только на «реальные» ошибки (неверный username и т.п.).
2. **Backoff** — повтор через 2 → 5 → 15 → 30 мин.
3. **Circuit breaker** — после 3 подряд 5xx пауза ~30 мин, затем снова.
4. **Polling** — если заказ в `processing`, а webhook не пришёл, бот опрашивает iStar каждые ~2 мин (после 3 мин в processing).

## Действия оператора

### Заказ оплачен (`paid`), звёзды не ушли

1. Откройте карточку заказа в боте.
2. Проверьте получателя (`user_note`) — должен быть `@username` без опечаток.
3. Если iStar долго 500 — **выдайте вручную** через кабинет iStar / Fragment.
4. В карточке нажмите **«Выдан»** — покупатель получит «выдан», админам придёт **🎁 #N выдан**.

### Сбросить попытки автовыдачи

В карточке: **«Сбросить попытки»** (если лимит исчерпан из-за старой логики).

### Мало TON

Алерт: **«Мало TON на кошельке iStar»**. Пополните кошелёк в кабинете iStar; воркер продолжит сам.

### Webhook iStar

- URL: `https://aladdin-ai.ru/v1/payments/istar-webhook`
- Secret: `ISTAR_WEBHOOK_SECRET` в `.env` на Contabo.

## Уведомления админам

Все ops-уведомления (TON, застрявшие paid, circuit breaker, новые заказы, выдача) идут в **один чат** `ALERT_TELEGRAM_CHAT_ID` на русском (`ADMIN_BOT_ALERTS_ENABLED=true`).
