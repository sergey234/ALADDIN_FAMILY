# План: Профиль без рефералки + статус VPN

**Дата:** 2026-07-14  
**Цель UX:** одно место для рефералки; профиль — только личные данные и VPN; актуальный статус VPN в профиле и в разделе VPN.  
**Cursor TODO SSOT:** `PROFILE_VPN_STATUS_TODO_TRACKER.md` (ids `pf-*`)  
**Индекс всех треков:** `SHOP_BOT_ACTIVE_TRACKS_INDEX_2026-07-14.md`  
**Happ Android (отдельный SSOT, не дублировать шаги сюда):** `VPN_HAPP_ANDROID_CONNECT_GUIDE.md` / `ha-*`

---

## 1. Проблема (факт)

| Место | Сейчас |
|-------|--------|
| 👥 `nav:ref` | реф-ссылка, условия, статистика, кнопки — **оставляем как есть** |
| 👤 `nav:profile` / `profile_body_html` | **дубль** рефералки (текст + ссылка + статистика) + `append_referral_action_rows` + кнопка «Как работает приглашение» |
| 🛡️ VPN | есть блок аккаунта / «Подписка активна», но формат «осталось X дн. Y ч» + единый helper для профиля **не доведён** под ТЗ |

Пользователь путается, где управлять приглашениями.

---

## 2. Наилучшее решение (канон)

### 2.1 SSOT рефералки = только «Пригласить друга»

- **Не трогать** логику/тексты/ссылку/стат/кнопки/`nav:ref` / FAQ из этого раздела (кроме общих правок `rb-*` про spend VPN-only в FAQ — без переноса в профиль).
- Из профиля **вырезать** любой реф-контент и реф-кнопки.
- Кнопка «👤 Полный профиль» из `nav:ref` — **можно оставить** (навигация к профилю, не дубль реф-логики).
- Кнопку «👥 Пригласить друга» в хабе — без изменений.

### 2.2 Профиль = карточка пользователя

Шаблон тела (HTML):

```
🆔 ID: <telegram_user_id>
📅 Дата регистрации: дд.мм.гггг
💳 Основной баланс: XXX ₽
🎁 Бонусный баланс: XXX ₽
   Используется только для оплаты VPN.   ← согласовано с rb-*
🛡️ VPN:
   …блок статуса (общий helper)…
```

Клавиатура профиля после чистки:

- VPN copy/sub (если active) — ок  
- **Без** `append_referral_action_rows`  
- **Без** `nav:reffaq`  
- Опционально оставить «Продать Stars» / «Мои заявки» — это не рефералка (не в списке ТЗ как контент, но навигация допустима; в DoD — не смешивать с реф-текстом)

### 2.3 Единый VPN status helper (один источник правды)

Новый (или расширение) helper, напр. `vpn_user_status_block_html(settings, telegram_user_id) → str`:

Источник: `vpn.db` через уже существующий `vpn_admin_support_repo.fetch_vpn_account_user_facing` + `paid_until` / `status`.

| Состояние | UI |
|-----------|-----|
| `vpn_active` и `paid_until` > now | `✅ Статус: Активен` / `⏳ Осталось: X дн. Y ч` / `📅 Действует до: дд.мм.гггг чч:мм` |
| нет аккаунта / `vpn_expired` / past until | `❌ Статус: Не активен` (в VPN-разделе: `❌ VPN не подключён`) |

Детали реализации:

- Переиспользовать `parse_paid_until_utc`, `format_datetime_display_msk(..., date_only=False)`, логику часов из `hours_until_expiry` (trial_reminder) — **не** копировать третий форматтер.
- Добавить `format_remaining_dhm(end)` → «12 дней 5 часов» (полные дни + остаток часов).
- Вызывать helper:  
  - в **профиле**;  
  - в **VPN** (`vpn_main_block_html` / `_vpn_account_user_section_html`) — один формат, актуальные данные при каждом открытии экрана (уже live из БД; «автообновление» = пересчёт на каждый `nav`/edit, не websocket).

### 2.4 Почему не альтернативы

| Вариант | Почему хуже |
|---------|-------------|
| Оставить краткий реф-блок в профиле «для удобства» | снова дубль ТЗ |
| Перенести всю рефку только в профиль | ломает кнопку хаба «Пригласить друга» |
| Тянуть статус только из кэша сообщения | устареет; нужен read vpn.db на каждый показ |
| Разные форматы в профиле и VPN | рассинхрон и баги копирайта |
