## 🎯 ВОЗМОЖНЫЕ ПРИЧИНЫ КРАША НА РЕАЛЬНОМ УСТРОЙСТВЕ

### 1. ⚠️ ПРОБЛЕМА ПРОИЗВОДИТЕЛЬНОСТИ: Множественные вычисления

**Проблема:**
- `calculatedProtectionLevel` вызывается **10+ раз** за один рендер
- `safeCurrentTariff` вызывается **10+ раз** за один рендер
- Каждое вычисление вызывает `tariff.createCard()`, что дорого по ресурсам

**Почему это вызывает краш на реальном устройстве:**
- Реальные устройства имеют **меньше памяти** и **медленнее процессор**
- Множественные вычисления могут вызвать:
  - **Таймаут рендеринга** (SwiftUI убивает view, если рендер занимает > 16ms)
  - **Переполнение стека** (если вычисления вызывают друг друга рекурсивно)
  - **Нехватку памяти** (если создается много объектов)

**Решение:** ✅ **РЕАЛИЗОВАНО**
- Добавлено кэширование `calculatedProtectionLevel` в `@State`
- Добавлено кэширование `safeCurrentTariff` в `@State`
- Кэш обновляется только при изменении тарифа или через 1 секунду

---

### 2. ⚠️ ПРОБЛЕМА ПАМЯТИ: Утечки памяти

**Проблема:**
- Множественные вычисления создают много временных объектов
- На реальном устройстве меньше доступной памяти
- Может вызвать **OOM (Out of Memory)** краш

**Решение:** ✅ **РЕАЛИЗОВАНО**
- Добавлена диагностика памяти в `onAppear`
- Кэширование уменьшает количество создаваемых объектов
- Логирование использования памяти для мониторинга

---

### 3. ⚠️ ПРОБЛЕМА ПОТОКОВ: Доступ не на main thread

**Проблема:**
- На реальном устройстве SwiftUI может вызывать computed properties на фоновых потоках
- Доступ к `@Published` свойствам не на main thread вызывает краш

**Решение:** ✅ **УЖЕ РЕАЛИЗОВАНО**
- Проверка `Thread.isMainThread` во всех computed properties
- Fallback значения для фоновых потоков
- Критическое логирование при вызове не на main thread

---

### 4. ⚠️ ПРОБЛЕМА ИНИЦИАЛИЗАЦИИ: Race conditions

**Проблема:**
- На реальном устройстве инициализация может происходить медленнее
- `tariffManager.currentTariff` может быть недоступен при первом вызове
- `localizationManager` может быть не инициализирован

**Решение:** ✅ **УЖЕ РЕАЛИЗОВАНО**
- Безопасные computed properties с fallback значениями
- Проверки инициализации в `onAppear`
- Защита от множественных вызовов `initializeNotifications()`

---

### 5. ⚠️ ПРОБЛЕМА KEYCHAIN: Доступ к токенам

**Проблема:**
- На реальном устройстве Keychain может работать медленнее
- Доступ к токенам может быть заблокирован
- Может вызвать таймаут при инициализации

**Решение:** ✅ **УЖЕ РЕАЛИЗОВАНО**
- `MetricsService` теперь не требует авторизации для отправки метрик

### 2. Кэширование `safeCurrentTariff`

**До:**
```swift
private var safeCurrentTariff: TariffType {
    // Вызывается каждый раз (10+ раз за рендер)
    return tariffManager.currentTariff
}
```

**После:**
```swift
@State private var cachedTariff: TariffType = .free
@State private var cachedTariffId: String = ""

private var safeCurrentTariff: TariffType {
    let currentTariff = tariffManager.currentTariff
    let currentTariffId = currentTariff.id
    
    // Используем кэш, если тариф не изменился
    if cachedTariffId == currentTariffId && cachedTariff == currentTariff {
        return cachedTariff // ✅ Возвращаем кэш
    }
    
    cachedTariff = currentTariff // ✅ Обновляем кэш
    return currentTariff
}
```

**Результат:**
- ✅ Уменьшение обращений к `tariffManager` с **10+ до 1** за рендер
- ✅ Уменьшение нагрузки на менеджер
